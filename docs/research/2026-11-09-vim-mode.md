# Research: vim mode in Zed and VS Code

- **Date:** 2026-11-09
- **Status:** research notes, not a spec yet.
- **Purpose:** choose a direction for Lucerna's vim mode, after looking at how Zed and VS Code do it.

> Sections 1–4 are written from general knowledge. **Section 5 (2026-11-10) is the result of reading the real source**: Zed's `crates/vim` at the pinned GPUI revision (`b5cd310`), and VSCodeVim commit `28f0275`. Where the two parts contradict, section 5 is right.

## 1. Zed: vim built into the editor

- **Where it lives:** vim is part of the editor, in the `crates/vim` crate of the Zed repo, not an extension.
- **How to enable it:** set `"vim_mode": true` in `settings.json`. Zed also has `"helix_mode"`, which works the same way.
- **Architecture:**
  - Each editor stores its current mode: normal, insert, visual, visual line, visual block, replace.
  - Keys are bound in a separate keymap for vim, and each binding has a condition on context, for example `vim_mode == normal`.
  - Each key calls an existing editor action: a motion, an operator or a text object.
  - So vim shares the keymap and action system with the rest of the editor; it is not a layer bolted on from outside.
- **Main features:**
  - motions and the `d`/`c`/`y` operators
  - text objects
  - the visual modes
  - registers, macros, marks, the `.` command
  - part of the `:` commands (`:w`, `:s`, `:g`…)
  - surround
  - combination with multiple cursors
- **Why it isn't an extension:** Zed's WASM extension API has no place to intervene in receiving keys or editing text. Extensions can only provide themes, languages, LSP and similar things.
- **License:** `crates/vim` is **GPL-3**. Lucerna (MIT OR Apache-2.0) **must not copy code** from it; it may only learn the design and read the docs that describe behavior.

## 2. VS Code: vim runs as an extension

VS Code has no built-in vim. There are two main ways to get vim:

1. **VSCodeVim** (`vscodevim/vim`, MIT, written in TypeScript)
   - Rewrites vim behavior from scratch and runs in the extension host. It is the most popular extension.
   - Downside: every keystroke goes through the extension host, so there is latency, and some rare cases behave differently from real vim.
   - Upside for Lucerna: it has a **very large test suite** of the form "in state X, typing key Y gives result Z", and under the MIT license we may reference it as long as we credit the source.
2. **vscode-neovim** (MIT)
   - Runs **real Neovim** as the backend and syncs the buffer over msgpack-RPC.
   - Upside: behavior is almost exactly right, and the user's Neovim config can be reused.
   - Downside: users must install `nvim`, and the two sides must sync constantly, which is fairly complex.

## 3. Applying this to Lucerna

- **Vim must be built in, like Zed.** Lucerna uses Zed's extension format (phase 2), so extensions can't intervene in receiving keys either.
- **Lucerna already has the groundwork:**
  - A VS Code-style keymap with `when` clauses; we only need to add context keys such as `vimMode == 'normal'`. Note: the keymap runs in the capture phase, so every single-letter key binding must have a `when`.
  - Motion, selection and search commands already exist (`CodeView::go_to`, `select`, the find widget), so vim is mostly a layer that turns keys into commands.
  - Input boxes have the context key `textInputFocus`, so vim must turn off while typing into an input box.
- **Split into two phases** (see the roadmap in spec §1.3):
  - **Motion vim**, built after phase 2, works right away on the read-only viewer:
    - `hjkl`, `w`/`b`/`e`, `0`/`$`/`^`, `gg`/`G`, `{`/`}`, `%`
    - search: `/`, `?`, `n`/`N`, `*`/`#`
    - scrolling: `Ctrl+d`/`Ctrl+u`/`Ctrl+f`/`Ctrl+b`, `zz`/`zt`/`zb`
    - leading counts (`5j`), marks (`m`/`'`), visual mode to select and then copy (`v`, `V`, `y`)
  - **Editing vim**, built after phase 4 (once code can be edited):
    - insert mode, the `d`/`c`/`y`/`>`/`<` operators combined with motions and text objects
    - `.`, macros, registers, `u`/`Ctrl+r`, part of the `:` commands
- **Don't go the Neovim-as-backend route,** unless exact behavior is truly needed later. For a viewer focused on reading code it is too heavy.
- **How to enable it:** set `"vim.enabled": true` in `settings.json`, following VSCodeVim's key name so VS Code users feel at home. We may also accept `"vim_mode"` as an alternative name, like Zed. The official decision is left to the spec.

## 5. Source cross-check (2026-11-10, for V1 "motion vim")

Sources: Zed `crates/vim` and `assets/keymaps/vim.json` at `~/.cargo/git/checkouts/zed-*/b5cd310` (GPL-3, learn the design only, don't copy code). VSCodeVim (`VSCodeVim/Vim`, MIT, `Copyright (c) 2015 VSCodeVim`), commit `28f0275`.

### 5.1 Mode model and pending keys

- **Zed**
  - The mode enum: Normal, Insert, Replace, Visual, VisualLine, VisualBlock (plus two Helix modes).
  - Each editor has a `Vim` entity (an addon) holding the mode and an *operator stack*.
  - A global holds the count, `last_find`, registers and marks.
  - The key sequences `g g`, `z z`, `z t` are ordinary chords in the keymap.
  - `f`/`t`/`m`/`'` push a "waiting" operator. The next character typed has no binding, so the editor emits `InputIgnored{text}`, and vim reads that character.
  - Number keys are `vim::Number` bindings. The `0` key is a motion, unless a count is being typed (context `VimCount`).
- **VSCodeVim**
  - Letter keys are not keybindings: the extension overrides VS Code's `type` command. The `type` command only runs when a text editor has focus, so input boxes, Quick Open and the find widget never reach vim.
  - Only Ctrl keys and special keys are keybindings, with `when` set to `editorTextFocus && vim.active`, plus `vim.use<C-x>`.
  - A parser collects the pending key sequence (`vim.command`).
- **Lucerna chooses:** a pure state machine (no gpui) that receives the *typed character* (`key_char`), the way VSCodeVim uses `type`. Reasons:
  - `keys::to_keystroke` uses `key` rather than `key_char`, so `$`, `{`, `%`, `^`, `*`, `#` would become `shift+4`, `shift+[`… and depend on the keyboard layout.
  - `f<c>`, `m<c>` and counts need to read the raw character anyway.
  - The vim layer runs before the keymap in `dispatch_key`, only when `editorFocus && !textInputFocus`. Keys with cmd always go through the keymap.

### 5.2 Context keys for `when`

- **Zed:** `vim_mode` (`normal`/`visual`/`insert`/`operator`/`waiting`…), `vim_operator`, `VimControl`, `VimCount`.
- **VS Code:** `vim.active`, `vim.mode` (`'Normal'`, `'Visual'`, `'VisualLine'`, `'VisualBlock'`…).
- **Lucerna:** set `vim.active` and `vim.mode` using VSCodeVim's names, so VS Code users' keybindings can be reused.

### 5.3 Motion behavior (easy to get wrong)

| Motion | Zed | VSCodeVim / Vim | Lucerna |
|---|---|---|---|
| `w`/`b`/`e` | 3 character classes: word (letters, digits, `_`), punctuation, whitespace. An empty line is a stop | Same as Zed. A line with only whitespace is skipped. `w` on the last word of the file goes to the end of the line | Follow Vim/VSCodeVim |
| `W`/`B`/`E` | Punctuation counts as word, only whitespace separates | Same as Zed | Same |
| `N$` | Go down N−1 lines then to the end of the line. Desired column = ∞ | Same as Zed | Same |
| `gg`/`G` | Keep the column | `startofline=true` (default): go to the first non-blank character. The count is clamped to the last line | **Follow VS Code/Vim**: the first non-blank character |
| `{`/`}` | Only truly empty lines are boundaries | Same as Zed. `}` at the end of the file goes to the end of the last line | Same |
| `%` | Find the nearest bracket from the cursor on the current line, then jump to its pair (uses tree-sitter, with a text-based fallback) | Same as Zed, with the pairs `(){}[]` | Search on the line, then use the existing `matching_bracket` |
| `H`/`M`/`L` | Take a count (`3H`). Have a scroll margin | Ignore the count | **Follow Zed/Vim** (with count). Reason: real Vim has counts |
| `t` then `;` | `;` retries with count+1 if it didn't move, so it gets past the adjacent character | Same as Zed | Same |
| `*`/`#` | Whole word, case-sensitive | Whole word, following `ignorecase` (case-insensitive by default) but ignoring smartcase. On whitespace it takes the next word on the line | Follow VSCodeVim |
| `n`/`N` | Follow the last search direction (after `?`, `n` goes backward). Wraps | Same as Zed. `wrapscan` is on by default | Same |
| `Ctrl+d`/`Ctrl+u` | Half a page, the cursor follows | Same as Zed. `N<C-d>` resets `scroll` | Half a page. A count resets `scroll`, following Vim |
| `Ctrl+f`/`Ctrl+b` | One page minus one line | One page | One page minus two lines, like Vim |
| `zz`/`zt`/`zb` | Scroll only | Scroll only, keeping the desired column | Same |
| `'x` / `` `x `` | The first non-blank of the line / the exact position | Same as Zed | Same |
| Jumplist | G, gg, `{`, `}`, `%`, H/M/L, search, marks | Same as Zed | Record the `'` mark for jumps (V1 has no `Ctrl+o` yet) |

### 5.4 Visual mode

- **Zed**
  - Uses ordinary selections, but *inclusive*: the character under the cursor belongs to the selection.
  - `V` turns on line mode. `Ctrl+v` creates one selection per line (multi-cursor).
  - After `y`, the cursor goes to the start of the selection. With `V` it goes to column 0. With block it goes to the top-left corner.
  - `Esc` collapses the selection to the end that moves (the head).
- **VSCodeVim:** same as Zed. In addition: `Esc` keeps the desired column, and visual mode sets the marks `'<`/`'>`.
- **Lucerna:** CodeView has only one selection, so block mode needs its own way of drawing: a list of rectangles by display column.

### 5.5 Cursor and mode indicator

- **Zed**
  - Normal mode uses a block cursor.
  - The cursor may not sit after the last character of a line (`clip_at_line_ends`).
  - j/k remember the desired column (the goal).
  - Mode indicator on the status bar: `-- NORMAL --`, `-- VISUAL --`, `-- VISUAL LINE --`, `-- VISUAL BLOCK --`, prefixed by the count or pending keys.
- **VSCodeVim**
  - Uses the same text for the indicator.
  - While searching, the status bar shows the command line `/foo|`.
- **Lucerna:**
  - The indicator text matches the two others.
  - Pending keys (`2d`, `g`…) show next to the indicator, following `vim.showcmd`.

### 5.6 Settings

- **Zed:** `vim_mode`, plus a `vim.{use_system_clipboard, use_smartcase_find, use_regex_search, cursor_shape…}` block.
- **VSCodeVim**
  - **There is no `vim.enabled`**: installing the extension turns it on. Turn it off with `vim.disableExtension`.
  - Related keys and defaults: `vim.useSystemClipboard`=false, `vim.ignorecase`=true, `vim.smartcase`=true, `vim.hlsearch`=false, `vim.incsearch`=true, `vim.wrapscan`=true, `vim.startofline`=true, `vim.scroll`=0, `vim.showmodename`=true, `vim.showcmd`=true.
- **Lucerna**
  - Enable with `vim.enabled` (default false), because Lucerna has vim built in rather than installed as an extension. This is a departure from VS Code, and the key name stays in the same `vim.*` namespace. Also accept `vim_mode` as an alternative name.
  - The other keys use VSCodeVim's exact names.

## 6. Editing, for V2 (2026-11-13)

Sources: Zed `crates/vim` at `b5cd310` (GPL-3, learn the design only) and VSCodeVim HEAD on 2026-11-13 (MIT, `Copyright (c) 2015 VSCodeVim`).

### 6.1 Operator model

- **Zed**
  - An operator is an `Operator` stack. The motion or text object that follows completes the operator.
  - Doubling (`dd`, `cc`, `yy`, `>>`, `gUU`) is a binding in the keymap: in the context `vim_operator == d`, the `d` key calls `CurrentLine`.
  - Counts multiply: `2d3w` = 6 words.
  - Each motion has a default kind:

    | Kind | Motions |
    |---|---|
    | Linewise | j, k, gg, G, H/M/L, `'x` |
    | Inclusive | `$`, `%`, e, E, ge, f, t |
    | Exclusive | w, b, h, l, 0, ^, `{`, `}`, F, T, `` `x `` |

  - A `v` placed before a motion forces the kind to change.
  - Applies Vim's exclusive rule: if the end point lands on column 0 of the next line, move back to the end of the previous line, and the motion becomes inclusive (or linewise if the start point is before the first non-blank character).
  - `dw` does not cross a newline. `cw` on a non-blank character becomes `ce`. `cc` and `S` keep the indentation.
- **VSCodeVim:** same as Zed, with the same edge cases above. `vim.changeWordIncludesWhitespace` (default false) controls `cw` → `ce`.

### 6.2 Registers

- **Zed**
  - Stores a `HashMap<char, Register>`. A linewise register is recognized by "the text ends with `\n`".
  - `"A` appends. `"_` discards. `"0` stores the last yank. `"-` stores the last small delete (no `\n`). The `"1`–`"9` ring shifts on a linewise or multi-line delete.
  - `use_system_clipboard` has three values: `always` (default), `on_yank` and `never`.
- **VSCodeVim**
  - Each register has a `RegisterMode`: CharacterWise, LineWise and BlockWise.
  - `vim.useSystemClipboard` defaults to **false**. When on, the unnamed register is `*`. On read, if the clipboard differs from the text written, it takes the clipboard as characterwise.
  - Appending linewise with `"A` to a characterwise register makes the register linewise.
  - Departures from Vim: `c` doesn't write `"1` or `"-`; the numbered ring still shifts when a named register is used.
- **Paste, the same on both sides:**

  | Register kind | `p` | `P` | Cursor after pasting |
  |---|---|---|---|
  | Linewise | line below | line above | first non-blank character |
  | Characterwise | after the cursor | at the cursor | last character; if there is a `\n`, back to the start of the pasted text |

  - `gp` and `gP` put the cursor right after the pasted text.
  - Visual `p` writes the old selection into the unnamed register; Visual `P` doesn't.

### 6.3 Repeat with `.`, undo, macros

- **Zed**
  - Records the *actions* (including `Insertion { text }`) and replays them.
  - Each command is in one `transact`. Inserts are merged with `group_until_transaction`.
  - The `q` macro stores a list of actions, separate from registers.
  - `N.` replaces the original count.
- **VSCodeVim**
  - Also records actions.
  - Undo is implemented by itself via diffs, following these principles:
    - one Normal command is one step;
    - one Insert session is one step;
    - one macro run is one step;
    - `<Left>` in Insert creates an undo point.
  - `u` returns the cursor to where the command started.
  - `N.` repeats the whole command N times (a departure from Vim).
  - Macros are stored in registers, and `@x` can also run text in a register.
  - The status bar shows `recording @q`.

### 6.4 Text objects

- **Both sides agree on:**
  - `aw`: takes the whitespace after; if there is none, takes the whitespace before. On whitespace it takes the whitespace plus the next word.
  - Quotes: searched only on the current line, skipping `\"`. `a"` takes the trailing whitespace too.
  - Brackets: searched across multiple lines and nested.
  - `ip` / `ap`: counted by blocks of blank lines and lines with text.
  - `it` / `at`: use tree-sitter in Zed.
- **They differ on:**
  - VSCodeVim searches *forward to* the next bracket pair if the cursor isn't inside any pair. A count such as `c3i)` goes out through nested pairs. It also has `ia` / `aa` (argument) and `ae` (whole file).
  - Zed also has `if` / `af` / `ic` / `ac` based on `textobjects.scm`, and ignores the count with brackets.

### 6.5 The `:` command line

- **Zed**
  - There is no separate command line: `:` opens the **command palette** and translates the typed string into actions.
  - Ranges support `%`, `.`, `$`, `'x`, `+N`; there is **no** `/pat/`.
  - `:42` is go to line. `:w` saves. `:q` closes the tab.
  - `:s` runs through the search bar: it scopes the search to the range, then replaces all.
- **VSCodeVim**
  - The command line lives in the status bar, with history (`vim.history` = 50).
  - Supports many commands and has `/pat/` ranges.
  - `:s` has the flags `g`, `c`, `n`, has `\U` / `\u`, `&` and `~`. `vim.gdefault` (default false) inverts the `g` flag.
  - After `:s`, the status bar reports something like `3 substitutions on 2 lines`.

| Highlight on yank | `vim.highlightedyank.enable`=false, `vim.highlightedyank.duration`=200 |
| Substitution | `vim.gdefault`=false |
| Text editing | `vim.joinspaces`=true, `vim.changeWordIncludesWhitespace`=false, `vim.tildeop`=false, `vim.whichwrap`="b,s" |
