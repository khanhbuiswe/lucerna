# Research: LSP and code intelligence (VS Code and Zed)

- **Date:** 2026-11-10
- **Status:** research notes, the basis for the Phase 3 spec (LSP + WASM host for extensions).
- **Sources:**
  - VS Code: `microsoft/vscode` branch `main` (MIT), `microsoft/vscode-languageserver-node` (MIT), the `rust-analyzer` extension manifest (`editors/code/package.json`), the docs at `code.visualstudio.com/docs`. File paths below are relative to `src/vs/`.
  - Zed: source at rev `b5cd310` (`~/.cargo/git/checkouts/zed-*/b5cd310`). The crates `lsp`, `project`, `editor`, `language`, `languages`, `outline`, `outline_panel`, `breadcrumbs`, `project_symbols`, `diagnostics`, `lsp_locations`, `language_tools`, `activity_indicator`, `extension_host`, `extension`, `language_extension`, `node_runtime`, `github_releases` are **GPL-3**: this document only describes the design and copies no code. Identifier names, setting keys and constants are quoted as facts.
  - Zed's `crates/extension_api/**` alone (the WIT files, `settings.rs`, the `zed_extension_api` crate) is **Apache-2.0** and can be vendored into Lucerna together with `LICENSE-APACHE`.
- Shortcuts are the macOS defaults. Items not verified directly in the source are marked **[unverified]**.
- Lucerna is only for viewing code, so editing-side features (completion, code action, rename, format, signature help) are only mentioned where they affect shared infrastructure.

## 1. Summary

| Topic | VS Code | Zed | Lucerna leans toward |
|---|---|---|---|
| Go to definition | `F12`, Cmd+click; multiple results open peek; standing right on the definition switches to references | `f12`, Cmd+click; multiple results open a multibuffer tab (or a picker with preview); finding nothing falls back to Find All References | VS Code keys/commands; multiple results open a Zed-style picker with preview |
| Peek | Zone widget inserted between lines, preview + result tree | None | Not built; a picker with preview replaces it |
| Find references | `Shift+F12` opens peek; `Shift+Alt+F12` opens the References view in the sidebar | `alt-shift-f12` opens a "References to X" tab (multibuffer) | A picker with preview, can be opened as a tab |
| Hover | 300 ms delay, diagnostic first, LSP part after | 300 ms delay, sends the request at half the delay, diagnostic and info popovers stacked | Follow Zed (half-delay prefetch, sizes) |
| Diagnostics in the editor | Squiggles, overview ruler, minimap; **no** gutter icon | 1 px squiggles, markers on the scrollbar; **no** gutter icon; error lens off by default | Squiggles + scrollbar markers, no gutter icon |
| Error navigation | `F8` across files, `Alt+F8` within the file; zone widget | `f8` within the buffer; block inserted below the line | VS Code keys, Zed-style block |
| Error list | Problems panel (`Cmd+Shift+M`) as a tree | "Diagnostics" multibuffer tab (`cmd-shift-m`) | To be decided, see §11 |
| Outline | LSP `documentSymbol`, a view in the Explorer | Tree-sitter `outline.scm` by default, LSP optional | Tree-sitter first, LSP optional |
| Breadcrumbs | Each segment is clickable, opens a picker | The whole row is one button that opens the outline | To be decided |
| Quick Open `@` / `#` | `Cmd+Shift+O` / `Cmd+T`, `#` debounced 200 ms | `cmd-shift-o` / `cmd-t`, no debounce, cancels the old request on drop | VS Code keys, short debounce + cancel on drop |
| LSP client | `vscode-languageclient`, auto-restarts up to 4 times / 3 minutes | Hand-written JSON-RPC, 120 s timeout, cancel-on-drop, no auto-restart | Hand-written after Zed's design, plus a bounded restart like VS Code |
| Server configuration | Each extension has its own namespace (`rust-analyzer.server.path`…) | `lsp.<server>` + `languages.<L>.language_servers` | Use Zed's shape (WASM extensions need exactly this shape) |
| How a server is obtained | The extension bundles client + server | Native adapters for popular languages, the rest via WASM extensions | Native adapters + a WASM host for the long tail |

## 2. Go to definition

### 2.1 VS Code
- **Commands and keys** (`editor/contrib/gotoSymbol/browser/goToCommands.ts`):

  | Command ID | Key |
  |---|---|
  | `editor.action.revealDefinition` | `F12` |
  | `editor.action.revealDefinitionAside` | `Cmd+K F12` |
  | `editor.action.peekDefinition` | `Alt+F12` |
  | `editor.action.goToTypeDefinition` / `peekTypeDefinition` | none |
  | `editor.action.goToImplementation` | `Cmd+F12` |
  | `editor.action.peekImplementation` | `Cmd+Shift+F12` |
  | `editor.action.revealDeclaration` / `peekDeclaration` | none |
  | `workbench.action.navigateBack` / `navigateForward` | `Ctrl+-` / `Ctrl+Shift+-` |

  Each command needs the matching provider's context key (`editorHasDefinitionProvider`…). The "Go to …" entries are in the `navigation` group of the context menu, and the peek variants are in the "Peek" submenu.
- **Result handling** (shared by every kind):
  1. The request is canceled when the content or the cursor position changes. The progress bar only appears after 250 ms.
  2. **No results:** a small bubble at the cursor, for example `No definition found for 'foo'`. Cmd+click stays silent.
  3. **A single result at the cursor position:** runs the alternative command. `editor.gotoLocation.alternativeDefinitionCommand` (and the Type Definition and Declaration versions) defaults to `"editor.action.goToReferences"`; the Implementation and Reference versions default to `""`. The effect is that pressing F12 right on the definition name produces the references list.
  4. **Otherwise:** follows `editor.gotoLocation.multipleDefinitions` (and `multipleTypeDefinitions`, `multipleDeclarations`, `multipleImplementations`, `multipleReferences`), all defaulting to **`peek`**: one result jumps, multiple results open peek. `gotoAndPeek` jumps to the first result and then opens peek; `goto` only jumps to the first result.
  5. On jump: uses `targetSelectionRange` if present, puts the cursor at the start, scrolls "near the top if outside the viewport", and the target range is highlighted for 350 ms.
- **Cmd+click / Cmd+hover** (`link/goToDefinitionAtPosition.ts`, `clickLinkGesture.ts`):
  - The trigger key is the opposite of `editor.multiCursorModifier` (default `alt`), that is **Cmd** on mac; add **Alt** to open to the side.
  - Holding Cmd while hovering: requests the definition for the word under the mouse (canceling the previous request). If there is a result, the word is underlined, changes to the link color, and the mouse cursor becomes a hand.
  - Hovering over the link: for one result, a preview of the target source, at most 8 lines (`MAX_SOURCE_PREVIEW_LINES = 8`, trimmed by indent); for multiple results, the text `Click to show N definitions.`
  - Click runs Go to Definition with `openInPeek = editor.definitionLinkOpensInPeek` (default `false`).
- **Navigation history:** `Ctrl+-` / `Ctrl+Shift+-`, each jump creates an entry. `workbench.editor.navigationScope` (`default` | `editorGroup` | `editor`). `workbench.editor.enablePreviewFromCodeNavigation` defaults to `false`: jumping from a preview tab pins that tab instead of replacing it.

### 2.2 Zed
- **Commands and keys** (`assets/keymaps/default-macos.json`):

  | Action | Key |
  |---|---|
  | `editor::GoToDefinition` / `GoToDefinitionSplit` | `f12` / `alt-f12` |
  | `GoToTypeDefinition` / `GoToTypeDefinitionSplit` | `cmd-f12` / `alt-cmd-f12` |
  | `GoToImplementation` | `shift-f12` |
  | `GoToDeclaration` / `GoToDeclarationSplit` | `ctrl-f12` / `alt-ctrl-f12` |
  | `FindAllReferences` | `alt-shift-f12` |
  | `pane::GoBack` / `pane::GoForward` | `ctrl--` / `ctrl-_` |

- **Behavior** (`crates/editor/src/navigation.rs`):
  - One result jumps directly, scrolling by `go_to_definition_scroll_strategy` (default `center`; also `minimum`, `top`, `preserve`).
  - Multiple results follow `lsp_results_location`: `"multi_buffer"` (default) opens a multibuffer tab named "Definitions" / "Type Definitions" / "Implementations"; `"picker"` opens a filterable modal with a **preview pane** (the `lsp_locations` crate).
  - Links pointing at the cursor's own position are dropped.
  - If nothing can be navigated and `go_to_definition_fallback = "find_all_references"` (default), it runs Find All References. The same idea as VS Code's alternative command.
- **Cmd+hover link** (`hover_links.rs`): while `cmd` is held, Zed tries in turn: the server's document link, a URL in the text, a file path in the text, then the LSP definition (with `shift` added, the type definition). Results are cached by range, so moving the mouse within the same symbol does not resend the request. UI: a straight 1 px underline, text color `link_text.hover`, hand cursor. Click: `cmd` → definition, `cmd-shift` → type definition, add `alt` → open in a split.
- **History:** the pane's `NavHistory` stores (anchor, scroll position) before each jump, skipping jumps under `MIN_NAVIGATION_HISTORY_ROW_DELTA = 10` rows. There are `preview_tabs.enable_preview_file_from_code_navigation` and `enable_keep_preview_on_code_navigation`.

### 2.3 Similarities and differences
- Same: `F12`, Cmd+click, `Ctrl+-` to go back, fallback to references when already at the definition.
- Different in keys: VS Code `Cmd+F12` is Implementation and `Shift+F12` is References; Zed `cmd-f12` is Type Definition and `shift-f12` is Implementation. Lucerna follows VS Code.
- Different for multiple results: VS Code opens peek in place, Zed opens a multibuffer tab or a picker with preview.

## 3. Peek

### 3.1 VS Code
- **Layout** (`gotoSymbol/browser/peek/referencesWidget.ts`, `peekView/browser/peekView.ts`):
  - A **zone widget** inserted below the anchor line, pushing the following lines down (not an overlay), with a small arrow pointing to the anchor position.
  - Header: the name of the file being previewed, a dimmed directory, the label `References (12)` / `Definitions (3)`, a close button. While loading it shows `Loading...`, when empty `No results`.
  - Body: a horizontal SplitView, **the preview editor on the left** (minimap off, minimum width 200 px), **the result tree on the right** (minimum 100 px, background `peekViewResult.background`). The default ratio is 0.7 / 0.3, 18 lines tall; saved to the storage key `peekViewLayout` on close.
  - The tree is grouped by file (icon, name, directory, count badge), with the matching lines below. With only one file, the header row is dropped.
  - On open: selects the reference nearest the anchor position and focuses the tree (`editor.peekWidgetDefaultFocus`: `tree` default | `editor`).
- **Keys in peek** (`referencesController.ts`): `closeReferenceSearch` (`Esc`), `goToNextReference` / `goToPreviousReference` (`F4` / `Shift+F4`), `togglePeekWidgetFocus` (`Cmd+K F2`), `revealReference` (`Enter`, `Cmd+Down`), `openReferenceToSide` (`Ctrl+Enter`). Clicking a row previews it; double-clicking in the preview editor opens it in the main editor and closes peek, unless `editor.stablePeek` (default `false`).
- Context keys: `referenceSearchVisible`, `inReferenceSearchEditor`.

### 3.2 Zed
No peek. "Peek" appears neither in `crates/editor` nor in the docs. The closest things are the hover popover and the `lsp_locations` picker with preview.

### 3.3 Similarities and differences
Peek is where the two differ most. Peek needs a second editor embedded between the lines of the main editor, which is fairly costly in GPUI. A picker with preview covers most of the "quick look without leaving the place" need and reuses the existing picker.

## 4. Find references

### 4.1 VS Code
- `Shift+F12` = `editor.action.goToReferences`: with `multipleReferences: peek` it opens peek (one result jumps directly); the request has `includeDeclaration: true`.
- `editor.action.referenceSearch.trigger` (Peek References, no key) always opens peek, `includeDeclaration: false`.
- `Shift+Alt+F12` = `references-view.findReferences` (the built-in extension *references-view*): a "References" tree in the sidebar, titled "N results in M files", with history, refresh, clear, copy, and removing individual items. `F4` / `Shift+F4` = `references-view.next` / `.prev`. There are also `references-view.findImplementations` and `references-view.showCallHierarchy` (`Shift+Alt+H`).
- `references.preferredLocation`: `peek` (default) | `view`.

### 4.2 Zed
- `FindAllReferences` sends `textDocument/references` to every server that supports it, merging and de-duplicating. Calling it again while the request for the same position is still running is ignored.
- One result (after dropping the range that contains the current selection) jumps directly. Otherwise it opens a multibuffer tab **"References to <symbol>"**:
  - Each matching region becomes an excerpt with 2 context lines (`excerpt_context_lines`), and overlapping regions are merged.
  - An identical tab (same title and ranges) is **reused**, with no new tab opened.
  - The first match is selected; all matches get the background `editor.highlighted_line.background`.
  - The file header is like the Project Search tab: `FILE_HEADER_HEIGHT = 2` lines tall, a `rounded_sm` card, a 1 px `border` (when selected: `border_focused`), background `editor.subheader.background`, hover `element.hover`; with a 28 px fold button, a dimmed file icon, the file name, a dimmed directory; the header is sticky while scrolling.
  - `alt-enter` (`editor::OpenExcerpts`) opens the real file, `cmd-alt-enter` opens a split.
- When `lsp_results_location = "picker"`: a modal with the placeholder "Filter references…", rows grouped under file headers (icon, name, dimmed directory), each match has a right-aligned dimmed line number column and a text line with the match highlighted in `search.match_background`; a preview pane beside it; when empty, "No references found".

### 4.3 Similarities and differences
- VS Code has three places that show references (peek, the sidebar view, CodeLens); Zed has two (multibuffer tab, picker).
- Lucerna already has the multibuffer header and sticky header for the Search tab (see `2026-11-10-project-search-ui.md` §6), so a "References to X" tab can reuse them almost unchanged. A picker with preview suits a viewer better for quick actions.

## 5. Hover

### 5.1 VS Code
- Appears after `editor.hover.delay`, above the line if there is room (`editor.hover.above`).
- Content is assembled from the participants in order: the **diagnostic part first**, then the LSP markdown part, separated by a rule. One block per provider. A slow provider shows `Loading...` **[latency unverified]**.
- Diagnostic part: message, source, code (can be a link), related information as clickable `file(line, col): message`; the row below has **View Problem** (`Alt+F8`) and **Quick Fix...** (Lucerna can drop these).
- Markdown: code fences are colored by language, links are clickable, command links only when the MarkdownString is trusted.
- **Settings:**

  | Key | Default |
  |---|---|
  | `editor.hover.enabled` | `"on"` (`on` \| `off` \| `onKeyboardModifier`) |
  | `editor.hover.delay` | `300` |
  | `editor.hover.sticky` | `true` |
  | `editor.hover.hidingDelay` | `300` |
  | `editor.hover.above` | `true` |

- **Commands:** `editor.action.showHover` (`Cmd+K Cmd+I`; when already showing, focuses the hover), `editor.action.showDefinitionPreviewHover`, `editor.action.hideHover` (`Esc`), scroll inside the hover with arrows / PageUp / PageDown / Home / End when `editorHoverFocused`.

### 5.2 Zed
- **Timing** (`crates/editor/src/hover_popover.rs`): `hover_popover_enabled` true, `hover_popover_delay` **300 ms**, `hover_popover_sticky` true, `hover_popover_hiding_delay` 300 ms.
- **Half-delay prefetch:** waits half the delay and then *sends* the request, waits the other half and only then shows it. If the mouse moves, the old task is dropped and the request is canceled with `$/cancelRequest`. This hides latency without spamming the server when the mouse moves fast.
- No new request is sent if the mouse is still within the range of the symbol or the diagnostic being shown.
- `editor::Hover` (`cmd-k cmd-i`) shows immediately at the cursor, without waiting.
- Sticky: computes the distance from the mouse to the popover (4 px tolerance); moving away starts counting down `hover_popover_hiding_delay`, coming back close resets it, entering the popover cancels it. Hidden on typing, scrolling, or opening a context menu. The symbol being hovered gets the background `element.hover`.
- **Content:** the request goes to every server that supports it, one `InfoPopover` per response. The PlainText / Markdown / Code blocks are merged into one markdown string, at most `MAX_HOVER_BYTES = 100_000`. Prose uses the UI font, code blocks use the colored buffer font, with a copy button and wrapping. File links open in the editor, other URLs open in the browser.
- **Diagnostic popover:** the narrowest diagnostic containing the mouse position is rendered separately, stacked with the info popover. Background `<sev>.background`, 1 px border `<sev>.border`, padding `py_1 pl_2 pr_8`.
- **Size and position** (`element.rs`):
  - Info popover: `elevation_2` (background `elevated_surface.background`, border, shadow), padding `p_2`, `gap_2`, scrolls vertically.
  - Maximum width min(**120 em**, half the editor), minimum 20 characters; maximum height min(**16 lines**, half the editor), minimum 4 lines.
  - Placed above the line if it fits, otherwise below. Popovers are spaced `HOVER_POPOVER_GAP = 10 px` apart, and the gap is filled with an invisible cover so the mouse passing through does not hide them. `POPOVER_RIGHT_OFFSET = 8 px` from the right edge.

### 5.3 Similarities and differences
The behavior almost matches: 300 ms delay, sticky, 300 ms hiding delay, `cmd-k cmd-i`, diagnostic on top. Zed adds the prefetch trick and explicit size rules. Lucerna takes VS Code's `editor.hover.*` settings and Zed's UI and timing.

## 6. Diagnostics

### 6.1 VS Code
- **In the editor** (`editor/common/services/markerDecorationsService.ts`):
  - Squiggles by severity: Error red, Warning yellow, Info blue. **Hint** is just three dots under the first 2 characters.
  - The `Unnecessary` tag fades the text, `Deprecated` strikes it through.
  - An empty range is expanded to the whole word. A whole-line marker starts at the first non-whitespace character.
  - The overview ruler (`editorOverviewRuler.errorForeground`…) and the minimap have colored ticks.
  - **No icon in the gutter**: the marker's decoration only sets `className`, `inlineClassName`, `overviewRuler`, `minimap`, with no `glyphMarginClassName`.
- **Note for a read-only viewer:** `editor.renderValidationDecorations` (`'editable' | 'on' | 'off'`, default **`'editable'`**) hides all error squiggles when the editor is read-only. This is an internal Monaco option, not in the Settings UI. Lucerna is always read-only, so copying the `editable` semantics verbatim would lose every squiggle. Lucerna must treat the viewer as `on`.
- **Navigation** (`editor/contrib/gotoError/browser/gotoError.ts`):

  | Command ID | Key |
  |---|---|
  | `editor.action.marker.next` / `.prev` (within the file) | `Alt+F8` / `Shift+Alt+F8` |
  | `editor.action.marker.nextInFiles` / `.prevInFiles` | `F8` / `Shift+F8` |
  | `closeMarkersNavigation` | `Esc` |

  Opens a zone widget below the error line: a frame colored by severity, a title like `file.rs  1 of 5 problems`, the message, source/code, related information, previous/next buttons. Only Error, Warning and Info count (Hint is dropped), ordered by `problems.sortOrder` (`severity` default | `position`), wrapping around to the start when it runs out.
- **Problems panel** (`workbench/contrib/markers/browser/markers.contribution.ts`):
  - The view `workbench.panel.markers.view` is in the Panel, opened with `workbench.actions.view.problems` (**`Cmd+Shift+M`**).
  - A tree by file (default) or a table (`problems.defaultViewMode`).
  - The filter box (`Cmd+F`) supports text, globs, and `!` for exclusion; the filter menu has Errors / Warnings / Infos / Active File Only / Excluded Files.
  - `Enter` opens (`problems.action.open`), `Ctrl+Enter` opens to the side (`problems.action.openToSide`). A total-count badge on the panel tab.
- **Status bar:** the `status.problems` item on the left, priority 50: `$(error) N $(warning) M`, plus `$(info) K` when K > 0. Above 999 becomes `1K`, above 9999 becomes `10K+`. Tooltip `Errors: N, Warnings: M, Infos: K` or `No Problems`. Click calls `workbench.actions.view.toggleProblems`.
- **Explorer and tabs:** a file with Error/Warning gets a colored name (`list.errorForeground` / `list.warningForeground`), a count badge (`1`..`9`, `9+`), and the color propagates up to parent folders.
- **Settings:**

  | Key | Default |
  |---|---|
  | `problems.visibility` | `true` |
  | `problems.decorations.enabled` | `true` |
  | `problems.autoReveal` | `true` |
  | `problems.defaultViewMode` | `"tree"` |
  | `problems.showCurrentInStatus` | `false` |
  | `problems.sortOrder` | `"severity"` |
  | `editor.renderValidationDecorations` | `"editable"` |

### 6.2 Zed
- **Storage** (`crates/project/src/lsp_store.rs`):
  - Diagnostics are ordered by severity, with related information gathered into **groups** (one primary and the secondary entries).
  - Stored per buffer **and per server**, as anchors so they shift with the content automatically. For a buffer not yet open, they are kept by path.
  - Each path has a summary (error and warning counts) for the UI to display.
  - Supports both push (`publishDiagnostics`) and pull (`diagnostics.lsp_pull_diagnostics.enabled`, on by default, debounce 50 ms; the workspace pull repeats after 2 s).
  - "Disk-based" diagnostics (cargo check) are mapped from the saved version to the current version.
- **In the editor:**
  - **1 px** squiggles, colored `error` / `warning` / `info` / `hint` (anything else `ignored`). Filtered by `diagnostics_max_severity` (default `"all"`).
  - "Unnecessary" code is faded by `unnecessary_code_fade` (default `0.3`) instead of being underlined.
  - **No gutter icon by default.** The scrollbar has markers (`scrollbar.diagnostics: "all"`).
  - Inline diagnostics (error-lens style): `diagnostics.inline.enabled` defaults to **false**. When on: a one-line pill, 4 em after the end of the line, `px_1`, `rounded_xs`, a background in the severity color at 5% alpha, text in the severity color, `text_sm`, buffer font.
- **`f8` / `shift-f8`** (`editor::GoToDiagnostic` / `GoToPreviousDiagnostic`): jumps to the next diagnostic in the buffer and **activates** its group, inserting a block below the lines. Block: a **2 px** left border in the severity color, background `<sev>.background`, `pl_1p5 pr_0p5`, at most 120 em wide, a markdown body, a copy button; the primary has "(source code)" (the code is a link if `codeDescription.href` exists). `Esc` or moving the cursor hides it.
- **Status bar** (`crates/diagnostics/src/items.rs`): when clean, a `Check` icon; with errors, an `XCircle` in the Error color + count, a `Warning` in the Warning color + count, small icons and labels, `gap_1`. Next to it is the diagnostic message at the cursor (first line) as a small button; clicking it jumps to the next diagnostic. Setting `diagnostics.button: true`.
- **Project diagnostics** (`cmd-shift-m` → `diagnostics::Deploy`):
  - A "Diagnostics" multibuffer tab, the tab title carries a count; when empty "No problems in workspace".
  - Each group whose highest severity is ≥ warning becomes a block below the excerpt (`ToggleWarnings` to keep only errors).
  - The excerpt context is expanded with tree-sitter to the outline item containing it, if that item is under `DIAGNOSTIC_EXPANSION_ROW_LIMIT = 32` lines.
  - Updates are debounced 50 ms; buffers with no change are skipped.
- Tabs (`tabs.show_diagnostics`, off by default) and the project panel (`project_panel.show_diagnostics`, default `"all"`) color file names by severity.

### 6.3 Similarities and differences
- Same: squiggles, fading unneeded code, scrollbar markers, no gutter icon, a count in the status bar, `Cmd+Shift+M`.
- Different for `F8`: VS Code `F8` goes across files and `Alt+F8` within the file; Zed `f8` is within the buffer only. Lucerna follows VS Code.
- Different for the list: VS Code is a tree panel with a filter box; Zed is a multibuffer tab that shows the surrounding code directly. For a viewer, the multibuffer tab shows context without opening the file and reuses the Search tab infrastructure.
- Different for the status bar: Zed additionally shows the message at the cursor (VS Code has it but off by default, `problems.showCurrentInStatus`).

## 7. Outline

### 7.1 VS Code
- The Outline view lives in the **Explorer** container (`order: 2`), collapsed by default, and can be dragged elsewhere; `outline.focus`.
- The data source is the LSP `textDocument/documentSymbol` of the active editor, shown as a tree with icons by kind; symbols that contain errors are colored and have a badge.
- Messages: `The active editor cannot provide outline information.`, `Loading document symbols for 'x'...`, `No symbols found in document 'x'`.
- Clicking a node: reveals the symbol in the editor, focus stays in the tree (150 ms delay to tell it apart from a double-click); double-click: reveals and focuses the editor.
- The "…" menu (state saved per workspace, not a setting): `outline.followCursor` (off by default), `outline.filterOnType` (on by default), `outline.sortByPosition` / `sortByName` / `sortByKind`, `outline.collapse` / `outline.expand`.
- Settings: `outline.icons` (`true`), `outline.collapseItems` (`alwaysExpand` default), `outline.problems.enabled` / `.colors` / `.badges` (`true`), `outline.show<Kind>` for every SymbolKind (default `true`).

### 7.2 Zed
- **Source:** the per-language setting `document_symbols`, default `"off"`, meaning use the **tree-sitter `outline.scm`**. `"on"` switches to LSP `documentSymbol` for both the outline and breadcrumbs. A single entry point (`buffer_outline_items`) serves the outline modal, the outline panel and breadcrumbs.
- **Captures in `outline.scm`:** `@item` (the whole node), `@name` (the name, used for fuzzy matching), `@context` (keywords like `pub`, `fn`, `impl`, shown along with the name), `@context.extra`, `@annotation` (attributes, doc comments), `@open` / `@close` (compute `body_range`).
- **Item text:** context and name joined in source order, separated by one space, into a short signature like `pub struct OutlineItem`, colored by the syntax theme. For LSP items, the name and detail are re-parsed with the grammar so they get colors too.
- **Fuzzy match:** the candidate string is "ancestor path + item text" (for example `impl Foo fn bar`). A single-word query only matches at the leaf part; a multi-word query uses the ancestor part to narrow, and fully matched ancestors become non-selectable "context rows".
- **Outline modal** (`cmd-shift-o`): with an empty query, it selects the deepest item containing the cursor. Moving the selection highlights the item's lines in the editor (`editor.highlighted_line.background`) and scrolls to the middle; Enter places the cursor; `Esc` restores the old position. A row is a `ListItem` (inset, sparse), indented 1 rem per level, **buffer font at buffer size**, matched characters highlighted with a `text.accent` 30% alpha background. Placeholder "Search buffer symbols...".
- **Outline panel** (`cmd-shift-b`): a dockable panel (right side by default, 300 wide, `indent_size` 20, indent guides), follows the cursor, has a filter box. Click selects and scrolls the editor, double-click jumps and focuses the editor.

### 7.3 Similarities and differences
- VS Code depends on LSP: no server means no outline. Zed has an outline right from tree-sitter, with LSP optional.
- Lucerna already has tree-sitter and queries from Zed extensions (`outline.scm` is a valid query, see `2026-11-09-extensions.md` §5), so following Zed's default makes sense. Command names and keys still follow VS Code (`workbench.action.gotoSymbol`, `Cmd+Shift+O`).

## 8. Breadcrumbs

### 8.1 VS Code
- A bar below the tab row: **path segments** (folders relative to the workspace → file, with icons) then the **symbol path** (the ancestors containing the cursor, with kind icons), separated by chevrons.
- **Clicking a segment** opens a dropdown picker right below that segment (`maxHeight = min(0.7 * windowHeight, 300)`, `width = max(240, innerWidth/4.17)`):
  - Folder/file segment: the file tree of the parent folder, select to open.
  - Symbol segment: the outline tree, filtered as you type, sorted by `breadcrumbs.symbolSortOrder`. Focusing an item previews it in the editor; canceling restores.
- **Keys:** `breadcrumbs.focusAndSelect` (`Cmd+Shift+.`), `breadcrumbs.focus` (`Cmd+Shift+;`), `breadcrumbs.focusNext` / `focusPrevious` (`Right` / `Left`), `breadcrumbs.selectFocused` (`Enter` / `Down`), `breadcrumbs.revealFocused` (`Space` / `Cmd+Enter`), `breadcrumbs.selectEditor` (`Esc`), `breadcrumbs.toggle`, `breadcrumbs.copyPath`.
- **Settings:** `breadcrumbs.enabled` (`true`), `breadcrumbs.filePath` (`"on"` | `off` | `last`), `breadcrumbs.symbolPath` (`"on"` | `off` | `last`), `breadcrumbs.symbolSortOrder` (`"position"`), `breadcrumbs.icons` (`true`), `breadcrumbs.symbolPathSeparator` (`"."`), `breadcrumbs.show<Kind>` (`true`).

### 8.2 Zed
- `Breadcrumbs` is a `ToolbarItemView` on each pane (`toolbar.breadcrumbs: true`). The row is `h_8` tall (32 px), scrolls horizontally on overflow, UI font size.
- Content: the file path relative to the worktree (with the root name when several worktrees are open), then the **symbol chain at the cursor** (the tree-sitter outline items containing the cursor, with increasing depth). A symbol segment keeps its syntax color, is drawn in the **buffer font**, with the `Color::Muted` background color.
- The separator is `›` in `Color::Placeholder`, `gap_1`. At most `MAX_SEGMENTS = 12`; beyond that it keeps the first 6 and last 6, with `⋯` in the middle.
- The file icon only shows when the tab bar is hidden.
- **Click:** the whole row is one `ButtonLike` that opens the outline modal. The tooltip "Show Symbol Outline" comes with the key and "Right-Click to Copy Path"; right-click copies the path. **Individual segments are not separately clickable.**
- A multibuffer has no breadcrumbs on the toolbar; the excerpt header shows breadcrumbs instead.

### 8.3 Similarities and differences
The content is the same (path + symbol chain). The difference is in interaction: VS Code allows clicking each segment and keyboard navigation, while Zed folds the whole row into one button that opens the outline. Zed's way is much cheaper because it reuses the outline modal.

## 9. Quick Open `@` and `#`

### 9.1 VS Code
- **`@` — Go to Symbol in Editor** (`workbench.action.gotoSymbol`, **`Cmd+Shift+O`**; or type `@` in `Cmd+P`):
  - The source is the document symbols of the active editor, flattened (label = name, description = container). A query with a space: the first word matches the name, the rest matches the container.
  - By default in file order. Typing **`@:`** groups by kind with separators like `classes (3)`, `methods (12)`…
  - **Preview while moving:** the editor scrolls to and highlights the symbol's range; `Esc` restores; `Enter` jumps. The entry at or before the cursor is preselected.
  - Messages: `The active text editor does not provide symbol information.`, `No matching editor symbols`, `No editor symbols`.
- **`#` — Go to Symbol in Workspace** (`workbench.action.showAllSymbols`, **`Cmd+T`**):
  - Sends `workspace/symbol { query }` to every provider, through a **200 ms `ThrottledDelayer`** (`TYPING_SEARCH_DELAY`); the previous request is canceled with a token.
  - The client fuzzy-matches the name (and container), sorts by score, then name, then kind. The description is `containerName • relative/path`. Deprecated ones are struck through.
  - On selection, it calls `workspaceSymbol/resolve` if the server supports it and then opens the file. **No preview while moving.**
  - Empty: `No matching workspace symbols`. `search.quickOpen.includeSymbols` (default `false`) mixes symbols into the `Cmd+P` results.

### 9.2 Zed
- `@` corresponds to the outline modal (§7.2).
- **Project symbols** (`cmd-t`, `crates/project_symbols`): placeholder "Search project symbols...".
  - On each keystroke: immediately filters the candidates it already has so the list responds instantly, then sends `workspace/symbol` to **every running server**. **No debounce**: the new task replaces the old one, and dropping the old task cancels the request.
  - Results are split into two groups: in-project (not ignored) first, outside the project/ignored after. At most `MAX_MATCHES = 100`.
  - For a query of the form `a::b::c` (rust-analyzer), only the last segment is used for client-side fuzzy matching, while the whole query is still sent to the server.
  - A two-line row: line 1 is a synthesized code label (for example `fn name()`, `struct Name`) colored with the grammar, buffer font, matched characters with a `text.accent` 30% background; line 2 is a small, dimmed `path:line`.

### 9.3 Similarities and differences
The keys are the same (`Cmd+Shift+O`, `Cmd+T`). VS Code debounces 200 ms; Zed does not debounce but cancels the old request on drop. VS Code has the `@:` group-by-kind mode, Zed does not. Zed has colored code labels, VS Code only has kind icons.

## 10. LSP client architecture

### 10.1 Zed (`crates/lsp`, `crates/project/src/lsp_store.rs`)
- **Transport:**
  - Hand-written JSON-RPC over the child process's stdio (`kill_on_drop`). `lsp-types` is a Zed fork; the original on crates.io is MIT, so Lucerna can use it directly.
  - Does not use tokio: GPUI's executor plus `smol`/`async-process`.
  - Only advertises the `UTF16` position encoding.
  - Write task: an unbounded outbound channel, writes `Content-Length: N\r\n\r\n` + body, flushes after each message.
  - Read task: reads the header up to `\r\n\r\n` (tolerates `Content-Type`, in any order), `read_exact` for the body. Requests/notifications from the server enter a **bounded channel of 128** (`INCOMING_MESSAGE_QUEUE_CAPACITY`) for backpressure; responses call the handler directly.
  - The dispatch loop runs on the app context and calls `yield_now` after each message so a server spamming notifications cannot freeze the UI. Requests from the server with no handler are answered `MethodNotFound` automatically.
  - Stderr task: reads line by line into the log; during startup it is also kept to attach to the error message if `initialize` fails.
- **Requests:** incrementing ids. Each request has a timer, default `DEFAULT_LSP_REQUEST_TIMEOUT_SECS = 120` (setting `global_lsp_settings.request_timeout`, 0 means unlimited). On expiry it is `Timeout`; if the server dies it is `ConnectionReset`.
- **Cancel-on-drop:** the request's future holds a guard; if the future is dropped before a response arrives, the guard sends `$/cancelRequest {id}`. The UI just drops the old task (new hover position, new symbol query) and the server is told to stop automatically. This is the pattern most worth learning.
- **Lifecycle:**
  - A server starts lazily when a buffer of that language is registered (a file is opened or its language was just detected). Skipped for non-local files, files with a line longer than `global_lsp_settings.max_buffer_line_length` (default 20000, blocks minified files), and files with no language.
  - Server identity: (worktree, server name, toolchain, binary + init options in settings). Changing the binary or init options in settings produces a new identity and the server is restarted. One server serves the whole worktree; other subprojects are added as **workspace folders** instead of running another process.
  - Startup order: find the binary → spawn → compute `workspace_configuration` and `initialization_options` (the adapter's defaults deep-merged with `lsp.<server>.initialization_options`, the user wins) → register every handler **before** sending `initialize` → `initialize` → `initialized` → `workspace/didChangeConfiguration` right away. On failure the state is `Failed` with the kept stderr, and the activity indicator shows "Failed to run X. Click to show error."
  - Binary states: `None | CheckingForUpdate | Downloading | Starting | Stopping | Stopped | Failed{error}`.
  - For a worktree that is not trusted yet (restricted mode), finding the binary waits until the user trusts it.
- **Finding the root:** walks up from the file's directory looking for the language's `manifest_name` (`Cargo.toml` for Rust, `pyproject.toml` for Python, most have none). For Cargo it takes the **farthest ancestor** with a `Cargo.toml` (within a depth limit), to use the workspace root instead of each crate.
- **Document sync:**
  - `didOpen` with version 0 and the full text.
  - `didChange` according to the server's capability: `FULL` sends the whole text, `INCREMENTAL` sends each edit with a UTF-16 range. The version increments by 1 each time.
  - Keeps the 10 most recent snapshots (`OLD_VERSIONS_TO_RETAIN = 10`) per (buffer, server), so a diagnostic tagged with an old version is interpreted correctly against the text the server saw.
  - `didSave` is sent to every server that registered for it; `didClose` when the buffer closes.
  - `didChangeWatchedFiles` is registered dynamically, reusing the worktree scanner's events without creating a new OS watcher.
  - Refreshing LSP data in the editor is debounced `LSP_REQUEST_DEBOUNCE_TIMEOUT = 50 ms`.
- **Server requests that must be answered** (otherwise some servers hang):
  - `workspace/configuration`: returns `config[section]` for each item; the default adapter returns `lsp.<server>.settings`.
  - `window/workDoneProgress/create`: always returns OK (a comment in the code says gopls hangs otherwise).
  - `client/registerCapability` / `unregisterCapability`: dynamic registration.
  - `workspace/workspaceFolders`: returns the current set of folders.
  - `window/showMessageRequest`: shows a prompt with buttons.
  - Notifications: `window/showMessage` (the notice auto-hides after `notifications.dismiss_timeout_ms` 5000), `window/logMessage` (into the log), `$/progress` (updates running work, the token `rust-analyzer/flycheck` marks cargo check).
- **Shutdown:** a `shutdown` request with `SERVER_SHUTDOWN_TIMEOUT = 5 s` → `exit` → close the channel → wait for writes to finish (sharing the same 5 s) → kill. Dropping the last `LanguageServer` runs this procedure automatically. On app quit, all servers are shut down in parallel.
- **Crash:** **no auto-restart.** When the process dies, stdout hits EOF, pending requests become `ConnectionReset`, and the state stays until the user restarts via `editor::RestartLanguageServer` / `StopLanguageServer` or the LSP button menu.
- **Management UI:**
  - The LSP button on the status bar (`BoltOutlined`, with a colored dot: Error when a server fails, Warning on a health warning or restricted mode). The popover lists servers by worktree, each server has a status dot and a Restart / Stop / open log submenu; at the bottom are Restart All / Stop All.
  - Log view: a read-only buffer with dropdowns to pick the server and kind: Server Logs (logMessage + stderr), Server Trace (`$/logTrace`), RPC Messages (only recorded while the view is open), Server Info. At most `MAX_STORED_LOG_ENTRIES = 2000` per kind.
  - Activity indicator: a spinner + "{title} ({pct}%): {message} + N more", "Downloading X…", "Failed to run X. Click to show error."

### 10.2 vscode-languageclient
- States: `initial → starting → running → stopping → stopped` (+ `startFailed`).
- Startup: spawn (stdio/IPC/socket), `initialize` (capabilities, `rootUri`, `workspaceFolders`, `initializationOptions`, `processId`, `trace`), then `initialized`. An init error is decided by `initializationFailedHandler`.
- Sync: only documents that match `documentSelector`; `didOpen` / `didChange` (full or incremental) / `didClose` / `didSave`. A viewer only needs `didOpen` / `didClose`, plus reopening when the file changes on disk.
- **Restart (`DefaultErrorHandler`):** `maxRestartCount` defaults to **4**. Each time the connection closes it records a timestamp; on the 5th close, if the 5 are within **3 minutes**, it does not restart any more and reports `The <name> server crashed 5 times in the last 3 minutes. The server will not be restarted. See the output for more information.`; otherwise it drops the oldest timestamp and restarts. For message-level errors: ignores the first 3, then shuts down.
- **Shutdown:** `shutdown` then `exit`, timeout **2000 ms** (`stop(timeout = 2000)`).
- **Log:** a `LogOutputChannel` named after the client in the Output panel, optionally with a `traceOutputChannel`. `revealOutputChannelOn` defaults to `Error`; an error shows a notification with "Go to output".
- **Trace:** `<clientId>.trace.server` (`off` | `messages` | `verbose`, or `{verbosity, format: text|json}`). Newer versions only trace when the channel's log level is Trace; changing the log level resends `$/setTrace`.
- `window/showMessage` becomes a notification, `window/logMessage` goes to the output, `$/progress` becomes progress in the status bar, and diagnostics (push or pull) go into the client's own `DiagnosticCollection` and then into the marker service.

### 10.3 Similarities and differences
- Both: lazy start, `shutdown` then `exit` with a timeout, a log per server, answering the mandatory requests.
- Differences: VS Code restarts automatically with a limit, Zed leaves the restart to the user. VS Code's shutdown timeout is 2 s, Zed's 5 s. Zed has a timeout for every request and cancel-on-drop at the transport layer; VS Code relies on cancellation tokens in each feature.
- **Workspace trust:** VS Code does not activate extensions with `capabilities.untrustedWorkspaces.supported: false` (rust-analyzer declares this) when the folder is not trusted, so the server does not run; path-type settings such as the binary path only take the user-level value in Restricted Mode. Zed also waits for trust before finding the binary. Lesson for Lucerna: running a language server means running code controlled by the project (build scripts, proc macros), so a trust mechanism is needed before enabling LSP.

## 11. How a language server is obtained

### 11.1 Zed: native adapters and extensions
- **Native adapters** (`crates/languages/src/*.rs`, GPL):

  | Language | Server | How it is obtained |
  |---|---|---|
  | Rust | rust-analyzer | the worktree's rustup toolchain, then `which`; each candidate is **trial-run** with `--help` because the rustup proxy in `~/.cargo/bin` often fails when a component is missing; if none, downloads `rust-analyzer-<arch>-<target>.gz` from a GitHub release |
  | Go | gopls | needs `go` on PATH; `which gopls`, otherwise `go install golang.org/x/tools/gopls@latest` with `GOBIN` set to its own directory |
  | TS / TSX / JS | vtsls (default), typescript-language-server | `npm install` through the Node managed by Zed; prefers the version installed in the project |
  | Python | basedpyright, ruff, ty, pyright, pylsp, pyrefly | npm or a GitHub/PyPI binary |
  | JSON / JSONC, YAML, CSS, Bash | vscode-json-language-server, yaml-language-server, vscode-css-language-server, bash-language-server | npm |
  | C / C++ | clangd | GitHub release |
  | (many languages) | tailwindcss-language-server, eslint | npm |

  No server: diff, env, markdown, regex, gitcommit.
- **Binary lookup order:** (1) a binary the user installed on PATH (unless `binary.ignore_system_version`), not cached because each worktree may give a different result (for example `node_modules/.bin`); (2) the in-memory cached version; (3) the version downloaded last time in `languages_dir()/<server>`, while checking for a newer version in parallel; if the download fails, the old version is used. If both an old binary and an update exist, it waits at most `SERVER_DOWNLOAD_TIMEOUT = 10 s`, then uses the old one and keeps downloading in the background.
- **Download directory:** `~/Library/Application Support/Zed/languages/<server-name>/`.
- **Environment:** the login shell's env for the worktree is mixed in beneath `binary.env`.
- **Extensions:** every other language (Ruby, PHP, Elixir, Java, Kotlin, Swift, Zig, TOML, HTML, Svelte, Vue, Astro…) gets its server through WASM extensions (§12). `default.json` already lists `language_servers` for these languages so the order is right when installed.

### 11.2 VS Code: each extension handles it
- **There is no shared "language servers" setting.** Each language extension bundles the client and has its own settings namespace. For example rust-analyzer: `rust-analyzer.server.path` (null = the bundled binary), `rust-analyzer.server.extraEnv`, `rust-analyzer.trace.server` (`off` by default), `rust-analyzer.restartServerOnConfigChange` (`false`), `rust-analyzer.initializeStopped` (`false`).
- The restart commands are also per extension: `rust-analyzer.restartServer`, `rust-analyzer.startServer`, `rust-analyzer.stopServer`; `typescript.restartTsServer`, `eslint.restart` **[unverified]**.
- Lazy activation through `activationEvents`: `workspaceContains:Cargo.toml`, `onLanguage:<id>`…

### 11.3 Zed settings
- `languages.<L>.enable_language_server` (bool, default `true`).
- `languages.<L>.language_servers` (default `["..."]`): an ordered list; `!name` disables a server; `"..."` expands to every server registered for the language that is not yet listed. A server disabled by default (for example `typescript-language-server`, `ty`, `pyrefly`) is never pulled in by `"..."`. The order also decides the primary server. Python example: `["basedpyright", "ruff", "!ty", "!pyrefly", "!pyright", "!pylsp", "..."]`.
- `lsp.<server>`: `binary { path, arguments, env, ignore_system_version }`, `initialization_options` (deep-merged with the adapter's defaults), `settings` (returned for `workspace/configuration` and `didChangeConfiguration`), `fetch { pre_release }`.
- `global_lsp_settings`: `button`, `request_timeout` (120), `max_buffer_line_length` (20000), `notifications.dismiss_timeout_ms` (5000).
- Toggles relevant to a viewer: `hover_popover_*`, `lsp_highlight_debounce` (75 ms), `go_to_definition_fallback`, `go_to_definition_scroll_strategy`, `lsp_results_location`, `diagnostics_max_severity`, `diagnostics.{button, include_warnings, lsp_pull_diagnostics, inline}`, `document_symbols`, `semantic_tokens` (`"off"`), `excerpt_context_lines` (2), `toolbar.breadcrumbs`, `scrollbar.diagnostics`.

### 11.4 Similarities and differences
VS Code pushes everything to each extension, with one settings style per server. Zed gathers it into one shared shape `lsp.<server>`. Lucerna cannot run VS Code extensions, and Zed's WASM extensions read exactly the `lsp.<server>` shape through `get-settings` (§12.2), so keeping Zed's key names for this part is reasonable even though the other settings follow VS Code.

  | `since_v0.0.6` | lsp, nodejs, settings |

A missing or wrong section is a hard error. The `extension.toml` manifest has `[lib] kind = "Rust", version = "x.y.z"`; the registry has `wasm_api_version`.

### 12.4 How Zed hosts it (design only)
- **Engine:** one global `wasmtime::Engine`, with the component model and **epoch interruption** enabled, and a task that increments the epoch every ~100 ms. Each extension has its own `Store`, with a 1-tick deadline in **yield** mode back to the executor instead of trapping, so a guest cannot hold the thread more than ~100 ms per poll. No fuel and no hard timeout.
- **Bindings:** one `bindgen!` per version (imports `async | trappable`, exports `async`). Older versions map the shared interfaces to the latest version's types via `with:` and convert with `From`; the older version's host traits mostly forward to the new one.
- **Execution:** compiling and reading the version run on the background executor; initialization and all calls run on **tokio** because `wasmtime-wasi` does I/O through tokio. Each extension has a closure queue, with a single task draining the queue, so calls into the same extension are serialized. A host function that needs app state sends a closure to the main thread and waits.
- **WASI and work dir:** `<data_dir>/extensions/work/<id>/`. Env `PWD=<absolute work dir>`; the work dir is **preopened twice** (under the name `.` and under its absolute path), and nothing else (no sockets, no other directories). On the guest side, the `register_extension!` macro sets wasi-libc's cwd from `PWD` and disables `chdir`, so `env::current_dir()` returns the work dir. **A host that does not set `PWD` breaks the extension.**
- **Path sandbox** for `download-file` and `make-file-executable`: resolve relative to the work dir, normalize and reject if it escapes, canonicalize the nearest existing ancestor (handles symlinks), and require the result to be inside the work dir.
- **`download-file`:** GET with redirects, error if not 2xx; `uncompressed` writes directly, `gzip` decompresses the stream, `gzip-tar` reads into memory and then unpacks into the target **directory**, `zip` unpacks the stream.
- **Returned command:** a relative path is joined onto the work dir, an absolute one is kept as is; the extension's `env` overlays the process env.
- **Node:** uses `node` / `npm` on PATH if ≥ 22.0.0 (unless `node.ignore_system_version`), otherwise downloads Node v24.22.1, managed separately, into `<data_dir>/node/`. `npm-install-package` runs `npm install <name>@<version> --no-package-lock --save-exact` with the work dir as cwd.
- **Capabilities:** the manifest declares `[[capabilities]]` of kind `process:exec`, `download_file`, `npm:install`. The setting `granted_extension_capabilities` **grants all three with wildcards** by default. `process:exec` needs both a declaration in the manifest and the user's permission; the other two only need the user's permission (granted by default). `http-client.fetch` is not gated.
- **GitHub:** calls `api.github.com/repos/<repo>/releases`, sending `Authorization: Bearer $GITHUB_TOKEN` if the environment variable exists.
- **Building `extension.wasm`** (`extension_builder.rs`): ensures the `wasm32-wasip2` target (`rustup target add`), `cargo build --target wasm32-wasip2 --release`, strips custom sections except `zed:api-version` and `component-type:*`. wasip2 produces a component directly, with no preview1 adapter needed.

### 12.5 wasmtime 48: a single version
- Lucerna already compiles **wasmtime 48.0.8** through `tree-sitter 0.27` with the `wasm` feature (`wasmtime-c-api-impl 48.0.8`); Zed uses 48.0.7.
- Adding `wasmtime = { version = "48.0.8", default-features = false, features = ["runtime", "cranelift", "component-model", "async"] }` and `wasmtime-wasi = { version = "48.0.8", default-features = false, features = ["p2"] }` makes Cargo unify to **the same version**, only turning on extra features (turn off `wasmtime-wasi`'s defaults to avoid pulling in `wiggle`).
- New crates: `wasmtime-wasi`, `wasmtime-wasi-io`, the cap-std family, component macros, `wit-parser`, tokio with a runtime. About 40–60 crates. License `Apache-2.0 WITH LLVM-exception` (already anticipated in `deny.toml`), tokio MIT.
- **Pinning rule:** always keep Lucerna's `wasmtime` on the same major as the `tree-sitter` version in use; when tree-sitter bumps wasmtime, bump at the same time, otherwise Cargo builds two sets of wasmtime + cranelift (about 1 GB more in `target/`). Add a CI check: `cargo tree -d | grep wasmtime` must be empty.
- Tokio: pick a dedicated tokio runtime with 1–2 threads inside the host crate, separate from GPUI. Writing WASI p2 ourselves is not worth the effort.
- Vendor the WIT into Lucerna (for example `crates/lucerna-extension-host/wit/since_v0.6.0/`) together with `LICENSE-APACHE` and a NOTICE line.

### 12.6 Risks
1. **A Rust toolchain is needed to build `extension.wasm`.** Lucerna builds from source itself and does not use `api.zed.dev` (Phase 2 spec), so every extension with an LSP has to be compiled on the user's machine: it needs `cargo`, `rustup`, the `wasm32-wasip2` target (~1 GB), the first build downloads crates and takes 30–90 s per extension. Options: (a) require rustup, with a clear error when missing; (b) install a minimal toolchain ourselves (heavy); (c) revisit the "do not use `api.zed.dev`" decision just for `extension.wasm`; (d) Lucerna's CI prebuilds and rehosts, which brings a license review of distributing each extension. **This is the biggest product risk.**
2. **The work dir is shared with grammar building.** Lucerna currently uses `extensions/work/<id>/grammars` and `work/<id>/src` for cloned sources. Giving the guest write access to all of `work/<id>` exposes them, and some extensions (zig, lua) do `read_dir(".")` and then `remove_dir_all` everything not matching the current version. They must be separated: a directory for the guest's runtime only, with sources and grammars moved to `extensions/build/<id>/` (or use `extensions/runtime/<id>/`). To be settled before release.
3. **Node.** 7/23 extensions need Node (Vue, Svelte, Astro, PHP intelephense, Dockerfile, Prisma, Ruby). It needs node ≥ 22 on the machine or a downloaded copy (~100 MB), with npm running with the work dir as cwd and respecting the proxy/registry in npmrc.
4. **PATH of the login shell.** A GUI app on macOS does not inherit the login shell's PATH. `which` and `shell-env` must use an env captured from `$SHELL -l -i -c env` (per project directory if direnv is needed), cached. With a wrong PATH, an extension downloads a duplicate server.
5. **GitHub limits.** 13/23 extensions call `latest-github-release` on **every** server start. Unauthenticated gets only 60 requests/hour/IP. We need to read `GITHUB_TOKEN` and cache results in the host for a few minutes.
6. **Do not block the UI.** `npm install`, file downloads and GitHub calls can take minutes. Every extension call runs off the main thread, never `block_on` from GPUI; sequential within one extension, parallel across extensions.
7. **Guests that run forever.** Zed only yields, it does not kill. Lucerna should add a hard epoch-based deadline for the guest's CPU time; after a trap, reinitialize the instance.
8. **Sandboxing when extracting.** Check each entry (zip-slip, tar with `..` or absolute paths, symlinks pointing outside). If calling an external `tar` / `unzip`, use flags that reject such entries, or check the listing first.
9. **Compile latency.** Cranelift compiling a 1–3 MB component takes a few hundred ms to a few seconds. Cache with `Component::serialize` / `deserialize` into `extension.cwasm`, keyed by the wasmtime version and the wasm hash (`deserialize` is `unsafe`, only read files Lucerna wrote itself). Load lazily when the first file that needs a server is opened, to keep the goals of first frame < 200 ms and idle memory < 150 MB.
10. **Capabilities.** At minimum, respect `[[capabilities]] process:exec` in the manifest, and ask for confirmation the first time for an extension that declares exec or downloading executable files.
11. **Popular languages are still missing.** The WASM host does not provide rust/go/python/ts/json/yaml/css/bash/c, because Zed builds them as native adapters (GPL). Lucerna has to write native adapters for these languages itself, independent of the WASM host.

## 13. What Lucerna chooses

Settled with the user on 2026-11-10; details in `docs/superpowers/specs/2026-11-10-lucerna-phase3-lsp-design.md`.

| Topic | Choice | Reason |
|---|---|---|
| Server source | Prebuilt adapters for servers on PATH (rust-analyzer, gopls, pyright/basedpyright, typescript-language-server, clangd); no downloading by ourselves. The WASM host is split off into Phase 3b | The WASM host does not cover Rust/Go/Python/TS (Zed writes those servers in Rust), and it needs a Rust toolchain on the user's machine to build `extension.wasm` |
| Servers declared through settings | No | The user chose to use only the built-in adapters, like both VS Code and Zed |
| Architecture | A gpui-free `lucerna-lsp` crate, hand-written transport, using `lsp-types` | Testable with a fake server; does not pull in tokio |
| Peek and multiple results | A picker with preview (following Zed's `lsp_locations`) + a References tab reusing the Search tab UI | UI follows Zed; there is no insertion area in the editor |
| Symbol source | LSP `documentSymbol`, with the extension's `outline.scm` when there is no server | As accurate as VS Code, and still has an outline when there is no server |
| Outline | Only the `@` modal and breadcrumbs, no panel | Compact |
| Diagnostics | Squiggles (always shown even though read-only), gutter icon, inline (off by default), scrollbar ticks, status bar, F8; no Problems tab | Following the user's choice |
| Folder trust | Like Zed: Restricted Mode by default, a Trust modal, remember the choice, `session.trustAllWorktrees` | A server can run the project's code |
| Crash | No auto-restart (like Zed); Restart from the status popover | Simple, the user clearly sees the error |
