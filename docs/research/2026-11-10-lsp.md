## 1. Tóm tắt

| Chủ đề | VS Code | Zed | Lucerna nghiêng về |

| Peek | Zone widget chèn giữa các dòng, preview + cây kết quả | Không có | Chưa làm; picker có preview thay thế |

## 2. Go to definition

### 2.1 VS Code
- **Lệnh và phím** (`editor/contrib/gotoSymbol/browser/goToCommands.ts`):

  | Command ID | Phím |
  |---|---|
  | `editor.action.revealDefinition` | `F12` |
  | `editor.action.revealDefinitionAside` | `Cmd+K F12` |
  | `editor.action.peekDefinition` | `Alt+F12` |
  | `editor.action.goToTypeDefinition` / `peekTypeDefinition` | không có |
  | `editor.action.goToImplementation` | `Cmd+F12` |
  | `editor.action.peekImplementation` | `Cmd+Shift+F12` |
  | `editor.action.revealDeclaration` / `peekDeclaration` | không có |
  | `workbench.action.navigateBack` / `navigateForward` | `Ctrl+-` / `Ctrl+Shift+-` |

  Mỗi lệnh cần context key của provider tương ứng (`editorHasDefinitionProvider`…). Các mục "Go to …" nằm trong nhóm `navigation` của context menu, các biến thể peek nằm trong submenu "Peek".
- **Xử lý kết quả** (dùng chung cho mọi loại):
  1. Request bị hủy khi nội dung hoặc vị trí con trỏ đổi. Thanh tiến trình chỉ hiện sau 250 ms.
  2. **Không có kết quả:** bong bóng nhỏ tại con trỏ, ví dụ `No definition found for 'foo'`. Cmd+click thì im lặng.
  3. **Kết quả duy nhất trùng vị trí con trỏ:** chạy lệnh thay thế. `editor.gotoLocation.alternativeDefinitionCommand` (và bản Type Definition, Declaration) mặc định là `"editor.action.goToReferences"`; bản Implementation và Reference mặc định `""`. Kết quả là nhấn F12 ngay trên tên định nghĩa sẽ ra danh sách references.
  4. **Còn lại:** theo `editor.gotoLocation.multipleDefinitions` (và `multipleTypeDefinitions`, `multipleDeclarations`, `multipleImplementations`, `multipleReferences`), mặc định đều là **`peek`**: một kết quả thì nhảy, nhiều kết quả thì mở peek. `gotoAndPeek` nhảy tới kết quả đầu rồi mở peek; `goto` chỉ nhảy tới kết quả đầu.
  5. Khi nhảy: dùng `targetSelectionRange` nếu có, con trỏ đặt ở đầu, cuộn "gần đỉnh nếu đang ngoài viewport", vùng đích được tô sáng 350 ms.
- **Cmd+click / Cmd+hover** (`link/goToDefinitionAtPosition.ts`, `clickLinkGesture.ts`):
  - Phím kích hoạt là phím ngược với `editor.multiCursorModifier` (mặc định `alt`), tức **Cmd** trên mac; thêm **Alt** để mở bên cạnh.
  - Giữ Cmd khi rê chuột: request definition cho từ đang trỏ (hủy request trước). Có kết quả thì từ đó được gạch chân, đổi màu link, con trỏ chuột thành bàn tay.
  - Hover trên link: một kết quả thì preview mã nguồn đích, tối đa 8 dòng (`MAX_SOURCE_PREVIEW_LINES = 8`, cắt theo indent); nhiều kết quả thì chữ `Click to show N definitions.`
  - Click chạy Go to Definition với `openInPeek = editor.definitionLinkOpensInPeek` (mặc định `false`).
- **Lịch sử điều hướng:** `Ctrl+-` / `Ctrl+Shift+-`, mỗi lần nhảy tạo một mục. `workbench.editor.navigationScope` (`default` | `editorGroup` | `editor`). `workbench.editor.enablePreviewFromCodeNavigation` mặc định `false`: nhảy từ một preview tab sẽ ghim tab đó thay vì thay thế.

### 2.2 Zed
- **Lệnh và phím** (`assets/keymaps/default-macos.json`):

  | Action | Phím |
  |---|---|
  | `editor::GoToDefinition` / `GoToDefinitionSplit` | `f12` / `alt-f12` |
  | `GoToTypeDefinition` / `GoToTypeDefinitionSplit` | `cmd-f12` / `alt-cmd-f12` |
  | `GoToImplementation` | `shift-f12` |
  | `GoToDeclaration` / `GoToDeclarationSplit` | `ctrl-f12` / `alt-ctrl-f12` |
  | `FindAllReferences` | `alt-shift-f12` |
  | `pane::GoBack` / `pane::GoForward` | `ctrl--` / `ctrl-_` |

- **Hành vi** (`crates/editor/src/navigation.rs`):
  - Một kết quả thì nhảy thẳng, cuộn theo `go_to_definition_scroll_strategy` (mặc định `center`; còn có `minimum`, `top`, `preserve`).
  - Nhiều kết quả thì theo `lsp_results_location`: `"multi_buffer"` (mặc định) mở tab multibuffer tên "Definitions" / "Type Definitions" / "Implementations"; `"picker"` mở modal lọc được, có **pane preview** (crate `lsp_locations`).
  - Link trỏ về chính vị trí con trỏ bị loại.
  - Không điều hướng được gì và `go_to_definition_fallback = "find_all_references"` (mặc định) thì chạy Find All References. Cùng ý với lệnh thay thế của VS Code.
- **Cmd+hover link** (`hover_links.rs`): khi giữ `cmd`, Zed lần lượt thử: document link của server, URL trong text, đường dẫn file trong text, rồi definition LSP (thêm `shift` thì type definition). Kết quả cache theo range nên rê chuột trong cùng symbol không gửi lại request. Giao diện: gạch chân thẳng 1 px, màu chữ `link_text.hover`, con trỏ bàn tay. Click: `cmd` → definition, `cmd-shift` → type definition, thêm `alt` → mở split.
- **Lịch sử:** `NavHistory` của pane lưu (anchor, vị trí cuộn) trước mỗi lần nhảy, bỏ qua bước nhảy dưới `MIN_NAVIGATION_HISTORY_ROW_DELTA = 10` dòng. Có `preview_tabs.enable_preview_file_from_code_navigation` và `enable_keep_preview_on_code_navigation`.

### 2.3 Giống và khác
- Giống: `F12`, Cmd+click, `Ctrl+-` quay lại, fallback sang references khi đã đứng ở định nghĩa.
- Khác về phím: VS Code `Cmd+F12` là Implementation, `Shift+F12` là References; Zed `cmd-f12` là Type Definition, `shift-f12` là Implementation. Lucerna theo VS Code.
- Khác về nhiều kết quả: VS Code mở peek tại chỗ, Zed mở tab multibuffer hoặc picker có preview.

## 3. Peek

### 3.1 VS Code
- **Bố cục** (`gotoSymbol/browser/peek/referencesWidget.ts`, `peekView/browser/peekView.ts`):
  - Một **zone widget** chèn dưới dòng neo, đẩy các dòng sau xuống (không phải overlay), có mũi tên nhỏ chỉ vào vị trí neo.
  - Header: tên file đang preview, thư mục mờ, nhãn `References (12)` / `Definitions (3)`, nút đóng. Đang tải thì `Loading...`, rỗng thì `No results`.
  - Thân: SplitView ngang, **trái là editor preview** (tắt minimap, rộng tối thiểu 200 px), **phải là cây kết quả** (tối thiểu 100 px, nền `peekViewResult.background`). Tỉ lệ mặc định 0.7 / 0.3, cao 18 dòng; lưu vào storage key `peekViewLayout` khi đóng.
  - Cây gom theo file (icon, tên, thư mục, badge số lượng), dưới là từng dòng khớp. Chỉ có một file thì bỏ hàng header.
  - Khi mở: chọn reference gần vị trí neo nhất, focus vào cây (`editor.peekWidgetDefaultFocus`: `tree` mặc định | `editor`).
- **Phím trong peek** (`referencesController.ts`): `closeReferenceSearch` (`Esc`), `goToNextReference` / `goToPreviousReference` (`F4` / `Shift+F4`), `togglePeekWidgetFocus` (`Cmd+K F2`), `revealReference` (`Enter`, `Cmd+Down`), `openReferenceToSide` (`Ctrl+Enter`). Click một dòng thì preview; double-click trong editor preview thì mở ở editor chính và đóng peek, trừ khi `editor.stablePeek` (mặc định `false`).
- Context key: `referenceSearchVisible`, `inReferenceSearchEditor`.

### 3.2 Zed
Không có peek. Không thấy "peek" trong `crates/editor` lẫn docs. Thứ gần nhất là hover popover và picker có preview của `lsp_locations`.

### 3.3 Giống và khác
Peek là chỗ hai bên khác nhau nhiều nhất. Peek cần nhúng một editor thứ hai vào giữa các dòng của editor chính, khá tốn công trong GPUI. Picker có preview đáp ứng phần lớn nhu cầu "xem nhanh mà không rời chỗ" và dùng lại được picker sẵn có.

## 4. Find references

### 4.1 VS Code
- `Shift+F12` = `editor.action.goToReferences`: với `multipleReferences: peek` thì mở peek (một kết quả thì nhảy thẳng); request có `includeDeclaration: true`.
- `editor.action.referenceSearch.trigger` (Peek References, không phím) luôn mở peek, `includeDeclaration: false`.
- `Shift+Alt+F12` = `references-view.findReferences` (extension có sẵn *references-view*): cây "References" ở sidebar, tiêu đề "N results in M files", có lịch sử, refresh, clear, copy, xóa từng mục. `F4` / `Shift+F4` = `references-view.next` / `.prev`. Cũng có `references-view.findImplementations`, `references-view.showCallHierarchy` (`Shift+Alt+H`).
- `references.preferredLocation`: `peek` (mặc định) | `view`.

### 4.2 Zed
- `FindAllReferences` gửi `textDocument/references` tới mọi server hỗ trợ, gộp và khử trùng lặp. Gọi lại khi request cho cùng vị trí còn chạy thì bỏ qua.
- Một kết quả (sau khi loại range chứa selection hiện tại) thì nhảy thẳng. Còn lại mở tab multibuffer **"References to <symbol>"**:
  - Mỗi vùng khớp thành một excerpt với 2 dòng ngữ cảnh (`excerpt_context_lines`), các vùng chồng nhau được gộp.
  - Tab giống hệt (cùng tiêu đề và range) được **dùng lại**, không mở tab mới.
  - Chọn match đầu; mọi match được tô nền `editor.highlighted_line.background`.
  - Header file như tab Project Search: cao `FILE_HEADER_HEIGHT = 2` dòng, thẻ `rounded_sm`, viền 1 px `border` (khi chọn: `border_focused`), nền `editor.subheader.background`, hover `element.hover`; có nút gập 28 px, icon file mờ, tên file, thư mục mờ; header dính khi cuộn.
  - `alt-enter` (`editor::OpenExcerpts`) mở file thật, `cmd-alt-enter` mở split.
- Khi `lsp_results_location = "picker"`: modal placeholder "Filter references…", hàng gom dưới header file (icon, tên, thư mục mờ), mỗi match có cột số dòng canh phải màu mờ và dòng text với match tô `search.match_background`; pane preview bên cạnh; rỗng thì "No references found".

### 4.3 Giống và khác
- VS Code có ba nơi hiện references (peek, view sidebar, CodeLens); Zed có hai (tab multibuffer, picker).
- Lucerna đã có multibuffer header và header dính cho tab Search (xem `2026-11-10-project-search-ui.md` §6), nên tab "References to X" dùng lại được gần như nguyên vẹn. Picker có preview hợp với trình xem hơn cho thao tác nhanh.

## 5. Hover

### 5.1 VS Code
- Hiện sau `editor.hover.delay`, phía trên dòng nếu đủ chỗ (`editor.hover.above`).
- Nội dung ghép từ các participant theo thứ tự: **phần diagnostic trước**, rồi phần markdown của LSP, ngăn bằng đường kẻ. Mỗi provider một khối. Provider chậm thì có `Loading...` **[chưa kiểm chứng độ trễ]**.
- Phần diagnostic: message, source, code (có thể là link), related information dạng `file(line, col): message` bấm được; hàng dưới có **View Problem** (`Alt+F8`) và **Quick Fix...** (Lucerna bỏ được).
- Markdown: code fence được tô màu theo ngôn ngữ, link bấm được, command link chỉ khi MarkdownString được tin cậy.
- **Settings:**

  | Key | Mặc định |
  |---|---|
  | `editor.hover.enabled` | `"on"` (`on` \| `off` \| `onKeyboardModifier`) |
  | `editor.hover.delay` | `300` |
  | `editor.hover.sticky` | `true` |
  | `editor.hover.hidingDelay` | `300` |
  | `editor.hover.above` | `true` |

- **Lệnh:** `editor.action.showHover` (`Cmd+K Cmd+I`; đang hiện thì focus vào hover), `editor.action.showDefinitionPreviewHover`, `editor.action.hideHover` (`Esc`), cuộn trong hover bằng mũi tên / PageUp / PageDown / Home / End khi `editorHoverFocused`.

### 5.2 Zed
- **Thời gian** (`crates/editor/src/hover_popover.rs`): `hover_popover_enabled` true, `hover_popover_delay` **300 ms**, `hover_popover_sticky` true, `hover_popover_hiding_delay` 300 ms.
- **Prefetch nửa delay:** chờ nửa delay rồi *gửi* request, chờ nửa còn lại rồi mới hiện. Chuột di chuyển thì task cũ bị drop, request bị hủy bằng `$/cancelRequest`. Che độ trễ mà không spam server khi rê chuột nhanh.
- Không gửi request mới nếu chuột vẫn trong range của symbol hoặc diagnostic đang hiện.
- `editor::Hover` (`cmd-k cmd-i`) hiện ngay tại con trỏ, không chờ.
- Sticky: tính khoảng cách chuột tới popover (dung sai 4 px); đi xa thì đếm ngược `hover_popover_hiding_delay`, đi lại gần thì đặt lại, vào trong popover thì hủy. Ẩn khi gõ, cuộn, hoặc mở context menu. Symbol đang hover được tô nền `element.hover`.
- **Nội dung:** request gửi tới mọi server hỗ trợ, mỗi phản hồi một `InfoPopover`. Các khối PlainText / Markdown / Code được gộp thành một chuỗi markdown, tối đa `MAX_HOVER_BYTES = 100_000`. Prose dùng UI font, code block dùng buffer font có tô màu, có nút copy và wrap. Link file mở trong editor, URL khác mở trình duyệt.
- **Popover diagnostic:** diagnostic hẹp nhất chứa vị trí chuột được render riêng, xếp chồng với info popover. Nền `<sev>.background`, viền 1 px `<sev>.border`, padding `py_1 pl_2 pr_8`.
- **Kích thước và vị trí** (`element.rs`):
  - Info popover: `elevation_2` (nền `elevated_surface.background`, viền, đổ bóng), padding `p_2`, `gap_2`, cuộn dọc.
  - Rộng tối đa min(**120 em**, nửa editor), tối thiểu 20 ký tự; cao tối đa min(**16 dòng**, nửa editor), tối thiểu 4 dòng.
  - Đặt trên dòng nếu vừa, không thì dưới. Các popover cách nhau `HOVER_POPOVER_GAP = 10 px`, khe được lấp bằng vùng che vô hình để chuột đi qua không làm ẩn. Cách mép phải `POPOVER_RIGHT_OFFSET = 8 px`.

### 5.3 Giống và khác
Hành vi gần như trùng: delay 300 ms, sticky, hiding delay 300 ms, `cmd-k cmd-i`, diagnostic đứng trên. Zed thêm mẹo prefetch và quy tắc kích thước rõ ràng. Lucerna lấy setting `editor.hover.*` của VS Code và giao diện, timing của Zed.

## 6. Diagnostics

### 6.1 VS Code
- **Trong editor** (`editor/common/services/markerDecorationsService.ts`):
  - Gạch lượn sóng theo mức: Error đỏ, Warning vàng, Info xanh. **Hint** chỉ là ba chấm dưới 2 ký tự đầu.
  - Tag `Unnecessary` làm mờ chữ, `Deprecated` gạch ngang.
  - Range rỗng được mở rộng ra cả từ. Marker cả dòng bắt đầu từ ký tự không phải khoảng trắng đầu tiên.
  - Overview ruler (`editorOverviewRuler.errorForeground`…) và minimap có vạch màu.
  - **Không có icon ở gutter**: decoration của marker chỉ đặt `className`, `inlineClassName`, `overviewRuler`, `minimap`, không có `glyphMarginClassName`.
- **Lưu ý với trình chỉ đọc:** `editor.renderValidationDecorations` (`'editable' | 'on' | 'off'`, mặc định **`'editable'`**) ẩn toàn bộ gạch lỗi khi editor read-only. Đây là option nội bộ của Monaco, không có trong Settings UI. Lucerna luôn read-only, nên chép nguyên ngữ nghĩa `editable` sẽ làm mất hết gạch lỗi. Lucerna phải coi trình xem như `on`.
- **Điều hướng** (`editor/contrib/gotoError/browser/gotoError.ts`):

  | Command ID | Phím |
  |---|---|
  | `editor.action.marker.next` / `.prev` (trong file) | `Alt+F8` / `Shift+Alt+F8` |
  | `editor.action.marker.nextInFiles` / `.prevInFiles` | `F8` / `Shift+F8` |
  | `closeMarkersNavigation` | `Esc` |

  Mở zone widget dưới dòng lỗi: khung màu theo mức, tiêu đề kiểu `file.rs  1 of 5 problems`, message, source/code, related information, nút trước/sau. Chỉ tính Error, Warning, Info (bỏ Hint), xếp theo `problems.sortOrder` (`severity` mặc định | `position`), vòng lại đầu khi hết.
- **Problems panel** (`workbench/contrib/markers/browser/markers.contribution.ts`):

### 7.2 Zed
- **Nguồn:** setting `document_symbols` theo ngôn ngữ, mặc định `"off"`, nghĩa là dùng **tree-sitter `outline.scm`**. `"on"` chuyển sang LSP `documentSymbol` cho cả outline lẫn breadcrumbs. Một điểm vào duy nhất (`buffer_outline_items`) phục vụ outline modal, outline panel và breadcrumbs.
- **Capture trong `outline.scm`:** `@item` (cả node), `@name` (tên, dùng để fuzzy match), `@context` (từ khóa như `pub`, `fn`, `impl`, hiện cùng tên), `@context.extra`, `@annotation` (attribute, doc comment), `@open` / `@close` (tính `body_range`).
- **Text của item:** ghép context và name theo thứ tự trong nguồn, cách nhau một dấu cách, thành chữ ký ngắn như `pub struct OutlineItem`, tô màu theo syntax theme. Item từ LSP được parse lại tên và detail bằng grammar để cũng có màu.

Di chuyển chọn thì tô các dòng của item trong editor (`editor.highlighted_line.background`) và cuộn vào giữa; Enter đặt con trỏ; `Esc` khôi phục vị trí cũ. Hàng là `ListItem` (inset, sparse), thụt 1 rem mỗi cấp, **buffer font cỡ buffer**, ký tự khớp tô nền `text.accent` 30% alpha. Placeholder "Search buffer symbols...".
- **Outline panel** (`cmd-shift-b`): panel dock được (mặc định bên phải, rộng 300, `indent_size` 20, indent guide), theo con trỏ, có ô lọc. Click chọn và cuộn editor, double-click nhảy và focus editor.

- VS Code phụ thuộc LSP: không có server thì không có outline. Zed có outline ngay từ tree-sitter, LSP là tùy chọn.

## 10. Kiến trúc client LSP

### 10.1 Zed (`crates/lsp`, `crates/project/src/lsp_store.rs`)
- **Transport:**
  - JSON-RPC tự viết trên stdio của tiến trình con (`kill_on_drop`). `lsp-types` là bản fork của Zed; bản gốc trên crates.io là MIT nên Lucerna dùng thẳng được.
  - Không dùng tokio: executor của GPUI cùng `smol`/`async-process`.
  - Chỉ quảng bá position encoding `UTF16`.
  - Task ghi: kênh outbound không giới hạn, ghi `Content-Length: N\r\n\r\n` + body, flush sau mỗi message.
  - Task đọc: đọc header tới `\r\n\r\n` (chịu được `Content-Type`, thứ tự bất kỳ), `read_exact` body. Request/notification từ server vào **kênh có giới hạn 128** (`INCOMING_MESSAGE_QUEUE_CAPACITY`) để có backpressure; response gọi handler ngay.
  - Vòng dispatch chạy trên app context, `yield_now` sau mỗi message để server spam notification không làm đứng UI. Request từ server không có handler được trả `MethodNotFound` tự động.
  - Task stderr: đọc từng dòng vào log; trong lúc khởi động còn giữ lại để gắn vào thông báo lỗi nếu `initialize` thất bại.
- **Request:** id tăng dần. Mỗi request có timer, mặc định `DEFAULT_LSP_REQUEST_TIMEOUT_SECS = 120` (setting `global_lsp_settings.request_timeout`, 0 là không giới hạn). Hết giờ thì `Timeout`; server chết thì `ConnectionReset`.
- **Cancel-on-drop:** future của request giữ một guard; future bị drop trước khi có phản hồi thì guard gửi `$/cancelRequest {id}`. UI chỉ việc bỏ task cũ (vị trí hover mới, query symbol mới), server tự được báo dừng. Đây là pattern đáng học nhất.
- **Vòng đời:**
  - Server khởi động lười khi một buffer của ngôn ngữ đó được đăng ký (mở file hoặc vừa nhận diện ngôn ngữ). Bỏ qua file không local, file có dòng dài hơn `global_lsp_settings.max_buffer_line_length` (mặc định 20000, chặn file minified), file không có ngôn ngữ.
  - Định danh server: (worktree, tên server, toolchain, binary + init options trong settings). Đổi binary hoặc init options trong settings sinh định danh mới, server được restart. Một server phục vụ cả worktree; subproject khác được thêm làm **workspace folder** thay vì chạy thêm tiến trình.
  - Thứ tự khởi động: tìm binary → spawn → tính `workspace_configuration` và `initialization_options` (mặc định của adapter deep-merge với `lsp.<server>.initialization_options`, người dùng thắng) → đăng ký mọi handler **trước** khi gửi `initialize` → `initialize` → `initialized` → `workspace/didChangeConfiguration` ngay. Thất bại thì trạng thái `Failed` kèm stderr đã giữ, activity indicator hiện "Failed to run X. Click to show error."
  - Trạng thái binary: `None | CheckingForUpdate | Downloading | Starting | Stopping | Stopped | Failed{error}`.
  - Worktree chưa được tin cậy (restricted mode) thì việc tìm binary chờ tới khi người dùng tin cậy.
- **Tìm root:** đi từ thư mục của file lên trên, tìm `manifest_name` của ngôn ngữ (`Cargo.toml` cho Rust, `pyproject.toml` cho Python, đa số không có). Với Cargo lấy **ancestor xa nhất** có `Cargo.toml` (trong giới hạn độ sâu), để dùng workspace root thay vì từng crate.
- **Đồng bộ tài liệu:**
  - `didOpen` với version 0 và toàn bộ text.
  - `didChange` theo khả năng của server: `FULL` gửi cả text, `INCREMENTAL` gửi từng edit với range UTF-16. Version tăng 1 mỗi lần.
  - Giữ 10 snapshot gần nhất (`OLD_VERSIONS_TO_RETAIN = 10`) cho mỗi (buffer, server), để diagnostic gắn version cũ được hiểu đúng trên text server đã thấy.
  - `didSave` gửi tới mọi server có đăng ký; `didClose` khi đóng buffer.
  - `didChangeWatchedFiles` đăng ký động, dùng lại sự kiện của worktree scanner, không tạo watcher OS mới.
  - Refresh dữ liệu LSP trong editor debounce `LSP_REQUEST_DEBOUNCE_TIMEOUT = 50 ms`.
- **Request từ server phải trả lời** (thiếu thì một số server treo):
  - `workspace/configuration`: trả `config[section]` cho từng item; adapter mặc định trả `lsp.<server>.settings`.
  - `window/workDoneProgress/create`: luôn trả OK (comment trong code ghi gopls sẽ treo nếu không).
  - `client/registerCapability` / `unregisterCapability`: đăng ký động.
  - `workspace/workspaceFolders`: trả tập folder hiện tại.
  - `window/showMessageRequest`: hiện prompt có nút.
  - Notification: `window/showMessage` (thông báo tự ẩn sau `notifications.dismiss_timeout_ms` 5000), `window/logMessage` (vào log), `$/progress` (cập nhật công việc đang chạy, token `rust-analyzer/flycheck` đánh dấu cargo check).
- **Tắt:** request `shutdown` với `SERVER_SHUTDOWN_TIMEOUT = 5 s` → `exit` → đóng kênh → chờ ghi xong (chung 5 s) → kill. Drop `LanguageServer` cuối cùng tự chạy quy trình này. Khi thoát app, mọi server được tắt song song.
- **Crash:** **không tự restart.** Tiến trình chết thì stdout EOF, các request đang chờ thành `ConnectionReset`, trạng thái giữ nguyên tới khi người dùng restart qua `editor::RestartLanguageServer` / `StopLanguageServer` hoặc menu nút LSP.
- **UI quản lý:**
  - Nút LSP trên status bar (`BoltOutlined`, có chấm màu: Error khi server lỗi, Warning khi health warning hoặc restricted mode). Popover liệt kê server theo worktree, mỗi server có chấm trạng thái và submenu Restart / Stop / mở log; cuối có Restart All / Stop All.
  - Log view: buffer read-only với dropdown chọn server và loại: Server Logs (logMessage + stderr), Server Trace (`$/logTrace`), RPC Messages (chỉ ghi khi view đang mở), Server Info. Tối đa `MAX_STORED_LOG_ENTRIES = 2000` mỗi loại.
  - Activity indicator: spinner + "{title} ({pct}%): {message} + N more", "Downloading X…", "Failed to run X. Click to show error."

### 10.2 vscode-languageclient
- Trạng thái: `initial → starting → running → stopping → stopped` (+ `startFailed`).
- Khởi động: spawn (stdio/IPC/socket), `initialize` (capabilities, `rootUri`, `workspaceFolders`, `initializationOptions`, `processId`, `trace`), rồi `initialized`. Lỗi init do `initializationFailedHandler` quyết định.
- Đồng bộ: chỉ tài liệu khớp `documentSelector`; `didOpen` / `didChange` (full hoặc incremental) / `didClose` / `didSave`. Với trình xem chỉ cần `didOpen` / `didClose`, cộng mở lại khi file đổi trên đĩa.
- **Restart (`DefaultErrorHandler`):** `maxRestartCount` mặc định **4**. Mỗi lần kết nối đóng ghi một timestamp; lần đóng thứ 5 mà 5 lần nằm trong **3 phút** thì không restart nữa và báo `The <name> server crashed 5 times in the last 3 minutes. The server will not be restarted. See the output for more information.`; ngược lại bỏ timestamp cũ nhất và restart. Lỗi ở mức message: bỏ qua 3 lần đầu, sau đó tắt.
- **Tắt:** `shutdown` rồi `exit`, timeout **2000 ms** (`stop(timeout = 2000)`).
- **Log:** một `LogOutputChannel` mang tên client trong Output panel, có thể thêm `traceOutputChannel`. `revealOutputChannelOn` mặc định `Error`; lỗi hiện notification có "Go to output".
- **Trace:** `<clientId>.trace.server` (`off` | `messages` | `verbose`, hoặc `{verbosity, format: text|json}`). Bản mới chỉ trace khi log level của channel là Trace; đổi log level thì gửi lại `$/setTrace`.
- `window/showMessage` thành notification, `window/logMessage` vào output, `$/progress` thành tiến trình ở status bar, diagnostic (push hoặc pull) vào `DiagnosticCollection` riêng của client rồi đổ vào marker service.

### 10.3 Giống và khác
- Hai bên cùng: lười khởi động, `shutdown` rồi `exit` có timeout, log theo server, trả lời các request bắt buộc.
- Khác: VS Code tự restart có giới hạn, Zed để người dùng restart. VS Code timeout tắt 2 s, Zed 5 s. Zed có timeout cho mọi request và cancel-on-drop ở tầng transport; VS Code dựa vào cancellation token ở từng feature.
- **Workspace trust:** VS Code không kích hoạt extension `capabilities.untrustedWorkspaces.supported: false` (rust-analyzer khai báo như vậy) khi folder chưa được tin cậy, nên server không chạy; setting kiểu đường dẫn binary chỉ lấy giá trị cấp user trong Restricted Mode. Zed cũng chờ trust trước khi tìm binary. Bài học cho Lucerna: chạy language server là chạy code do project kiểm soát (build script, proc macro), cần cơ chế trust trước khi bật LSP.

## 11. Cách có language server

### 11.1 Zed: adapter native và extension
- **Adapter native** (`crates/languages/src/*.rs`, GPL):

  | Ngôn ngữ | Server | Cách có |
  |---|---|---|
  | Rust | rust-analyzer | toolchain rustup của worktree, rồi `which`; mỗi ứng viên được **chạy thử** `--help` vì proxy rustup trong `~/.cargo/bin` hay lỗi khi thiếu component; không có thì tải `rust-analyzer-<arch>-<target>.gz` từ GitHub release |
  | Go | gopls | cần `go` trên PATH; `which gopls`, không có thì `go install golang.org/x/tools/gopls@latest` với `GOBIN` là thư mục riêng |
  | TS / TSX / JS | vtsls (mặc định), typescript-language-server | `npm install` qua Node do Zed quản lý; ưu tiên bản cài trong project |
  | Python | basedpyright, ruff, ty, pyright, pylsp, pyrefly | npm hoặc binary GitHub/PyPI |
  | JSON / JSONC, YAML, CSS, Bash | vscode-json-language-server, yaml-language-server, vscode-css-language-server, bash-language-server | npm |
  | C / C++ | clangd | GitHub release |
  | (nhiều ngôn ngữ) | tailwindcss-language-server, eslint | npm |

  Không có server: diff, env, markdown, regex, gitcommit.
- **Thứ tự tìm binary:** (1) binary người dùng cài trên PATH (trừ khi `binary.ignore_system_version`), không cache vì mỗi worktree có thể ra kết quả khác (ví dụ `node_modules/.bin`); (2) bản cache trong bộ nhớ; (3) bản tải lần trước trong `languages_dir()/<server>`, song song kiểm tra bản mới; tải lỗi thì dùng bản cũ. Có cả binary cũ lẫn bản cập nhật thì chờ tối đa `SERVER_DOWNLOAD_TIMEOUT = 10 s`, quá thì dùng bản cũ, tải tiếp ở nền.
- **Thư mục tải:** `~/Library/Application Support/Zed/languages/<server-name>/`.
- **Môi trường:** env của login shell cho worktree được trộn dưới `binary.env`.
- **Extension:** mọi ngôn ngữ khác (Ruby, PHP, Elixir, Java, Kotlin, Swift, Zig, TOML, HTML, Svelte, Vue, Astro…) có server qua extension WASM (§12). `default.json` đã liệt kê sẵn `language_servers` cho các ngôn ngữ này để xếp đúng thứ tự khi cài.

### 11.2 VS Code: mỗi extension tự lo
- **Không có setting "language servers" chung.** Mỗi extension ngôn ngữ đóng gói client và tự có namespace setting. Ví dụ rust-analyzer: `rust-analyzer.server.path` (null = binary đi kèm), `rust-analyzer.server.extraEnv`, `rust-analyzer.trace.server` (`off` mặc định), `rust-analyzer.restartServerOnConfigChange` (`false`), `rust-analyzer.initializeStopped` (`false`).
- Lệnh restart cũng theo extension: `rust-analyzer.restartServer`, `rust-analyzer.startServer`, `rust-analyzer.stopServer`; `typescript.restartTsServer`, `eslint.restart` **[chưa kiểm chứng]**.
- Kích hoạt lười qua `activationEvents`: `workspaceContains:Cargo.toml`, `onLanguage:<id>`…

### 11.3 Settings của Zed
- `languages.<L>.enable_language_server` (bool, mặc định `true`).
- `languages.<L>.language_servers` (mặc định `["..."]`): danh sách có thứ tự; `!name` tắt một server; `"..."` mở rộng thành mọi server đã đăng ký cho ngôn ngữ chưa được liệt kê. Server tắt mặc định (ví dụ `typescript-language-server`, `ty`, `pyrefly`) không bao giờ được `"..."` kéo vào. Thứ tự cũng quyết định server chính. Ví dụ Python: `["basedpyright", "ruff", "!ty", "!pyrefly", "!pyright", "!pylsp", "..."]`.
- `lsp.<server>`: `binary { path, arguments, env, ignore_system_version }`, `initialization_options` (deep-merge với mặc định của adapter), `settings` (trả cho `workspace/configuration` và `didChangeConfiguration`), `fetch { pre_release }`.
- `global_lsp_settings`: `button`, `request_timeout` (120), `max_buffer_line_length` (20000), `notifications.dismiss_timeout_ms` (5000).
- Toggle liên quan tới trình xem: `hover_popover_*`, `lsp_highlight_debounce` (75 ms), `go_to_definition_fallback`, `go_to_definition_scroll_strategy`, `lsp_results_location`, `diagnostics_max_severity`, `diagnostics.{button, include_warnings, lsp_pull_diagnostics, inline}`, `document_symbols`, `semantic_tokens` (`"off"`), `excerpt_context_lines` (2), `toolbar.breadcrumbs`, `scrollbar.diagnostics`.

### 11.4 Giống và khác
VS Code đẩy hết cho từng extension, mỗi server một kiểu setting. Zed gom về một shape chung `lsp.<server>`. Lucerna không chạy được extension VS Code, và extension WASM của Zed đọc đúng shape `lsp.<server>` qua `get-settings` (§12.2), nên giữ tên key của Zed cho phần này là hợp lý, dù các setting khác theo VS Code.

### 12.4 Zed host thế nào (chỉ thiết kế)
- **Engine:** một `wasmtime::Engine` toàn cục, bật component model, **epoch interruption**, một task tăng epoch mỗi ~100 ms. Mỗi extension một `Store`, deadline 1 tick ở chế độ **yield** về executor thay vì trap, nên guest không chiếm luồng quá ~100 ms mỗi lần poll. Không dùng fuel, không có timeout cứng.
- **Binding:** mỗi phiên bản một `bindgen!` (import `async | trappable`, export `async`). Bản cũ ánh xạ các interface chung sang kiểu của bản mới nhất qua `with:` và chuyển đổi bằng `From`; host trait của bản cũ chủ yếu chuyển tiếp sang bản mới.
- **Thực thi:** compile và đọc phiên bản chạy trên background executor; khởi tạo và mọi lời gọi chạy trên **tokio** vì `wasmtime-wasi` làm I/O qua tokio. Mỗi extension có một hàng đợi closure, một task duy nhất rút hàng đợi, nên lời gọi vào cùng một extension được tuần tự hóa. Host function cần state của app thì gửi closure về main thread và chờ.
- **WASI và work dir:** `<data_dir>/extensions/work/<id>/`. Env `PWD=<work dir tuyệt đối>`; work dir được **preopen hai lần** (dưới tên `.` và dưới đường dẫn tuyệt đối của nó), ngoài ra không có gì (không socket, không thư mục khác). Phía guest, macro `register_extension!` đặt cwd của wasi-libc từ `PWD` và vô hiệu `chdir`, nên `env::current_dir()` trả work dir. **Host không đặt `PWD` là extension hỏng.**
- **Sandbox đường dẫn** cho `download-file` và `make-file-executable`: resolve tương đối work dir, chuẩn hóa và từ chối nếu thoát ra ngoài, canonicalize ancestor gần nhất đang tồn tại (xử lý symlink), bắt buộc kết quả nằm trong work dir.
- **`download-file`:** GET theo redirect, lỗi nếu không 2xx; `uncompressed` ghi thẳng, `gzip` giải nén stream, `gzip-tar` đọc vào bộ nhớ rồi bung vào **thư mục** đích, `zip` bung stream.
- **Lệnh trả về:** đường dẫn tương đối được nối vào work dir, tuyệt đối giữ nguyên; `env` của extension phủ lên env tiến trình.
- **Node:** dùng `node` / `npm` trên PATH nếu ≥ 22.0.0 (trừ khi `node.ignore_system_version`), không thì tải Node v24.22.1 quản lý riêng vào `<data_dir>/node/`. `npm-install-package` chạy `npm install <name>@<version> --no-package-lock --save-exact` với cwd là work dir.
- **Capability:** manifest khai `[[capabilities]]` kiểu `process:exec`, `download_file`, `npm:install`. Setting `granted_extension_capabilities` mặc định **cấp cả ba bằng wildcard**. `process:exec` cần cả khai báo trong manifest lẫn quyền của người dùng; hai loại kia chỉ cần quyền người dùng (mặc định có). `http-client.fetch` không bị gate.
- **GitHub:** gọi `api.github.com/repos/<repo>/releases`, gửi `Authorization: Bearer $GITHUB_TOKEN` nếu có biến môi trường.
- **Build `extension.wasm`** (`extension_builder.rs`): đảm bảo target `wasm32-wasip2` (`rustup target add`), `cargo build --target wasm32-wasip2 --release`, strip custom section trừ `zed:api-version` và `component-type:*`. wasip2 ra component trực tiếp, không cần adapter preview1.

### 12.5 wasmtime 48: một bản duy nhất
- Lucerna đã biên dịch **wasmtime 48.0.8** qua `tree-sitter 0.27` feature `wasm` (`wasmtime-c-api-impl 48.0.8`); Zed dùng 48.0.7.
- Thêm `wasmtime = { version = "48.0.8", default-features = false, features = ["runtime", "cranelift", "component-model", "async"] }` và `wasmtime-wasi = { version = "48.0.8", default-features = false, features = ["p2"] }` thì Cargo hợp nhất về **cùng một bản**, chỉ bật thêm feature (tắt default của `wasmtime-wasi` để tránh kéo `wiggle`).
- Crate mới: `wasmtime-wasi`, `wasmtime-wasi-io`, họ cap-std, macro component, `wit-parser`, tokio có runtime. Khoảng 40–60 crate. License `Apache-2.0 WITH LLVM-exception` (đã dự tính trong `deny.toml`), tokio MIT.
- **Quy tắc ghim:** luôn để `wasmtime` của Lucerna trùng major với bản `tree-sitter` đang dùng; khi tree-sitter nâng wasmtime thì nâng cùng lúc, không thì Cargo build hai bộ wasmtime + cranelift (thêm ~1 GB trong `target/`). Thêm kiểm tra CI: `cargo tree -d | grep wasmtime` phải rỗng.
- Tokio: chọn một runtime tokio 1–2 luồng riêng trong crate host, tách khỏi GPUI. Tự viết WASI p2 không đáng công.
- Vendor WIT vào Lucerna (ví dụ `crates/lucerna-extension-host/wit/since_v0.6.0/`) kèm `LICENSE-APACHE` và dòng NOTICE.

### 12.6 Rủi ro
1. **Cần Rust toolchain để build `extension.wasm`.** Lucerna tự build từ nguồn và không dùng `api.zed.dev` (spec Phase 2), nên mỗi extension có LSP phải được biên dịch trên máy người dùng: cần `cargo`, `rustup`, target `wasm32-wasip2` (~1 GB), lần build đầu tải crate và mất 30–90 s mỗi extension. Phương án: (a) bắt buộc có rustup, báo lỗi rõ khi thiếu; (b) tự cài toolchain tối thiểu (nặng); (c) xem lại quyết định "không dùng `api.zed.dev`" riêng cho `extension.wasm`; (d) CI của Lucerna build sẵn và host lại, kéo theo việc rà license phân phối từng extension. **Đây là rủi ro sản phẩm lớn nhất.**
2. **Work dir dùng chung với việc build grammar.** Lucerna đang dùng `extensions/work/<id>/grammars` và `work/<id>/src` cho mã nguồn đã clone. Cho guest quyền ghi cả `work/<id>` là để lộ chúng, và một số extension (zig, lua) `read_dir(".")` rồi `remove_dir_all` mọi thứ không khớp phiên bản hiện tại. Cần tách: thư mục chỉ cho runtime của guest, mã nguồn và grammar chuyển sang `extensions/build/<id>/` (hoặc dùng `extensions/runtime/<id>/`). Phải chốt trước khi phát hành.
3. **Node.** 7/23 extension cần Node (Vue, Svelte, Astro, PHP intelephense, Dockerfile, Prisma, Ruby). Cần node ≥ 22 trên máy hoặc bản tải về (~100 MB), npm chạy với cwd là work dir và tôn trọng proxy/registry trong npmrc.
4. **PATH của login shell.** App GUI trên macOS không thừa hưởng PATH của login shell. `which` và `shell-env` phải dùng env bắt từ `$SHELL -l -i -c env` (theo thư mục project nếu cần direnv), có cache. PATH sai thì extension tải trùng server.
5. **Giới hạn GitHub.** 13/23 extension gọi `latest-github-release` ở **mỗi** lần khởi động server. Không xác thực chỉ được 60 request/giờ/IP. Cần đọc `GITHUB_TOKEN` và cache kết quả trong host vài phút.
6. **Không chặn UI.** `npm install`, tải file, gọi GitHub có thể mất vài phút. Mọi lời gọi extension chạy ngoài main thread, không `block_on` từ GPUI; tuần tự trong một extension, song song giữa các extension.
7. **Guest chạy mãi.** Zed chỉ yield, không kill. Lucerna nên thêm deadline cứng theo epoch cho thời gian CPU của guest; sau khi trap thì khởi tạo lại instance.
8. **Sandbox khi giải nén.** Kiểm tra từng entry (zip-slip, tar có `..` hoặc đường dẫn tuyệt đối, symlink trỏ ra ngoài). Nếu gọi `tar` / `unzip` ngoài thì dùng cờ từ chối các entry đó, hoặc kiểm tra danh sách trước.
9. **Độ trễ compile.** Cranelift biên dịch một component 1–3 MB mất vài trăm ms tới vài giây. Cache bằng `Component::serialize` / `deserialize` vào `extension.cwasm`, khóa theo phiên bản wasmtime và hash wasm (`deserialize` là `unsafe`, chỉ đọc file Lucerna tự ghi). Nạp lười khi mở file đầu tiên cần server, để giữ mục tiêu khung hình đầu < 200 ms và bộ nhớ nghỉ < 150 MB.
10. **Capability.** Ít nhất phải tôn trọng `[[capabilities]] process:exec` trong manifest, và hỏi xác nhận lần đầu cho extension khai exec hoặc tải file thực thi.
11. **Ngôn ngữ phổ biến vẫn chưa có.** Host WASM không cho rust/go/python/ts/json/yaml/css/bash/c, vì Zed làm chúng bằng adapter native (GPL). Lucerna phải tự viết adapter native cho các ngôn ngữ này, độc lập với host WASM.

### 12.7 Ước lượng công sức

## 13. Lucerna chọn gì

Đã chốt với người dùng ngày 2026-11-10; chi tiết ở `docs/superpowers/specs/2026-11-10-lucerna-phase3-lsp-design.md`.

| Chủ đề | Chọn | Lý do |
|---|---|---|
| Nguồn server | Adapter viết sẵn cho server trên PATH (rust-analyzer, gopls, pyright/basedpyright, typescript-language-server, clangd); không tự tải. Host WASM tách sang Phase 3b | Host WASM không cho Rust/Go/Python/TS (Zed viết các server đó bằng Rust), và cần Rust toolchain trên máy người dùng để build `extension.wasm` |
| Server tự khai báo qua settings | Không | Người dùng chọn chỉ dùng adapter có sẵn, như cả VS Code và Zed |
| Kiến trúc | Crate `lucerna-lsp` không gpui, tự viết transport, dùng `lsp-types` | Test được bằng fake server; không kéo tokio |
| Peek và nhiều kết quả | Picker có preview (theo `lsp_locations` của Zed) + tab References dùng lại giao diện tab Search | Giao diện theo Zed; không có vùng chèn trong editor |
| Nguồn symbol | LSP `documentSymbol`, không có server thì `outline.scm` của extension | Chính xác như VS Code, vẫn có outline khi không có server |
| Outline | Chỉ modal `@` và breadcrumbs, không có panel | Gọn |
| Diagnostics | Gạch lượn sóng (luôn hiện dù chỉ đọc), icon gutter, inline (tắt mặc định), vạch scrollbar, status bar, F8; không có tab Problems | Theo lựa chọn của người dùng |
| Tin cậy thư mục | Như Zed: Restricted Mode mặc định, modal Trust, nhớ lựa chọn, `session.trustAllWorktrees` | Server có thể chạy code của project |
| Crash | Không tự restart (như Zed); Restart từ popover trạng thái | Đơn giản, người dùng thấy rõ lỗi |
