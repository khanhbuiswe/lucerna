- **Status:** research notes, the basis for the Phase 4 spec (`docs/superpowers/specs/2026-11-11-lucerna-phase4-editing-design.md`).

## 1. Summary

| Topic | VS Code | Zed | Lucerna chooses |
|---|---|---|---|
| Buffer structure | Piece tree; undo stores reverse diffs, compacted when a group closes | CRDT: rope + fragments, undo flips "visibility" by undo count | The existing `ropey` rope + reverse diffs (no CRDT) |
| Undo grouping | By **operation type** (`EditOperationType`); every cursor move, Enter, paste, cut and save closes the group | By **time**: edits less than 300 ms apart merge | VS Code's rule (behavior) |
| Cursor on undo | Restores the selection before the group; redo restores the selection after the group | Same | Same |
| Clean again when undoing to the saved version | Yes ("alternative version id") | Yes (versions compared by content) | Yes |
| Reload when the buffer is clean | Reloads automatically, applied as a diff, is one undo step | Same | Same (extends the existing `Reload`) |
| File changed on disk while the buffer is dirty | Does nothing until save; save reports the error "content is newer" with Compare / Overwrite | Warning-colored dot on the tab; save asks Overwrite / Discard Edits / Cancel | Zed's warning dot + a notice bar in the editor + auto-merge when there is no overlap (see §5) |
| Multi-cursor | ⌘D, ⌘K ⌘D, ⇧⌘L, ⌥⌘↑/↓, ⇧⌥I, ⌥-click, ⇧⌥-drag, ⌘U | Mostly the same; ⇧⌥I has no default | VS Code keys |
| IME | Composition via `compositionType` | Composing text is really inserted into the buffer and highlighted, one region per cursor; the whole composition is one undo step | Follow Zed |
| Completion | Suggest widget; `fuzzyScoreGracefulAggressive`; sorted by score → sortText | Popover 280–540 px, 3–12 rows, documentation on the right | VS Code behavior and settings, Zed UI |
| Rename | F2, input box **above** the symbol, ⌘Enter previews | F2, single-line editor **below** the symbol, bold text, other occurrences dimmed to 0.6 | F2, Zed-style input, no preview yet |
| Format | ⇧⌥F, ⌘K ⌘F, `editor.formatOnSave` false; no hard timeout, shows "Saving…" + Skip after 3 s | ⌘⇧I; `format_on_save` off; hard timeout 5 s | VS Code keys and settings; hard 5 s timeout like Zed |
| Writing the file | Written through the file service, with an etag to detect conflicts | Overwritten in place (not atomic) | Temp file + fsync + rename; write in place when the target is a symlink/hardlink |

## 2. Edit and undo model

### 2.1 VS Code (`editor/common/model/editStack.ts`, `platform/undoRedo/common/undoRedoService.ts`)

- Each model has one `EditStack`. A `SingleModelEditStackElement` element holds `beforeVersionId`, `afterVersionId`, `beforeCursorState`, `afterCursorState` and a list of `TextChange` (compact reverse diffs). When closed, the element is serialized into an `ArrayBuffer` to save heap.
- An "undo stop" only means **closing the last element**: `pushStackElement()`. The next edit appends to the open element (`canAppend`) or creates a new element.
- Undo restores the selection from *before* the group's first edit; redo restores the selection from *after* the last edit.
- **When a group closes** (`editor/common/cursor/cursorTypeEditOperations.ts`, `cursor.ts`, `browser/coreCommands.ts`):
  - `EditOperationType { Other, DeletingLeft, DeletingRight, TypingOther, TypingFirstSpace, TypingConsecutiveSpace }`.
  - `shouldPushStackElementBetween(prev, cur)`: while typing, switching to another operation closes the group; right after `TypingFirstSpace` it does not close; otherwise it closes when the types differ (after merging the two whitespace types). Result: typing `abc def` becomes two steps, `abc` and ` def`.
  - Enter, paste, cut, surround and tab/outdent all close the group first (paste and cut close it afterwards too).
  - `deleteLeft` / `deleteRight` open a new group when the previous type differs, or when deleting across multiple lines.
  - **Every cursor movement command and mouse click** calls `pushStackElement()` before changing the cursor.
  - **Saving a file** also closes the group (`TextFileEditorModel.doSave`), so ⌘Z goes back exactly to the saved version.
  - An outside edit (not caused by the cursor) resets the previous type to `Other`.
- **Dirty / clean:** compare `model.getAlternativeVersionId()` with the id at save time; undoing back to exactly the saved state makes it clean.
- **Reload and Revert are undoable:** `modelService.updateModel` computes a line diff, then `pushStackElement(); pushEditOperations(diff); pushStackElement()`.
- `files.restoreUndoStack` (default true): closing a file keeps its undo history, up to 20 MB, and restores it on reopen if the content SHA-1 matches.
- **Multi-file undo:** `MultiModelEditStackElement`. Undoing in one file when other files have changed since is refused ("Could not undo '{0}' across all files…"); otherwise it asks "Undo in {n} Files / Undo this File / Cancel".
- Commands: `undo` ⌘Z, `redo` ⇧⌘Z, `cursorUndo` ⌘U (50 states, cleared when the content changes), `cursorRedo` has no key.

### 2.2 Zed (`crates/text/src/text.rs`, `crates/language/src/buffer.rs`, `crates/editor/src/editor.rs`)

- The buffer is a CRDT: deleted text is not lost but moves to the `deleted_text` rope; undoing an edit increments that edit's undo counter (odd = undone). Anchors point into insertions, so they survive every edit.
- `History`: `undo_stack`, `redo_stack`, `transaction_depth` (nested ones merge into the outer transaction; an empty transaction is dropped), **`group_interval` = 300 ms** (0 in tests).
  - `finalize_last_transaction`: blocks further merging (used before format, reload, completion).
  - `group_until_transaction`: merges everything after a transaction (used for IME).
  - `push_empty_transaction` + `merge_transactions`: builds a parent transaction for format.
- The editor keeps a `SelectionHistory` keyed by transaction id (selection before and after), capped at 1024. Undo restores the selection before; redo restores the selection after. There is a separate history for the cursor only (`UndoSelection` ⌘U / `RedoSelection` ⇧⌘U), which also restores the ⌘D state.
- `is_dirty` compares the content with `saved_version` via `edits_since`, so undoing back to the saved version makes it clean. When undo returns to clean but the on-disk mtime differs, the buffer emits `ReloadNeeded`.
- **What a single-user editor needs:** a transaction stack with a depth counter, a "finalize" flag, IME merging, merging into a parent (format), invertible reverse diffs, a `u64` version number, an edit log by version so syntax / LSP / diagnostics can catch up. It does not need replica ids, version vectors or a fragment tree.

### 2.3 Lucerna chooses

- **No CRDT.** `lucerna-text` keeps `ropey` (O(1) clone) and adds `edit`, `Transaction` (reverse diff + selection before/after), `History` with depth and a finalize flag, and `Patch` (a list of old → new ranges) so other components can map positions.
- **VS Code's grouping rule**, not time-based grouping: the behavior follows VS Code and is predictable (typing `abc def` always becomes two steps). IME follows Zed: the whole composition is one step.
- **Dirty by state**: each transaction has an id; saving a file remembers the id at the top of the stack; the buffer is dirty when the top id differs from the saved id.
- `files.restoreUndoStack` and multi-file undo come later (noted in the spec).

## 3. Multi-cursor

### 3.1 VS Code (`editor/contrib/multicursor/browser/multicursor.ts`, `coreCommands.ts`)

| Command | Key |
|---|---|
| `editor.action.insertCursorAbove` / `Below` | ⌥⌘↑ / ⌥⌘↓ |
| `editor.action.insertCursorAtEndOfEachLineSelected` | ⇧⌥I |
| `editor.action.addSelectionToNextFindMatch` | ⌘D |
| `editor.action.moveSelectionToNextFindMatch` | ⌘K ⌘D |
| `editor.action.addSelectionToPreviousFindMatch`, `moveSelectionToPreviousFindMatch` | none |
| `editor.action.selectHighlights` | ⇧⌘L |
| `editor.action.changeAll` | ⌘F2 |
| `removeSecondaryCursors` | Escape (when there are multiple selections) |
| `cancelSelection` | Escape (when there is a non-empty selection) |
| `cursorUndo` | ⌘U |
| `cursorColumnSelectLeft/Right/Up/Down/PageUp/PageDown` | ⇧⌥⌘ + arrows / PageUp / PageDown |
| Add a cursor with the mouse | ⌥-click; clicking a secondary cursor removes it |
| Column selection with the mouse | ⇧⌥-drag |

- First ⌘D with an empty cursor: selects the word under the cursor (whole word, case-sensitive). Later presses search from the end of the selection just added, wrapping around to the start of the file. When text is already selected, the match mode comes from the Find bar options. Note: `editor.selectedTextMatchMode` was once recorded here but could not be confirmed as a VS Code setting, so Lucerna does not have it.
- Settings: `editor.multiCursorModifier` (`alt` default | `ctrlCmd`), `editor.multiCursorMergeOverlapping` (true), `editor.multiCursorPaste` (`spread` | `full`), `editor.multiCursorLimit` (10000), `editor.columnSelection` (false).
- `spread` paste: if the clipboard has exactly as many chunks as there are cursors, each cursor gets one chunk; or if the number of lines equals the number of cursors, it splits by line.

### 3.2 Zed (`crates/editor/src/selections_collection.rs`, `selection.rs`)

- `SelectionsCollection`: `disjoint` (sorted, non-overlapping) + `pending` (being dragged with the mouse). Selections are stored as anchors.
- Merged when they overlap, share a start point, or an empty cursor touches the other selection's boundary. **Two non-empty selections that merely touch stay separate.**
- `SelectNext` searches with Aho-Corasick, skips results that overlap an existing selection, and wraps around. `AddSelectionAbove/Below` keep a stack so pressing the opposite direction removes some; the target column is preserved across short lines. Escape: multiple selections → keep the newest selection; one selection → the cursor.
- Default keys match VS Code at ⌘D, ⌘K ⌘D, ⇧⌘L, ⌥⌘↑/↓, ⌘U; ⇧⌥I exists only in Zed's "vscode" keymap.

### 3.3 Lucerna chooses

VS Code's keys, commands and settings. VS Code's merge rule (`multiCursorMergeOverlapping`), with the boundary-touching detail taken from Zed. Every editing command works on a **list of selections** from the very first step, so multi-cursor is just adding commands that create selections.

## 4. Typing and basic editing commands

### 4.1 Commands and keys (VS Code)

- Delete: `deleteLeft` ⌫, `deleteRight` ⌦ (⌃D), `deleteWordLeft` ⌥⌫, `deleteWordRight` ⌥⌦, `deleteAllLeft` ⌘⌫, `deleteAllRight` ⌘⌦ (⌃K).
- Movement (each command has a `…Select` version with ⇧): `cursorLeft/Right/Up/Down` (⌃B/F/P/N), `cursorWordLeft` ⌥←, `cursorWordEndRight` ⌥→ (on mac ⌥→ goes to the **end** of the word), `cursorHome` / `cursorEnd` (⌘← / ⌘→, Home / End), `cursorLineStart` / `cursorLineEnd` (⌃A / ⌃E), `cursorTop` / `cursorBottom` (⌘↑ / ⌘↓), `cursorPageUp/Down`. `editor.action.selectAll` ⌘A.
- `editor.action.smartSelect.expand` / `shrink`: ⌃⇧⌘→ / ⌃⇧⌘←.
- Lines: `editor.action.moveLinesUpAction/DownAction` ⌥↑/↓, `copyLinesUpAction/DownAction` ⇧⌥↑/↓, `deleteLines` ⇧⌘K, `insertLineAfter` ⌘Enter, `insertLineBefore` ⇧⌘Enter, `indentLines` / `outdentLines` ⌘] / ⌘[, `joinLines` ⌃J, `trimTrailingWhitespace` ⌘K ⌘X.
- Comments: `editor.action.commentLine` ⌘/, `addCommentLine` ⌘K ⌘C, `removeCommentLine` ⌘K ⌘U, `blockComment` ⇧⌥A.
- Clipboard: `editor.action.clipboardCutAction` ⌘X, `clipboardPasteAction` ⌘V. With nothing selected, copy/cut takes the whole line (`editor.emptySelectionClipboard` true), and pasting it back inserts above the current line.
- `tab` / `outdent` (⇧Tab), `lineBreakInsert` ⌃O.
- Word boundaries: `editor.wordSeparators` (default `` `~!@#$%^&*()-=+[{]}\|;:'",.<>/? ``), characters split into three classes: regular, whitespace, separator.

### 4.2 Settings (VS Code, defaults)

- `editor.autoClosingBrackets`, `editor.autoClosingQuotes`: `always | languageDefined | beforeWhitespace | never`, default `languageDefined`. `editor.autoClosingOvertype` (`auto`): only types over closing characters that the editor inserted itself. `editor.autoClosingDelete` (`auto`): ⌫ between a just auto-inserted pair deletes both. `editor.autoSurround` (`languageDefined`).
- `editor.autoIndent`: `none | keep | brackets | advanced | full`, default `full`.
- `editor.tabSize` 4, `editor.insertSpaces` true, `editor.detectIndentation` true, `editor.trimAutoWhitespace` true.
- `files.eol` `auto` (an existing file keeps its own line ending style), `files.encoding` `utf8`, `files.insertFinalNewline` false, `files.trimTrailingWhitespace` false, `files.trimFinalNewlines` false.
- `files.autoSave` `off | afterDelay | onFocusChange | onWindowChange` (default `off`), `files.autoSaveDelay` 1000.
- `files.hotExit` `onExit` (backs up dirty buffers on quit and restores them next time).

### 4.3 Zed

- **IME:** `EntityInputHandler` for the editor. Composing text is really inserted into the buffer and marked with the `InputComposition` highlight; each cursor has its own composition region, so IME works with multi-cursor. The whole composition merges into one undo step; undo cancels a composition in progress.
- `handle_input` runs per selection: it auto-closes brackets by the `brackets` pairs in the language's `config.toml` (only when the next character is in `autoclose_before` or at end of line; quotes do not auto-close right after a word character), types over closing characters, surrounds the selection, then edits with auto-indent.
- Enter: keeps the indent; between a bracket pair it inserts two lines and puts the cursor on the indented middle line; continues comments (`extend_comment_on_newline`). Syntax-based indent uses the `indents.scm` query, computed after parsing.
- Tab inside the indent area jumps to the suggested indent; elsewhere it inserts spaces up to the next tab stop. ⌫ inside the indent area goes back to the previous tab stop.
- Pasting multiple lines keeps the block's relative indentation.

### 4.4 Lucerna chooses

VS Code's commands, keys and settings. IME follows Zed. Language data (auto-closing bracket pairs, `autoclose_before`, line and block comments) is read from the `config.toml` of Zed language extensions; for now `lucerna-extension` only reads `line_comments`. `editor.autoIndent: full` uses `indents.scm` when the language has it, otherwise it behaves like `brackets`.

## 5. File changed on disk while editing

### 5.1 VS Code (`workbench/services/textfile/common/textFileEditorModel.ts`, `textFileEditorModelManager.ts`, `workbench/contrib/files/browser/editors/textFileSaveErrorHandler.ts`)

- Clean buffer: reloads automatically (`never reload dirty models`), applied as a diff, undoable.
- Dirty buffer: **says nothing** until save. Save carries an etag; if the file is newer, the error is `FILE_MODIFIED_SINCE`, and the message "Failed to save '{0}': The content of the file is newer. Please compare your version with the file contents or overwrite the content of the file with your changes." appears with **Compare** and **Overwrite** (plus Configure → `files.saveConflictResolution`: `askUser` | `overwriteFileOnDisk`).
- Compare opens the diff "{0} (in file) ↔ {1} (in Code) - Resolve save conflict" with two buttons on the title bar: use your version (overwrite) or discard changes (revert).
- **New on `main`:** `TextFileEditorModel.reconcileExternalChanges` does a three-way merge: the base is the content read last, the diffs are base → buffer (the user's edits) and base → disk (external edits); if `tryRebase` succeeds it applies the external part to the dirty buffer as one undo step, otherwise it returns `Conflict`. Who calls this function is **[unverified]**; it may be a chat-editing feature.
- Deleted file: waits 100 ms, checks again, marks it "orphaned"; the tab is struck through; saving recreates the file. `workbench.editor.closeOnFileDelete` false.
- Dirty tab: a ● dot replaces the × button, hover shows ×. Closing a dirty tab: "Do you want to save the changes you made to {0}?" / "Your changes will be lost if you don't save them." with Save / Don't Save / Cancel.
- Commands: `workbench.action.files.revert`, `workbench.files.action.compareWithSaved` (⌘K D), `workbench.action.files.save` (⌘S), `saveAs` (⇧⌘S), `saveAll` (⌥⌘S), `saveWithoutFormatting` (⌘K S).

### 5.2 Zed (`crates/language/src/buffer.rs`, `crates/workspace/src/pane.rs`, `crates/editor/src/items.rs`)

- Clean buffer: reloads silently, applying a diff computed on a background thread, as its own undo step (finalize before and after). If the user types during the reload, the result is dropped and a conflict is flagged.
- Dirty buffer whose on-disk mtime is newer than `saved_mtime`: `has_conflict`. The tab shows a **Warning-colored dot** (a plain dirty dot is Accent-colored). There is no banner.
- Saving during a conflict: "This file has changed on disk since you started editing it. Do you want to overwrite it?" with **Overwrite / Discard Edits / Cancel**. Deleted file: "This file has been deleted on disk since you started editing it. Do you want to recreate it?" with Save / Close / Cancel. The tab of a deleted file is struck through.
- Autosave never writes a file that is in conflict or has been deleted.
- Closing several dirty tabs: "Save all / Discard all / Cancel".

### 5.3 Lucerna chooses

An agent writing files while the user is editing is Lucerna's main scenario, so Lucerna goes further than both:

1. Clean buffer: reload like both (already exists), adding it to the undo history.
2. Dirty buffer, and the on-disk change does **not overlap** the user's edits: merge automatically like `reconcileExternalChanges` (one undo step), with a light notice on the status bar.
3. Overlap: a warning dot on the tab (Zed) and **a thin bar at the top of the editor** (differs from both) with "Reload" (take the on-disk version, still undoable) and "Keep Mine" (keep your version; the next save overwrites without asking again). Saving during a conflict asks like Zed.
4. "Compare" needs a diff UI, left for Phase 5.

## 6. Completion

### 6.1 VS Code (`editor/contrib/suggest/browser/*`)

- Settings: `editor.quickSuggestions` (`{other, comments, strings}`, default `other` on when there is no inline completion, `comments`/`strings` off), `editor.quickSuggestionsDelay` 10 ms, `editor.suggestOnTriggerCharacters` true, `editor.acceptSuggestionOnEnter` `on`, `editor.acceptSuggestionOnCommitCharacter` true, `editor.suggestSelection` `first`, `editor.snippetSuggestions` `inline`, `editor.tabCompletion` `off`, `editor.wordBasedSuggestions` (when there is no inline AI it is equivalent to `matchingDocuments`), `editor.suggest.insertMode` `insert`, `editor.suggest.filterGraceful` true, `editor.suggest.showIcons` true, `editor.suggest.preview` false, `editor.suggest.matchOnWordStartOnly` true.
- Triggers automatically when typing a word character (the word under the cursor is not a number) after 10 ms, or when typing the server's trigger character. ⌃Space opens it manually; ⌃Space while open toggles the details pane.
- Keys in the menu: Enter / Tab accept, ⇧Enter / ⇧Tab accept in the reverse mode (insert ↔ replace), ↑ ↓ PageUp PageDown, Escape closes.
- Filter and sort: the typed word is compared against `filterText` (or the label) with `fuzzyScoreGracefulAggressive` (tolerates one typo); sorted by descending score → `sortText` → label.
- Resolve (`completionItem/resolve`) when an item is focused. `additionalTextEdits` (for example adding a `use`) are applied in the same undo step. Insertion goes through the snippet engine: `$1`, `${1:default}`, `${1|a,b|}`, `$0`, variables (`$TM_FILENAME`…); Tab / ⇧Tab cycle through placeholders, placeholders with the same number are kept in sync; the undo group is closed before and after insertion.

### 6.2 Zed (`crates/editor/src/code_context_menus.rs`, `completions.rs`)

- A popover below the cursor (flipped above when there is no room), **280–540 px** wide, **3–12 rows** tall, a virtualized list (`uniform_list`), with no scrollbar shown. Each row: the label with matched characters in bold, detail on the right.
- The documentation pane sits to the **right** of the menu (260–500 px), or above/below when there is no room; Markdown; only resolves visible items ±4; a cache of 16 items.
- Ranking: group 1 is items whose query's first character matches the start of a word in the label (understands camelCase / snake_case); within the group sorted by exact match, fuzzy score, `sort_text`. Group 2 is by score.
- When the menu is open and the previous results are complete, it filters in place without asking the server again.
- Settings: `show_completions_on_input` true, `completions.words` `fallback` (use words in the buffer when the LSP fails), `words_min_length` 3.
- Applying a completion is its own undo step.

### 6.3 Lucerna chooses

VS Code's settings, keys and trigger rules; the popover UI and documentation pane follow Zed; ranking follows VS Code (fuzzy score → `sortText`). The snippet engine is shared by LSP snippets and extension snippets (for now `lucerna-extension` only checks syntax and has no runtime yet).

## 7. Rename

- **VS Code** (`editor/contrib/rename/browser/rename.ts`, `renameWidget.ts`): F2 (`editor.action.rename`). Calls `prepareRename`; if the server does not support it, it uses the word under the cursor; if rejected, it shows a small message in place. The input box sits **above** the symbol (below when there is no room), prefilled with the old name and fully selected, with the hint line "Enter to Rename, ⌘Enter to Preview". The result is a WorkspaceEdit applied via bulk edit: per-file version checks, one undo step across files. Unopened files are loaded as dirty buffers; `files.refactoring.autoSave` (true) saves them when more than one file changes.
- **Zed** (`editor.rs` `rename`, `confirm_rename`): F2, a single-line editor inserted as a block **right below** the symbol's line, indented to the symbol's column, **bold** text in the same syntax color, transparent background; other uses of the symbol in the file are faded (`fade_out` 0.6). Enter confirms, Escape cancels. The result is applied to multiple buffers (multibuffer) and is not saved automatically.
- **Lucerna chooses:** F2, `prepareRename`, VS Code's autosave rule; the input follows Zed (uses `TextInput` in a popover attached below the symbol). No preview (⌘Enter) yet. Undo is per file like Zed; no cross-file undo yet.

## 8. Format and save

- **VS Code** (`editor/contrib/format/browser/*`, `workbench/contrib/codeEditor/browser/saveParticipants.ts`):
  - `editor.action.formatDocument` ⇧⌥F, `editor.action.formatSelection` ⌘K ⌘F. `editor.defaultFormatter` (an extension id, per language).
  - The result is discarded if the user types or moves while waiting. Edits are reduced to the smallest diff (keeps the cursor). A manual format is one undo step.
  - `editor.formatOnSave` false; **skipped on autosave** (`files.autoSave`). `editor.formatOnSaveMode` `file | modifications | modificationsIfAvailable` (the latter two need SCM).
  - Order on save: trim trailing whitespace → code actions on save → format → final newline → trim final newlines.
  - No hard timeout: after 3 s it shows "Saving '{name}'" with a Skip button.
- **Zed** (`editor.rs` `perform_format`, `project/src/lsp_store.rs`):
  - `editor::Format` ⌘⇧I, `FormatSelections`, `SaveWithoutFormat` ⌘K S. `format_on_save` `off`; `formatter` (`auto`, `language_server`, `prettier`, an external command, a code action, or a list).
  - **`FORMAT_TIMEOUT` = 5 s.** Format is exactly one undo step; if the user edits during formatting it is canceled ("Buffer edited while formatting"). Applied as a diff.
  - Time-based autosave does not format.
- **Writing the file:** Zed overwrites in place (keeps the inode, permissions, symlink) but can leave a partial file on a crash. VS Code writes through the file service with an etag. Both keep encoding, BOM and line ending style.
- **Lucerna chooses:** VS Code's commands, keys and settings (`editor.formatOnSave`, `editor.defaultFormatter` accepting a language server name, `formatOnSaveMode` only `file` until Git arrives in Phase 5); Zed's hard 5 s timeout instead of a notice with Skip (simple, needs no progress UI); write a temp file + fsync + rename, writing in place when the target is a symlink or has multiple hardlinks.

## 9. Performance (Zed)

- `crates/rope` (Apache-2.0): a B-tree (`sum_tree`) of 128-byte chunks with a bitmap, converting offset ↔ line ↔ UTF-16 with popcount. Snapshot clone is O(1). Lucerna keeps `ropey` (clone is also O(1)); only consider switching if measurement shows slowness.
- After each edit: `tree.edit(InputEdit)` shifts the old tree immediately (approximate colors with no parse needed), tries a synchronous parse of **1 ms**, and if that is exceeded, parses incrementally on a background thread; the result carries a version and is dropped if stale. Lucerna already has `SyntaxState::edited` and `SYNC_PARSE_BUDGET` for reload; only the input needs to change from `Reload` to `Patch`.
- All heavy work (parsing, diffing on reload/format, completion filtering, computing LSP changes) runs on a snapshot on a background thread and checks the version before applying.
