## 1. Tóm tắt

| Chủ đề | VS Code | Zed | Lucerna chọn |
|---|---|---|---|
| Cấu trúc buffer | Piece tree; undo lưu diff ngược, nén khi đóng nhóm | CRDT: rope + fragment, undo là lật "hiển thị" theo số lần undo | Rope `ropey` sẵn có + diff ngược (không CRDT) |
| Nhóm undo | Theo **loại thao tác** (`EditOperationType`), mọi lần di chuyển con trỏ, Enter, paste, cut, save đều đóng nhóm | Theo **thời gian**: các edit cách nhau < 300 ms gộp lại | Quy tắc của VS Code (hành vi) |
| Con trỏ khi undo | Khôi phục selection trước nhóm; redo khôi phục selection sau nhóm | Giống | Giống |
| Hết bẩn khi undo về bản đã lưu | Có ("alternative version id") | Có (so phiên bản theo nội dung) | Có |
| Reload khi buffer sạch | Tự reload, áp dạng diff, là một bước undo | Giống | Giống (mở rộng `Reload` hiện có) |
| File đổi trên đĩa khi buffer bẩn | Không làm gì tới khi lưu; lưu báo lỗi "content is newer" với Compare / Overwrite | Chấm màu cảnh báo trên tab; lưu thì hỏi Overwrite / Discard Edits / Cancel | Chấm cảnh báo của Zed + thanh báo trong editor + tự gộp khi không chồng lấn (xem §5) |
| Multi-cursor | ⌘D, ⌘K ⌘D, ⇧⌘L, ⌥⌘↑/↓, ⇧⌥I, ⌥-click, ⇧⌥-kéo, ⌘U | Giống phần lớn; ⇧⌥I không có mặc định | Phím VS Code |
| IME | Composition qua `compositionType` | Chữ đang soạn được chèn thật vào buffer và tô đánh dấu, mỗi con trỏ một vùng; cả lần soạn là một bước undo | Theo Zed |
| Completion | Suggest widget; `fuzzyScoreGracefulAggressive`; sắp theo điểm → sortText | Popover 280–540 px, 3–12 dòng, tài liệu ở bên phải | Hành vi và settings VS Code, giao diện Zed |
| Rename | F2, ô nhập phía **trên** symbol, ⌘Enter xem trước | F2, editor một dòng **dưới** symbol, chữ đậm, các chỗ khác mờ 0.6 | F2, ô nhập kiểu Zed, chưa có xem trước |
| Format | ⇧⌥F, ⌘K ⌘F, `editor.formatOnSave` false; không có timeout cứng, hiện "Saving…" + Skip sau 3 s | ⌘⇧I; `format_on_save` off; timeout cứng 5 s | Phím và settings VS Code; timeout cứng 5 s kiểu Zed |
| Ghi file | Ghi qua file service, có etag để phát hiện xung đột | Ghi đè tại chỗ (không atomic) | File tạm + fsync + rename, ghi tại chỗ khi là symlink/hardlink |

## 2. Mô hình edit và undo

### 2.1 VS Code (`editor/common/model/editStack.ts`, `platform/undoRedo/common/undoRedoService.ts`)

- Mỗi model có một `EditStack`. Phần tử `SingleModelEditStackElement` giữ `beforeVersionId`, `afterVersionId`, `beforeCursorState`, `afterCursorState` và danh sách `TextChange` (diff ngược gọn). Khi đóng, phần tử được serialize vào `ArrayBuffer` để tiết kiệm heap.
- "Undo stop" chỉ có nghĩa là **đóng phần tử cuối**: `pushStackElement()`. Edit tiếp theo nối vào phần tử đang mở (`canAppend`) hoặc tạo phần tử mới.
- Undo khôi phục selection *trước* edit đầu tiên của nhóm; redo khôi phục selection *sau* edit cuối.
- **Khi nào đóng nhóm** (`editor/common/cursor/cursorTypeEditOperations.ts`, `cursor.ts`, `browser/coreCommands.ts`):
  - `EditOperationType { Other, DeletingLeft, DeletingRight, TypingOther, TypingFirstSpace, TypingConsecutiveSpace }`.
  - `shouldPushStackElementBetween(prev, cur)`: đang gõ mà chuyển sang thao tác khác thì đóng; ngay sau `TypingFirstSpace` thì không đóng; còn lại đóng khi loại (sau khi gộp hai loại khoảng trắng) khác nhau. Kết quả: gõ `abc def` thành hai bước `abc` và ` def`.
  - Enter, paste, cut, surround, tab/outdent đều đóng nhóm trước (paste và cut đóng cả sau).
  - `deleteLeft` / `deleteRight` mở nhóm mới khi loại trước khác, hoặc khi xóa qua nhiều dòng.
  - **Mọi lệnh di chuyển con trỏ và click chuột** gọi `pushStackElement()` trước khi đổi con trỏ.
  - **Lưu file** cũng đóng nhóm (`TextFileEditorModel.doSave`), để ⌘Z quay về đúng bản đã lưu.
  - Edit từ ngoài (không do con trỏ) đặt lại loại trước về `Other`.
- **Bẩn / sạch:** so `model.getAlternativeVersionId()` với id lúc lưu; undo về đúng trạng thái đã lưu thì hết bẩn.
- **Reload và Revert undo được:** `modelService.updateModel` tính diff theo dòng rồi `pushStackElement(); pushEditOperations(diff); pushStackElement()`.
- `files.restoreUndoStack` (mặc định true): đóng file vẫn giữ undo, tối đa 20 MB, khôi phục khi mở lại nếu SHA-1 nội dung khớp.
- **Undo nhiều file:** `MultiModelEditStackElement`. Undo ở một file mà các file khác đã đổi sau đó thì từ chối ("Could not undo '{0}' across all files…"); ngược lại hỏi "Undo in {n} Files / Undo this File / Cancel".
- Lệnh: `undo` ⌘Z, `redo` ⇧⌘Z, `cursorUndo` ⌘U (50 trạng thái, xóa khi nội dung đổi), `cursorRedo` không có phím.

### 2.2 Zed (`crates/text/src/text.rs`, `crates/language/src/buffer.rs`, `crates/editor/src/editor.rs`)

- Buffer là CRDT: văn bản bị xóa không mất mà chuyển sang rope `deleted_text`; undo của một edit là tăng bộ đếm undo của edit đó (lẻ = đã undo). Anchor trỏ vào insertion nên sống qua mọi edit.
- `History`: `undo_stack`, `redo_stack`, `transaction_depth` (lồng nhau thì gộp vào transaction ngoài; transaction rỗng bị bỏ), **`group_interval` = 300 ms** (0 khi test).
  - `finalize_last_transaction`: chặn gộp tiếp (dùng trước format, reload, completion).
  - `group_until_transaction`: gộp mọi thứ sau một transaction (dùng cho IME).
  - `push_empty_transaction` + `merge_transactions`: dựng transaction cha cho format.
- Editor giữ `SelectionHistory` theo transaction id (selection trước và sau), giới hạn 1024. Undo khôi phục selection trước; redo khôi phục selection sau. Có lịch sử riêng chỉ cho con trỏ (`UndoSelection` ⌘U / `RedoSelection` ⇧⌘U), khôi phục cả trạng thái ⌘D.
- `is_dirty` so nội dung với `saved_version` qua `edits_since`, nên undo về bản đã lưu thì sạch. Khi undo về sạch mà mtime trên đĩa khác, buffer phát `ReloadNeeded`.
- **Phần cần cho editor một người dùng:** stack transaction có đếm độ sâu, cờ "finalize", gộp IME, gộp vào cha (format), diff ngược khả nghịch, số phiên bản `u64`, nhật ký edit theo phiên bản để syntax / LSP / diagnostics bắt kịp. Không cần replica id, version vector, fragment tree.

### 2.3 Lucerna chọn

- **Không CRDT.** `lucerna-text` giữ `ropey` (clone O(1)), thêm `edit`, `Transaction` (diff ngược + selection trước/sau), `History` có độ sâu và cờ finalize, `Patch` (danh sách đoạn cũ → mới) để các thành phần khác ánh xạ vị trí.
- **Quy tắc nhóm của VS Code**, không nhóm theo thời gian: hành vi theo VS Code và dự đoán được (gõ `abc def` luôn thành hai bước). IME theo Zed: cả lần soạn là một bước.
- **Bẩn theo trạng thái**: mỗi transaction có id; lưu file ghi nhớ id đỉnh stack; bẩn khi id đỉnh khác id đã lưu.
- `files.restoreUndoStack` và undo nhiều file để sau (ghi trong spec).

## 3. Multi-cursor

### 3.1 VS Code (`editor/contrib/multicursor/browser/multicursor.ts`, `coreCommands.ts`)

| Lệnh | Phím |
|---|---|
| `editor.action.insertCursorAbove` / `Below` | ⌥⌘↑ / ⌥⌘↓ |
| `editor.action.insertCursorAtEndOfEachLineSelected` | ⇧⌥I |
| `editor.action.addSelectionToNextFindMatch` | ⌘D |
| `editor.action.moveSelectionToNextFindMatch` | ⌘K ⌘D |
| `editor.action.addSelectionToPreviousFindMatch`, `moveSelectionToPreviousFindMatch` | không có |
| `editor.action.selectHighlights` | ⇧⌘L |
| `editor.action.changeAll` | ⌘F2 |
| `removeSecondaryCursors` | Escape (khi có nhiều selection) |
| `cancelSelection` | Escape (khi có selection không rỗng) |
| `cursorUndo` | ⌘U |
| `cursorColumnSelectLeft/Right/Up/Down/PageUp/PageDown` | ⇧⌥⌘ + mũi tên / PageUp / PageDown |
| Thêm con trỏ bằng chuột | ⌥-click; click lên con trỏ phụ thì xóa nó |
| Chọn cột bằng chuột | ⇧⌥-kéo |

- ⌘D lần đầu với con trỏ rỗng: chọn từ dưới con trỏ (whole word, phân biệt hoa thường). Các lần sau tìm từ cuối selection vừa thêm, quay vòng về đầu file. Khi đã có chữ được chọn, chế độ khớp lấy từ `editor.selectedTextMatchMode` (`findOptions` mặc định).
- Settings: `editor.multiCursorModifier` (`alt` mặc định | `ctrlCmd`), `editor.multiCursorMergeOverlapping` (true), `editor.multiCursorPaste` (`spread` | `full`), `editor.multiCursorLimit` (10000), `editor.columnSelection` (false).
- Paste `spread`: clipboard có đúng số đoạn bằng số con trỏ thì chia mỗi con trỏ một đoạn; hoặc số dòng bằng số con trỏ thì chia theo dòng.

### 3.2 Zed (`crates/editor/src/selections_collection.rs`, `selection.rs`)

- `SelectionsCollection`: `disjoint` (đã sắp, không chồng) + `pending` (đang kéo chuột). Selection lưu bằng anchor.
- Gộp khi chồng lấn, cùng điểm đầu, hoặc một con trỏ rỗng chạm biên selection kia. **Hai selection không rỗng chỉ chạm nhau thì giữ riêng.**
- `SelectNext` tìm bằng Aho-Corasick, bỏ qua kết quả chồng selection có sẵn, quay vòng. `AddSelectionAbove/Below` giữ stack để bấm chiều ngược lại thì xóa bớt; giữ cột mục tiêu qua dòng ngắn. Escape: nhiều selection → còn selection mới nhất; một selection → con trỏ.
- Phím mặc định trùng VS Code ở ⌘D, ⌘K ⌘D, ⇧⌘L, ⌥⌘↑/↓, ⌘U; ⇧⌥I chỉ có trong keymap "vscode" của Zed.

### 3.3 Lucerna chọn

Phím, lệnh và settings của VS Code. Quy tắc gộp của VS Code (`multiCursorMergeOverlapping`), chi tiết chạm biên lấy theo Zed. Mọi lệnh sửa làm việc trên **danh sách selection** ngay từ bước đầu, để multi-cursor chỉ là thêm lệnh tạo selection.

### 4.2 Settings (VS Code, mặc định)

- `editor.autoClosingBrackets`, `editor.autoClosingQuotes`: `always | languageDefined | beforeWhitespace | never`, mặc định `languageDefined`. `editor.autoClosingOvertype` (`auto`): chỉ gõ đè ký tự đóng do editor tự chèn. `editor.autoClosingDelete` (`auto`): ⌫ giữa cặp vừa tự chèn thì xóa cả hai. `editor.autoSurround` (`languageDefined`).
- `editor.autoIndent`: `none | keep | brackets | advanced | full`, mặc định `full`.
- `editor.tabSize` 4, `editor.insertSpaces` true, `editor.detectIndentation` true, `editor.trimAutoWhitespace` true.
- `files.eol` `auto` (file có sẵn giữ kiểu xuống dòng của nó), `files.encoding` `utf8`, `files.insertFinalNewline` false, `files.trimTrailingWhitespace` false, `files.trimFinalNewlines` false.
- `files.autoSave` `off | afterDelay | onFocusChange | onWindowChange` (mặc định `off`), `files.autoSaveDelay` 1000.
- `files.hotExit` `onExit` (sao lưu buffer bẩn khi thoát và khôi phục lần sau).

### 4.3 Zed

- **IME:** `EntityInputHandler` cho editor. Chữ đang soạn được chèn thật vào buffer và đánh dấu bằng highlight `InputComposition`; mỗi con trỏ có vùng soạn riêng nên IME chạy với multi-cursor. Cả lần soạn gộp thành một bước undo; undo hủy lần soạn đang dở.
- `handle_input` chạy cho từng selection: tự đóng ngoặc theo cặp `brackets` trong `config.toml` của ngôn ngữ (chỉ khi ký tự kế tiếp thuộc `autoclose_before` hoặc cuối dòng; dấu nháy không tự đóng ngay sau chữ), gõ đè ký tự đóng, bọc selection, rồi edit với tự thụt lề.
- Enter: giữ thụt lề; giữa cặp ngoặc thì chèn hai dòng và đặt con trỏ ở dòng giữa đã thụt; nối comment (`extend_comment_on_newline`). Thụt lề theo cú pháp dùng query `indents.scm`, tính sau khi parse.
- Tab trong vùng thụt lề nhảy tới thụt lề gợi ý; ngoài ra chèn khoảng trắng tới tab stop kế. ⌫ trong vùng thụt lề lùi về tab stop trước.
- Paste nhiều dòng giữ thụt lề tương đối của khối.

### 4.4 Lucerna chọn

Lệnh, phím và settings của VS Code. IME theo Zed. Dữ liệu ngôn ngữ (cặp ngoặc tự đóng, `autoclose_before`, comment dòng và khối) đọc từ `config.toml` của extension ngôn ngữ Zed, hiện `lucerna-extension` mới đọc `line_comments`. `editor.autoIndent: full` dùng `indents.scm` khi ngôn ngữ có, nếu không thì như `brackets`.

## 5. File đổi trên đĩa khi đang sửa

### 5.1 VS Code (`workbench/services/textfile/common/textFileEditorModel.ts`, `textFileEditorModelManager.ts`, `workbench/contrib/files/browser/editors/textFileSaveErrorHandler.ts`)

- Buffer sạch: tự reload (`never reload dirty models`), áp dạng diff, undo được.
- Buffer bẩn: **không báo gì** cho tới khi lưu. Lưu kèm etag; file mới hơn thì lỗi `FILE_MODIFIED_SINCE`, hiện thông báo "Failed to save '{0}': The content of the file is newer. Please compare your version with the file contents or overwrite the content of the file with your changes." với **Compare** và **Overwrite** (phụ: Configure → `files.saveConflictResolution`: `askUser` | `overwriteFileOnDisk`).
- Compare mở diff "{0} (in file) ↔ {1} (in Code) - Resolve save conflict" với hai nút trên thanh tiêu đề: dùng bản của bạn (ghi đè) hoặc bỏ thay đổi (revert).
- **Mới trên `main`:** `TextFileEditorModel.reconcileExternalChanges` gộp ba chiều: gốc là nội dung đã đọc lần cuối, diff gốc → buffer (sửa của người dùng) và gốc → đĩa (sửa bên ngoài); nếu `tryRebase` được thì áp phần bên ngoài vào buffer bẩn thành một bước undo, ngược lại trả `Conflict`. Ai gọi hàm này **[chưa kiểm chứng]**, có thể là tính năng chat-editing.
- File bị xóa: chờ 100 ms, kiểm tra lại, đánh dấu "orphaned"; tab gạch ngang; lưu thì tạo lại file. `workbench.editor.closeOnFileDelete` false.
- Tab bẩn: chấm ● thay nút ×, hover hiện ×. Đóng tab bẩn: "Do you want to save the changes you made to {0}?" / "Your changes will be lost if you don't save them." với Save / Don't Save / Cancel.
- Lệnh: `workbench.action.files.revert`, `workbench.files.action.compareWithSaved` (⌘K D), `workbench.action.files.save` (⌘S), `saveAs` (⇧⌘S), `saveAll` (⌥⌘S), `saveWithoutFormatting` (⌘K S).

### 5.2 Zed (`crates/language/src/buffer.rs`, `crates/workspace/src/pane.rs`, `crates/editor/src/items.rs`)

- Buffer sạch: reload im lặng, áp diff tính ở luồng nền, là một bước undo riêng (finalize trước và sau). Người dùng gõ trong lúc reload thì bỏ kết quả và đánh dấu xung đột.
- Buffer bẩn mà mtime trên đĩa mới hơn `saved_mtime`: `has_conflict`. Tab hiện **chấm màu Warning** (bẩn thường là chấm màu Accent). Không có banner.
- Lưu khi xung đột: "This file has changed on disk since you started editing it. Do you want to overwrite it?" với **Overwrite / Discard Edits / Cancel**. File bị xóa: "This file has been deleted on disk since you started editing it. Do you want to recreate it?" với Save / Close / Cancel. Tab file bị xóa gạch ngang.
- Autosave không bao giờ ghi file đang xung đột hoặc đã bị xóa.
- Đóng nhiều tab bẩn: "Save all / Discard all / Cancel".

### 5.3 Lucerna chọn

Agent ghi file trong khi người dùng đang sửa là tình huống chính của Lucerna, nên Lucerna làm kỹ hơn cả hai:

1. Buffer sạch: reload như cả hai (đã có), thêm vào lịch sử undo.
2. Buffer bẩn, thay đổi trên đĩa **không chồng** lên chỗ người dùng sửa: tự gộp như `reconcileExternalChanges` (một bước undo), báo nhẹ trên status bar.
3. Chồng lấn: chấm cảnh báo trên tab (Zed) và **một thanh mỏng ở đầu editor** (lệch khỏi cả hai) với "Reload" (lấy bản trên đĩa, vẫn undo lại được) và "Keep Mine" (giữ bản của mình; lần lưu sau ghi đè không hỏi lại). Lưu khi đang xung đột hỏi như Zed.
4. "Compare" cần giao diện diff, để Phase 5.

## 6. Completion

### 6.1 VS Code (`editor/contrib/suggest/browser/*`)

- Settings: `editor.quickSuggestions` (`{other, comments, strings}`, mặc định `other` bật khi không có inline completion, `comments`/`strings` tắt), `editor.quickSuggestionsDelay` 10 ms, `editor.suggestOnTriggerCharacters` true, `editor.acceptSuggestionOnEnter` `on`, `editor.acceptSuggestionOnCommitCharacter` true, `editor.suggestSelection` `first`, `editor.snippetSuggestions` `inline`, `editor.tabCompletion` `off`, `editor.wordBasedSuggestions` (khi không có inline AI thì tương đương `matchingDocuments`), `editor.suggest.insertMode` `insert`, `editor.suggest.filterGraceful` true, `editor.suggest.showIcons` true, `editor.suggest.preview` false, `editor.suggest.matchOnWordStartOnly` true.
- Tự kích hoạt khi gõ ký tự từ (từ dưới con trỏ không phải số) sau 10 ms, hoặc khi gõ trigger character của server. ⌃Space mở thủ công; ⌃Space khi đang mở thì bật/tắt phần chi tiết.
- Phím trong menu: Enter / Tab nhận, ⇧Enter / ⇧Tab nhận theo chế độ ngược (insert ↔ replace), ↑ ↓ PageUp PageDown, Escape đóng.
- Lọc và sắp: từ đang gõ so với `filterText` (hoặc label) bằng `fuzzyScoreGracefulAggressive` (chịu một lỗi gõ); sắp theo điểm giảm dần → `sortText` → label.
- Resolve (`completionItem/resolve`) khi mục được focus. `additionalTextEdits` (ví dụ thêm `use`) áp cùng bước undo. Chèn qua snippet engine: `$1`, `${1:mặc định}`, `${1|a,b|}`, `$0`, biến (`$TM_FILENAME`…); Tab / ⇧Tab qua các placeholder, placeholder cùng số được đồng bộ; đóng nhóm undo trước và sau khi chèn.

### 6.2 Zed (`crates/editor/src/code_context_menus.rs`, `completions.rs`)

- Popover dưới con trỏ (lật lên trên khi thiếu chỗ), rộng **280–540 px**, cao **3–12 dòng**, danh sách ảo hóa (`uniform_list`), không hiện thanh cuộn. Mỗi dòng: label với ký tự khớp tô đậm, detail bên phải.
- Phần tài liệu nằm **bên phải** menu (260–500 px), không đủ chỗ thì trên/dưới; Markdown; chỉ resolve các mục đang thấy ±4; cache 16 mục.
- Xếp hạng: nhóm 1 là mục có ký tự đầu của query khớp đầu một từ trong label (hiểu camelCase / snake_case); trong nhóm sắp theo khớp chính xác, điểm fuzzy, `sort_text`. Nhóm 2 theo điểm.
- Menu đang mở và kết quả cũ đầy đủ thì lọc tại chỗ, không hỏi lại server.
- Settings: `show_completions_on_input` true, `completions.words` `fallback` (dùng từ trong buffer khi LSP lỗi), `words_min_length` 3.
- Áp completion là một bước undo riêng.

### 6.3 Lucerna chọn

Settings, phím và quy tắc kích hoạt của VS Code; giao diện popover và phần tài liệu theo Zed; xếp hạng theo VS Code (điểm fuzzy → `sortText`). Snippet engine dùng chung cho snippet của LSP và snippet của extension (hiện `lucerna-extension` chỉ kiểm tra cú pháp, chưa có runtime).

## 7. Rename

- **VS Code** (`editor/contrib/rename/browser/rename.ts`, `renameWidget.ts`): F2 (`editor.action.rename`). Gọi `prepareRename`; server không hỗ trợ thì dùng từ dưới con trỏ; bị từ chối thì hiện thông báo nhỏ ngay tại chỗ. Ô nhập nằm **trên** symbol (thiếu chỗ thì dưới), điền sẵn tên cũ và chọn hết, dòng gợi ý "Enter to Rename, ⌘Enter to Preview". Kết quả là WorkspaceEdit áp qua bulk edit: kiểm tra phiên bản từng file, một bước undo xuyên file. File chưa mở được nạp thành buffer bẩn; `files.refactoring.autoSave` (true) lưu chúng khi đổi nhiều hơn một file.
- **Zed** (`editor.rs` `rename`, `confirm_rename`): F2, một editor một dòng chèn thành block **ngay dưới** dòng của symbol, thụt tới đúng cột symbol, chữ **đậm** cùng màu cú pháp, nền trong suốt; các chỗ dùng symbol trong file mờ đi (`fade_out` 0.6). Enter xác nhận, Escape hủy. Kết quả áp vào nhiều buffer (multibuffer), không tự lưu.
- **Lucerna chọn:** F2, `prepareRename`, quy tắc tự lưu của VS Code; ô nhập theo Zed (dùng `TextInput` trong một popover gắn dưới symbol). Chưa có xem trước (⌘Enter). Undo theo từng file như Zed, chưa có undo xuyên file.

## 8. Format và lưu

- **VS Code** (`editor/contrib/format/browser/*`, `workbench/contrib/codeEditor/browser/saveParticipants.ts`):
  - `editor.action.formatDocument` ⇧⌥F, `editor.action.formatSelection` ⌘K ⌘F. `editor.defaultFormatter` (id extension, theo ngôn ngữ).
  - Kết quả bị bỏ nếu người dùng gõ hoặc di chuyển trong lúc chờ. Edit được rút gọn thành diff nhỏ nhất (giữ con trỏ). Format thủ công là một bước undo.
  - `editor.formatOnSave` false; **bỏ qua khi tự lưu** (`files.autoSave`). `editor.formatOnSaveMode` `file | modifications | modificationsIfAvailable` (hai giá trị sau cần SCM).
  - Thứ tự khi lưu: trim trailing whitespace → code actions on save → format → final newline → trim final newlines.
  - Không có timeout cứng: sau 3 s hiện "Saving '{name}'" với nút Skip.
- **Zed** (`editor.rs` `perform_format`, `project/src/lsp_store.rs`):
  - `editor::Format` ⌘⇧I, `FormatSelections`, `SaveWithoutFormat` ⌘K S. `format_on_save` `off`; `formatter` (`auto`, `language_server`, `prettier`, lệnh ngoài, code action, hoặc danh sách).
  - **`FORMAT_TIMEOUT` = 5 s.** Format là đúng một bước undo; người dùng sửa trong lúc format thì hủy ("Buffer edited while formatting"). Áp dạng diff.
  - Autosave theo thời gian không format.
- **Ghi file:** Zed ghi đè tại chỗ (giữ inode, quyền, symlink) nhưng có thể để lại file dở khi crash. VS Code ghi qua file service với etag. Cả hai giữ encoding, BOM và kiểu xuống dòng.
- **Lucerna chọn:** lệnh, phím và settings VS Code (`editor.formatOnSave`, `editor.defaultFormatter` nhận tên language server, `formatOnSaveMode` chỉ `file` cho tới khi có Git ở Phase 5); timeout cứng 5 s của Zed thay cho thông báo có Skip (đơn giản, không cần UI tiến trình); ghi file tạm + fsync + rename, ghi tại chỗ khi đích là symlink hoặc có nhiều hardlink.

## 9. Hiệu năng (Zed)

- `crates/rope` (Apache-2.0): B-tree (`sum_tree`) các chunk 128 byte kèm bitmap, đổi offset ↔ dòng ↔ UTF-16 bằng popcount. Snapshot clone O(1). Lucerna giữ `ropey` (clone cũng O(1)); chỉ cân nhắc đổi nếu đo thấy chậm.
- Sau mỗi edit: `tree.edit(InputEdit)` để dịch cây cũ ngay (màu gần đúng không cần parse), thử parse đồng bộ **1 ms**, quá thì parse tăng dần ở luồng nền; kết quả mang phiên bản, cũ thì bỏ. Lucerna đã có `SyntaxState::edited` và `SYNC_PARSE_BUDGET` cho reload, chỉ cần đổi đầu vào từ `Reload` sang `Patch`.
- Mọi việc nặng (parse, diff khi reload/format, lọc completion, tính thay đổi LSP) chạy trên snapshot ở luồng nền và kiểm tra phiên bản trước khi áp.
