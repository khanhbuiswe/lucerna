# Research: Welcome screen, Open Recent and the empty editor area

Date 2026-11-12. Sources: `microsoft/vscode` branch `main` (source read), Zed at the pinned GPUI revision `b5cd310b3b54dfc659fcc06453e6358843dfe216` (crate `workspace/src/welcome.rs`, `workspace/src/pane.rs`, `recent_projects`, `workspace/src/persistence.rs`, `assets/keymaps/default-macos.json`). Zed is mostly GPL: only the design is recorded, no code is copied.

## 1. VS Code

### 1.1 `workbench.startupEditor`
Files `contrib/welcomeGettingStarted/browser/gettingStarted.contribution.ts` and `startupPage.ts`.

- Values: `none | welcomePage | readme | newUntitledFile | welcomePageInEmptyWorkbench | terminal`. Default `welcomePage`.
- Description: "Controls which editor is shown at startup, if none are restored from the previous session."
- The Welcome page opens only when **no editor is restored** and the window is not a reload. A second page is not opened if one already exists. It opens as a preview (not pinned).
- `welcomePageInEmptyWorkbench`: opens only in an empty window (no folder). `welcomePage`: also in windows with a folder where no tab was restored.
- `newUntitledFile` applies only to an empty window. `--skip-welcome` turns it off entirely.

### 1.2 The Welcome page (Get Started)
Files `gettingStarted.ts`, `gettingStartedContent.ts`.

- The **Start** section, in order: New File…, then on macOS a single "Open…" entry (`workbench.action.files.openFileFolder`), while other platforms get "Open File…" and "Open Folder…"; next come Clone Git Repository…, Connect to….
- The **Recent** section:
  - Contains only folders and workspaces, no files.
  - Skips the currently open folder.
  - Shows 5 entries (10 when there is no walkthrough).
  - Each row has the folder name (as a button), the dimmed parent path, and a × button shown on hover ("Remove from Recently Opened").
  - At the end of the list is a "More…" link that opens Open Recent.
  - When empty: "You have no recent folders" with a link to open a folder.
- Clicking a recent entry opens it in the **same window**; holding ⌘ (Ctrl) opens a new window.

### 1.3 Open Recent
File `browser/actions/windowActions.ts`.

- `workbench.action.openRecent` ("Open Recent…", File group), key `ctrl+r` on macOS as well.
- Order: separator "folders & workspaces" (or "folders"), folders in most-recently-used order, then separator "files" and the files.
- Focus is set on the first entry automatically; if the first entry is the current window, it goes to the second.
- Placeholder on macOS: "Select to open (hold Cmd-key to force new window or Option-key for same window)". The filter box also matches the description (path).
- Enter opens in the same window, ⌘Enter opens a new window, ⌥Enter forces the same window.
- Each row has a × button ("Remove from Recently Opened"). There is no dedicated key for removing.
- Pressing `ctrl+r` again while the picker is open selects the next entry (`quickOpenNavigateNextInRecentFilesPicker`, when `inRecentFilesPicker`); adding Shift selects the previous one.
- The "Clear Recently Opened" command (`workbench.action.clearRecentFiles`) shows a confirmation dialog "Do you want to clear all recently opened files and workspaces?" with Clear / Cancel buttons.

### 1.4 Storing the list
File `platform/workspaces/electron-main/workspacesHistoryMainService.ts`.

- Key `history.recentlyOpenedPathsList` in application-level storage (shared by all windows, not synced), as JSON.
- At most `MAX_TOTAL_RECENT_ENTRIES = 500` for folders, 500 for files.
- An entry is added each time a path is opened (`WindowsMainService.doOpen`). A new entry goes first, duplicates are removed.
- Paths that no longer exist **are still kept**. Opening one reports "Path does not exist". Only the macOS dock shows just the paths that still exist.

### 1.5 The empty editor area (watermark)
File `browser/parts/editor/editorGroupWatermark.ts`.

- Toggled by `workbench.tips.enabled` (default `true`): "When enabled, will show the watermark tips when no editor is open."
- An empty window shows: Show All Commands, Open Recent, Open File or Folder (macOS), New Untitled Text File.
- A window with a folder shows: Show All Commands, then filler to reach at least 3 entries from Go to File, Find in Files, Start Debugging, Toggle Terminal, Open Settings.
- Each row has a label and a shortcut, dimmed text, centered.

### 1.6 The open commands
File `browser/actions/workspaceActions.ts`.

- `workbench.action.files.openFileFolder` ("Open…"): `cmd+o`, macOS only.
- `workbench.action.files.openFile` ("Open File…"): `ctrl+o` on Linux/Windows, no key on macOS.
- `workbench.action.files.openFolder` ("Open Folder…"): `ctrl+k ctrl+o` on Linux/Windows, no key on macOS.
- `workbench.action.closeFolder` ("Close Folder"): `cmd+k f`. This command returns the window to the empty state, with the Welcome page.

## 2. Zed (pinned revision)

### 2.1 Welcome
Files `workspace/src/welcome.rs`, `pane.rs`.

- Welcome is not a separate window. It is a `WelcomePage`, drawn in the empty pane of a workspace **with no worktree**: `pane.rs` shows it when the pane has no items and the project has no worktree. When there is a folder but the pane is empty, it is just an empty placeholder (double-click creates a new file), with **no key hints**.
- The window still has the title bar and status bar as usual.
- Layout: a centered column, at most `max_w_128` (512 px) wide, padding `p_8`, blocks spaced `gap_6`, scrolls vertically when space runs out, background `editor_background`.
  - Page top: a 45 px logo, next to it the title "Welcome back to Zed" (or "Welcome to Zed") and a small, dimmed, italic subline.
  - `SectionHeader`: an UPPERCASE title, XSmall size, buffer font, muted color, followed by a horizontal `border_variant` line.
  - `SectionButton`: a Medium `ButtonLike`, full column width. On the left a small muted icon and the label (truncated if long), on the right the shortcut at 12 px. Move between buttons with Tab or the arrow keys (`SelectNext` / `SelectPrevious` → focus_next / focus_prev).
  - "Get Started" section: New File, Open Project, Clone Repository, Open Command Palette.
  - The second section: when there are recent projects it is "Recent Projects" (5 entries, each a `SectionButton` with a folder icon and the folder name); otherwise it is "Configure" (Settings, Keymaps, Extensions).
  - In the Welcome pane, `cmd-1`…`cmd-5` open the 1st–5th recent project (`welcome::OpenRecentProject`).
- Opening a recent project follows the `default_open_behavior` setting: use the existing window or open a new window.
- The "Collaborate with Agents" and "Return to Onboarding" cards: Lucerna drops them (no AI, no onboarding).
- Startup setting `restore_on_startup`: `empty_tab | last_workspace | last_session (default) | launchpad`. `launchpad` is a window with no tabs, so the pane shows Welcome with the recent list.

### 2.2 Recent projects
Files `recent_projects/src/recent_projects.rs`, `workspace/src/persistence.rs`.

- The `projects::OpenRecent` picker, keys `alt-cmd-o` and `ctrl-r` on macOS. Groups have headers: "This Window" and "Recent Projects".
- Each row has an icon, the name (with matching characters highlighted), the path below it, and the full path as a tooltip.
- The buttons at the end of the row appear only on hover (`show_end_slot_on_hover`):
  - "Open in New Window / This Window" (secondary confirm, i.e. ⌘Enter);
  - × "Remove" (`RemoveSelected`).
- Stored in SQLite (table `workspaces`), ordered by timestamp.
- On read, `recent_project_workspaces` **hides** entries where a path no longer exists or there is no directory (`all_paths_exist_with_a_directory`, run async), but does not delete them from the DB. An entry is removed only when the user clicks ×.
- Displayed paths are shortened with `~` (`compact()`).

## 3. Comparison and choices for Lucerna

| Aspect | VS Code | Zed | Lucerna |
|---|---|---|---|
| Where Welcome lives | An editor tab in an empty window, and also in a window with a folder when no tab is restored | The empty pane of a workspace with no folder | A screen that fills the content area of a **window with no folder** (like Zed). Lucerna has no folderless workbench, so Welcome is the window's own root view, with a title bar. |
| Welcome content | Start + Recent (5) + walkthrough | Get Started + Recent (5) | Get Started (Open…, Open Recent…) + Recent (5), styled after Zed. No New File, Clone, AI or sign-in. |
| Startup setting | `workbench.startupEditor` | `restore_on_startup` | `workbench.startupEditor` (following VS Code), supporting `welcomePage`, `welcomePageInEmptyWorkbench`, `none`. |
| Recent picker | `openRecent`, ⌃R, folders/files groups, × button | `OpenRecent`, ⌃R, headers, × button and open-in-new-window on hover | Command and keys follow VS Code; the look is Lucerna's existing picker (theme picker / Quick Open), with the × button shown on hover Zed-style. |
| Enter / ⌘Enter | Same window / new window | Per setting / the opposite | Follows VS Code. "New window" is a new `luc` process, since each process has only one window. |
| Paths that no longer exist | Kept; error on open | Hidden on read, kept in the DB | Hidden on read (like Zed). Dropped from the file on the next write, per the "auto-remove" requirement. |
| Where it is stored | Application-level storage | SQLite | `recent.json` in the app's data directory, written atomically. |
| Limit | 500 | no explicit limit | 100 |
| Empty editor area | Watermark with keys, turned off by `workbench.tips.enabled` | Empty | Keep the VS Code-style watermark (Lucerna already has it), add entries, per `workbench.tips.enabled`. This is where Lucerna deviates from Zed, because Lucerna users come from VS Code and need to see the keys. |
| Close Folder | `cmd+k f` → empty window | (closes the project) | `workbench.action.closeFolder` `cmd+k f` → Welcome |

## 4. The app's menu bar

### 4.1 VS Code
File `src/vs/platform/menubar/electron-main/menubar.ts` and the `MenuId.Menubar*Menu` ids (`MenubarFileMenu`, `MenubarEditMenu`, `MenubarSelectionMenu`, `MenubarViewMenu`, `MenubarGoMenu`, `MenubarHelpMenu`…).

- **Menus in order:** Code (macOS only), File, Edit, Selection, View, Go, Run, Terminal, Window (macOS only), Help.
- **How it is built:** each extension or contribution registers its own entries into a `MenuId`. An entry is a command with a `group` and `order`, and may have a `when`. The shortcut next to an entry is the command's current key, taken from the user's keymap.
- **On macOS:**
  - About, Settings, Services, Hide, Hide Others, Show All and Quit are in the app menu.
  - The Window menu is managed by the system.
- **On Linux/Windows:**
  - About is in Help.
  - Preferences is in File; Exit is at the end of File.
  - The menu is drawn in the title bar (`window.titleBarStyle: custom`, `window.menuBarVisibility`).
- **Edit uses the standard Electron roles** (undo, redo, cut, copy, paste), so input boxes in system dialogs still work with ⌘X, ⌘C, ⌘V. Electron lets AppKit add Emoji & Symbols and Dictation to the Edit menu itself.

### 4.2 Zed
File `zed/src/zed/app_menus.rs` at the pinned revision.

- **Menus:** Zed, File, Edit, Selection, View, Go, Run, Window, Help.
- **Zed menu:** About, Check for Updates, Settings ▸ (the settings and keymap files), Services (`MenuItem::os_submenu(…, SystemMenuType::Services)`), Extensions, Install CLI, Hide, Hide Others, Show All, Quit.
- **File:** New, New Window, Open File…, Open…, Open Recent…, Open Remote…, Add Folder…, Save, Save As…, Save All, Close Editor, Close Project, Close Window.
- **Edit:**
  - Undo/Redo are `MenuItem::os_action(…, OsAction::Undo/Redo)`.
  - Cut/Copy/Paste are `os_action` with `OsAction::Cut/Copy/Paste`. GPUI attaches AppKit's `cut:`, `copy:`, `paste:` selectors.
  - Next come Find, Find in Project, Toggle Line Comment.
- **Selection:** Select All (`OsAction::SelectAll`), Expand/Shrink Selection, Add Cursor…, Move Line Up/Down, Duplicate Selection.
- **View:** font zoom, the docks and panels, Editor Layout ▸ Split…
- **Go:** Back, Forward, Command Palette, Go to File, Go to Symbol, Go to Line, the Go to Definition… entries, Next/Previous Problem.
- **Window:** Minimize, Zoom.
- **Help:** documentation, send feedback, Show Welcome.

**How GPUI builds menus** (`gpui/src/platform/app_menu.rs`, `gpui_macos/src/platform.rs`):
- A `Menu` consists of `MenuItem::{Action, Submenu, Separator, SystemMenu}`, and an item can carry `.disabled()` / `.checked()`. `cx.set_menus(…)` replaces the whole menu bar. Zed calls `set_menus` again (`reload_menus`) whenever the keymap changes.
- **The key shown** next to an item is the first binding of that action in the **GPUI keymap** (`keymap.bindings_for_action`), preferring a binding whose context matches Workspace/Pane/Editor. Only single-key bindings are shown; a chord has no key.
- **Clicking an item** makes GPUI call `cx.dispatch_action(action)`.
- **Enabling/disabling an item:** `validate_menu_item` calls `cx.is_action_available`, which is true when the active window handles that action or when the action has a global listener.
- **Key equivalent:** the window receives the key first (`handle_key_equivalent`). The menu runs the action only when the window does not handle that key.
- **macOS specifics:**
  - GPUI calls `setWindowsMenu` for the menu named "Window", and macOS adds the window list to it automatically.
  - GPUI does not call `setHelpMenu`. The search box in Zed's Help is there because AppKit recognizes a menu titled "Help" by itself; to be verified at run time.
  - Emoji & Symbols and Dictation are also added by AppKit to a menu titled "Edit".
- **Linux/Windows:** `title_bar/src/application_menu.rs` reads `cx.get_menus()` and draws each menu as a dropdown button in the title bar.

### 4.3 Choices for Lucerna

| Aspect | Choice | Reason |
|---|---|---|
| Menu groups | Lucerna, File, Edit, Selection, View, Go, Window, Help. Drop Run and Terminal. | Like Zed and VS Code; Lucerna has no debugger or terminal. |
| Source of entries | A single data table of VS Code-style command IDs. An entry whose ID is not registered is hidden. | No fake entries. The 4.2 commands (comment, lines, smart select) appear on their own once they exist. |
| Invoking a command | A GPUI action `RunCommand { id }` with a global listener. The listener forwards to the active window, i.e. `Workbench::run_command` or Welcome. | Lucerna commands are ID strings in `CommandRegistry`, not GPUI actions. |
| Key shown | Take the ID's first single-key binding in the Lucerna keymap (`Keymap::label_for` / binding), and register it as a GPUI `KeyBinding` in the `LucernaMenu` context. No element has this context, so GPUI never runs the binding itself. | GPUI reads keys only from the GPUI keymap. A dedicated context makes the binding display-only. Keys are still handled by `keys.rs` as today. |
| Platform | The data table is platform-independent. The menu-building layer puts About, Settings, Services, Hide and Quit in the app menu on macOS, and in Help or File on other platforms (following VS Code). Drawing the menu in the title bar on Linux/Windows is left for later. | Meets the requirement of not assuming macOS only. |

## 5. Changing folders while a folder is open (added 2026-11-13)

The user saw Open Folder close the window and reopen it with a zoom-in animation, because the first version of W8 starts a new process.

- **VS Code:** the setting `window.openFoldersInNewWindow` has the values `"on"`, `"off"` and `"default"` (default). With `"default"`, a folder chosen from inside the app (File menu, Open Recent) opens in the current window. A folder opened from outside (Finder, CLI) opens a new window. VS Code reloads the renderer but keeps the window, with no window-opening animation.
- **Zed:** File > Open and dragging a folder into the window open in the current window. The setting `cli_default_open_behavior` (`existing_window` / `new_window`) applies only to the CLI and double-click. The CLI flag `-n` opens a new window, `-r` replaces the project in the existing window. Sources: zed.dev/docs/windows-and-projects, zed.dev/docs/reference/cli.
- **Lucerna:** Open Folder, Open Recent (Enter) and Close Folder change the root right inside the window (spec W8, revised by W10). ⌘Enter and paths from Finder/CLI still follow `open_requests::route`. Lucerna has not added the `window.openFoldersInNewWindow` setting yet; when needed, add it following VS Code.
