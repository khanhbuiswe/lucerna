# Git: VS Code và Zed làm thế nào

Tra cứu cho giai đoạn 5 (Git chỉ để xem). Nguồn đọc:
- VS Code: `microsoft/vscode` nhánh `main`, đọc ngày 2026-11-13, giấy phép MIT. Gồm `extensions/git/` và `src/vs/workbench/contrib/scm/`.
- Zed: revision `b5cd310` mà Lucerna đang pin, giấy phép GPL. Chỉ học thiết kế, không chép code. Đọc các crate `git`, `buffer_diff`, `git_ui`, `project/src/git_store*`, `editor`, `project_panel`.

Spec dùng kết quả này: `docs/superpowers/specs/2026-11-13-git-view-design.md`.

## 1. Đọc git: thư viện hay lệnh `git`

**Zed** không dùng thư viện. Mọi thao tác đều gọi lệnh `git`:
- Trạng thái: `git status --porcelain=v1 --untracked-files=all --no-renames -z -- <paths>`. Có thể truyền danh sách đường dẫn để chỉ làm mới một phần cây.
- Nội dung file ở HEAD (`HEAD:<path>`) và ở index (`:<path>`) đọc qua **một** tiến trình `git cat-file --batch` chạy lâu dài.
- Số dòng thêm và bớt lấy từ `git diff --numstat`.
- Lệnh nào cũng kèm `-c core.fsmonitor=false --no-optional-locks --no-pager`. Ở thư mục chưa tin cậy, Zed tắt thêm hooks, `credential.helper` và `diff.external`.
- Mỗi repo có một hàng đợi việc chạy tuần tự ở luồng nền. Một việc mới cùng khóa sẽ thay việc cũ đang chờ trong hàng. Ví dụ "quét lại toàn bộ" chỉ có tối đa một việc chờ.

**VS Code** cũng gọi lệnh `git`, qua extension git viết bằng TypeScript.

**Lucerna đo trên máy (macOS, Apple Silicon).** Các chương trình thử được build release và strip. Repo thử là Zed ở revision trên, 4.401 file theo dõi:

| Cách | Binary tăng thêm | Trạng thái repo, sạch | Trạng thái, 20 file sửa + 1.000 file mới | `cargo deny` |
|---|---|---|---|---|
| `gix` 0.90 (`status`, `sha1`, `parallel`) | +3,3 MB, ~440 crate | 55–120 ms | ~60 ms | qua |
| `git2` 0.21 (`vendored-libgit2`) | +0,8 MB, nối với libz và libiconv của hệ thống | 85–195 ms | 105–135 ms | qua |
| lệnh `git` 2.x | 0 | 100–110 ms (lần đầu 750 ms do cache lạnh) | ~100 ms | không áp dụng |

Thêm vài số đo:
- Binary `luc` bản release hiện là 48,5 MB.
- Diff theo dòng file `editor.rs` (13.446 dòng) bằng `similar` mất khoảng 6 ms. `similar` đã có trong workspace, do `lucerna-text` dùng.
- Repo Lucerna (503 file): `gix` 5–16 ms, `git2` khoảng 10 ms, lệnh `git` 24 ms.

**Lucerna chọn lệnh `git`, như Zed.** Lý do:
- Binary không tăng.
- Kết quả luôn trùng với git mà agent đang dùng: worktree có file `.git` trỏ đi chỗ khác, sparse checkout, LFS, `core.autocrlf`, config riêng của người dùng.
- Tốc độ ngang `git2`.

Cái giá phải trả là máy cần có git. Trên macOS, `/usr/bin/git` là một shim: nếu chưa cài Command Line Tools thì nó bật hộp thoại đòi cài. Vì vậy Lucerna tìm git qua PATH của login shell (`lucerna-lsp::env::which`) và không gọi thẳng `/usr/bin/git` mà không kiểm tra trước.

## 2. Mốc để so (diff base)

| | VS Code | Zed |
|---|---|---|
| Gutter so với | index (bản đã stage). File đã stage có thêm lớp phụ HEAD↔index, màu nhạt hơn | HEAD↔buffer (diff "uncommitted"), lớp phụ là index |
| Setting đổi mốc | không có | `git.diff_base`: `"head"` (mặc định) hoặc `"default_branch"`. Gutter, màu project panel và `git::Diff` cùng đổi theo |
| View theo nhánh | không có sẵn | `git::DiffBranch` mở tab "Changes since main". Diff đi từ merge-base với nhánh mặc định tới bản trên đĩa; ô chọn nhánh trên toolbar đổi mốc tại chỗ |
| Tìm nhánh mặc định | không áp dụng | `refs/remotes/upstream/HEAD`, rồi `refs/remotes/origin/HEAD`, … |

Lucerna theo Zed: có setting `git.diffBase` với mặc định `"head"`, tab Uncommitted Changes và tab Changes since main. Người dùng để agent tự commit nên cần tab theo nhánh để xem lại cả nhiệm vụ.

## 3. Gutter

| | VS Code | Zed |
|---|---|---|
| Vạch | 3 px (`scm.diffDecorationsGutterWidth` từ 1 đến 5), nằm giữa số dòng và chữ. Dòng sửa vẽ sọc chéo | rộng `floor(0.275 × line_height)`, nằm ở mép trái gutter, góc vuông |
| Dòng xóa | tam giác 4×8 px ở đáy dòng phía trên | viên thuốc cao một dòng, nằm giữa hai dòng, bị cắt mất một nửa |
| Màu | `editorGutter.{added,modified,deleted}Background` | `version_control.{added,modified,deleted}`, trộn lên `editor.background` |
| Bấm vào vạch | mở khung peek chứa diff inline, có Stage, Revert, Next, Prev | bung hunk ngay trong editor (dòng xóa thành dòng thật, chỉ đọc) |
| Đi tới thay đổi | `workbench.action.editor.nextChange` / `previousChange`: Alt+F5 / Shift+Alt+F5. `editor.action.dirtydiff.next` / `previous`: Alt+F3 (mở peek) | `editor::GoToHunk` / `GoToPreviousHunk`: Cmd+F8 / Cmd+Shift+F8. Vim: `]c` / `[c` |
| Tính lại | throttle 200 ms, giới hạn 1 s | diff lại cả file trong task nền sau mỗi lần sửa, không làm từng phần. Mặc định không debounce; nếu bật thì tối thiểu 50 ms |
| Thuật toán | "advanced" của VS Code | imara-diff Histogram, cộng heuristic indent của git |
| Setting | `scm.diffDecorations` (`all`, `gutter`, `overview`, `minimap`, `none`), `…GutterVisibility`, `…GutterAction` | `git.git_gutter` (`tracked_files`, `hide`), `git.gutter_debounce`, `git.hunk_style` |

Lucerna lấy giao diện theo Zed (vị trí, độ rộng, dấu xóa), phím và setting theo VS Code. Thêm `]c` và `[c` khi bật Vim.

## 4. Explorer và project panel

| | VS Code | Zed |
|---|---|---|
| Tô tên file | có (`explorer.decorations.colors`) | có (`project_panel.git_status`) |
| Chữ cái | có, mặc định bật (`explorer.decorations.badges`): M, A, D, R, C, T, U (untracked), !, S | có nhưng mặc định tắt (`git_status_indicator`): !, U, D, M, A |
| Thư mục | lấy màu của con, thêm chấm tròn mờ. Ưu tiên: conflict > ignored > modified > còn lại. File bị xóa không lan lên | màu của con quan trọng nhất (tổng hợp trên cây). Ưu tiên: conflict > deleted > modified > created > ignored |
| Khóa màu | `gitDecoration.*ResourceForeground` | `conflict`, `deleted`, `modified`, `created`, `ignored` (khác bộ `version_control.*`) |

Lucerna tô tên file và thư mục như Zed, không hiện chữ cái theo mặc định của Zed, và dùng khóa setting của VS Code.

## 5. View gom mọi thay đổi

- **VS Code**: lệnh `git.viewChanges` mở multi-diff editor. Đó là một tab gồm nhiều diff editor xếp chồng, mỗi file có header thu gọn được và nút Open File. Nhóm rỗng thì hiện thông báo dạng toast.
- **Zed**: lệnh `git::Diff` mở tab "Uncommitted Changes". Đó là một multibuffer gồm mọi file đã đổi:
  - mọi hunk đều bung sẵn, kèm 2 dòng ngữ cảnh (`excerpt_context_lines`);
  - thứ tự file: conflict, rồi file đã theo dõi, rồi file mới; file bị xóa thu gọn sẵn;
  - khi trạng thái đổi thì dựng lại danh sách file, khi diff của một file đổi thì chỉ dựng lại file đó;
  - nạp tối đa 16 file cùng lúc;
  - trạng thái rỗng là chữ "No uncommitted changes" ở giữa.

  Toolbar có hunk trước/sau, Stage, Commit và nút chuyển một cột/hai cột. View này sửa được.

Lucerna dựng view này trên excerpt list, chỉ đọc, theo bố cục của Zed và bỏ phần stage và commit.

## 6. Diff một file

- **VS Code**: `git.openChange` ("Open Changes"):
  - file đã sửa: so index (hoặc HEAD) với file trên đĩa;
  - file đã stage: so HEAD với index;
  - file mới: mở file trơn;
  - file bị xóa: mở bản ở HEAD, chỉ đọc.

  Diff editor mặc định hai cột, chuyển sang một cột khi editor hẹp hơn 900 px. Mặc định bỏ qua khoảng trắng đầu và cuối dòng.
- **Zed**: `git::OpenFileDiff` mở `SoloDiffView`, hiện toàn bộ file theo mặc định. Có dạng hai cột (`SplittableEditor`), mặc định bật, chuyển sang một cột khi hẹp hơn 100 em.

Bản đầu của Lucerna chỉ có một cột. Dạng hai cột để bản sau.

## 7. Làm mới

- **Zed**: độ trễ watcher 100 ms.
  - File trong worktree đổi: chạy `git status -- <paths>` cho riêng các đường dẫn đó rồi vá vào cây.
  - File trong `.git` đổi (`index`, `HEAD`, `refs/…`): quét lại toàn bộ.
  - Bỏ qua `objects`, `hooks`, `lfs`, `rebase-*`, `sequencer`, `fsmonitor--daemon`, `COMMIT_EDITMSG`, `FETCH_HEAD`, `ORIG_HEAD`, `gc.pid`.
  - Không giới hạn số mục và không giới hạn cỡ file.
- **VS Code**: debounce 1 s, chờ git rảnh **và** cửa sổ đang focus, chạy `git status -z -uall`, rồi giữ 5 s.
  - `git.statusLimit` mặc định 10.000. Vượt ngưỡng thì repo bị coi là "quá lớn": ngừng tự làm mới và báo một lần.
  - Giới hạn cỡ file khi diff: 50 MB (`diffEditor.maxFileSize`).

Lucerna làm mới nhanh như Zed vì người dùng muốn thấy ngay khi agent ghi file, và lấy ngưỡng `git.statusLimit` của VS Code để bảo vệ repo rất lớn.

## 8. Restricted Mode

- **VS Code**: extension git không chạy trong workspace chưa tin cậy.
- **Zed**: vẫn chạy git, nhưng tắt hooks, credential helper và diff ngoài.

Config cục bộ của repo (`core.fsmonitor`, `filter.*.clean`, `diff.*.textconv`) có thể chạy lệnh tùy ý ngay cả khi chỉ đọc trạng thái. Vì vậy Lucerna theo VS Code: không chạy git trong thư mục chưa tin cậy.

## 9. Lucerna đo được (5.1)

Đo bằng benchmark không giao diện `crates/lucerna-workbench/tests/git_perf.rs` (`#[ignore]`, đặt `LUCERNA_GIT_BENCH_REPO`). Nó chạy `GitStore` thật trong `TestAppContext` với `git` thật, tính giờ bằng `std::time::Instant`. Repo: Zed ở revision đã pin (4.401 file, `crates/editor/src/editor.rs` dài 13.446 dòng); bước commit chạy trên nhánh tạm `lucerna-bench` trong bản clone, rồi xóa clone. Máy: macOS, build **debug** (chưa tối ưu), nên số thật của bản release chỉ tốt hơn. Một lần chạy, chưa lấy trung bình.

| Ngưỡng (spec §5) | Đo được | Kết quả |
|---|---|---|
| Màu Explorer hiện ≤ 500 ms sau khi quét xong (lần rescan đầu → snapshot đầu) | 321 ms | đạt |
| 1 file đổi → snapshot cập nhật ≤ 300 ms (`paths_changed`, 1 file) | 49 ms | đạt (không gồm độ trễ của watcher) |
| 500 file ghi cùng lúc: việc làm mới gộp lại, tối đa một việc chờ | 2 job status (gồm job đang chạy), settle sau 432 ms, gồm cả thời gian ghi 500 file | đạt |
| Commit → cập nhật ≤ 1 s (commit, `rescan` → snapshot) | 276 ms | đạt |
| Diff gutter file 13.446 dòng ≤ 20 ms ở luồng nền | 104 ms tổng, gồm đọc blob qua `git cat-file` và diff, debounce 50 ms nằm ở đồng hồ giả | chưa tách riêng phần diff; xem ghi chú |

Ghi chú về dòng cuối: 104 ms là toàn bộ chuỗi (spawn `git`, đọc blob, diff, publish) ở bản debug, không phải riêng phép diff. Phép diff nằm ở luồng nền, nên không chặn luồng UI. Chưa có số riêng cho `diff_hunks` ở bản release, nên mục 20 ms chưa được xác nhận bằng phép đo trực tiếp.

**Chưa đo:**
- Rớt khung hình khi 500 file được ghi: cần chạy giao diện thật và xem log frame-time. Benchmark chỉ đo số job và thời gian settle. Việc làm mới chạy ở luồng nền và gộp lại nên luồng UI không bị chặn, nhưng chưa quan sát bằng mắt.
- Độ trễ của watcher (từ ghi file đến sự kiện): không nằm trong benchmark không giao diện; số ở trên bắt đầu từ lúc gọi `paths_changed`.
- Kích thước binary: không build release vì thư mục `target/` dùng chung với các phiên khác đang chạy cargo. Lập luận: so với `7db69cb`, `Cargo.lock` chỉ thêm crate `lucerna-git`; các phụ thuộc ngoài của nó (`similar`, `notify`, `crossbeam-channel`, `tracing`) đã có sẵn trong workspace, nên binary chỉ lớn thêm đúng phần mã của `lucerna-git`. Chưa đo.
