# Research: the integrated terminal in VS Code and Zed

Date 2026-11-13. Supports Lucerna's integrated terminal spec (phase 5).

Sources:
- **VS Code:** the docs `code.visualstudio.com/docs/terminal/{basics,appearance,advanced,profiles,shell-integration}`, `docs/editor/workspace-trust`, and the source of `microsoft/vscode` branch `main` (`src/vs/workbench/contrib/terminal/`, `terminalContrib/links/`, `src/vs/platform/terminal/`). **Which keys go to the shell and which to the workbench.** A key is first matched against the workbench keybindings. If the command found is in the `terminal.integrated.commandsToSkipShell` list, the workbench handles it; otherwise xterm sends the key down to the PTY. The default list lives in the code (`DEFAULT_COMMANDS_TO_SKIP_SHELL`): the terminal commands above, Quick Open, Command Palette, `togglePanel`, switching editors, focusing editor groups, zoom, full screen… Users add IDs, or remove a built-in ID with the `-` prefix. `terminal.integrated.sendKeybindingsToShell` (default false) reverses this: it sends nearly all keys to the shell. `terminal.integrated.allowChords` (default true) lets chords like ⌘K ⌘X reach the workbench.

### 1.3 Panel

- The terminal is a view container in the bottom panel, shared with Problems, Output, Debug Console. The Terminal tab disappears when no terminal is left (`hideIfEmpty`).
- With two or more terminals, the tab list appears on the **right** of the panel (`tabs.hideCondition: singleTerminal`). Each tab has an icon, a name, a description and a status (bell, task result). Drag to reorder; the `+` button and the profile menu create a new terminal.
- A split is a horizontal row of cells in the same "group" (one entry in the tab list).
- Maximize the panel with `workbench.action.toggleMaximizedPanel`. The panel can be placed at the bottom, left or right.
- Resizing: xterm.js recomputes the column/row counts from the frame size and the font metrics, then sends the new size down to the PTY (`TIOCSWINSZ`).

### 1.4 Links

- Detector order: extension links, multi-line links, **local files** (when `enableFileLinks` is not `off`), URIs, then word links.
- Activation: hold ⌘ then click (if `editor.multiCursorModifier` is `ctrlCmd` then use ⌥). Hovering shows a key hint.
- Recognized position suffixes: `file:1:2`, `file:line 1, column 2`, `file(1,2)` and a few other forms.
- Path resolution (`terminalLinkResolver.ts`): strip the `:line:col` and `?query` suffix; expand `~`; a relative path is joined to the terminal's **initial cwd**; `stat` to confirm; 10-second cache. If the file is not found it falls back to a search link: opens a quick pick searching the workspace, and a single result opens directly.
- Opening: a file opens in the editor and the cursor is placed per `:line:col`. A folder in the workspace is revealed in the Explorer; outside the workspace it opens a new window.
- A URL opens only if its scheme is in `allowedLinkSchemes`; otherwise it asks.

### 1.6 Workspace Trust

The Workspace Trust docs say it plainly: **opening a terminal is blocked by default when the folder is in Restricted Mode.** VS Code shows a prompt asking whether to trust the folder; clicking Cancel keeps Restricted Mode and does not open the terminal. Reason: shells are often configured to run code automatically based on the contents of the current folder (direnv, `.nvmrc`, prompt themes that read git…).

The setting `terminal.integrated.allowInUntrustedWorkspace` (default false) skips this check. Confirmed in the code: `terminalConfiguration.ts` declares the setting, `terminalInstance.ts` checks it before demanding trust. In addition, the settings `cwd`, `env.*`, `shellIntegration.enabled`, `profiles` are *restricted*: values at workspace scope are ignored when the folder is not trusted, values at User scope still apply.

### 1.7 Environment variables

`TERM_PROGRAM=vscode`, `TERM_PROGRAM_VERSION`, `COLORTERM=truecolor`, `TERM=xterm-256color` *(unverified in the code)*. `LANG` is set to a UTF-8 locale if missing (`detectLocale`), because GUI apps on macOS often have no `LANG`. Env merge order: the host process's env, then `terminal.integrated.env.<os>`, then the profile's `env`. Shell integration adds the `VSCODE_*` variables and changes `ZDOTDIR` for zsh.

### 1.8 Edge cases

- On macOS the terminal runs the shell as a **login** shell (`-l`, zsh `-il`), because GUI apps have a minimal `PATH`. Set `args` to empty to drop this.
- Option is not Meta unless `macOptionIsMeta` is on.
- ⌘K (clear) blocks every ⌘K chord when focus is in the terminal.
- TUIs and the alt screen: the scroll commands work only on the main screen. When an app turns on mouse mode, clicks go down to the app; Option+click (needs `macOptionClickForcesSelection`) forces text selection.
- Bracketed paste can print junk `[201~` with a few shells, hence `ignoreBracketedPasteMode`.
- Heavy traffic: the pty host pauses the PTY when a threshold is exceeded and resumes when the renderer acknowledges *(unverified)*.

## 2. Zed (revision `b5cd310`)

### 2.1 Architecture

- `crates/terminal` uses the fork `zed-industries/alacritty` (`alacritty_terminal 0.26.1-dev`). All of alacritty's types are hidden behind an adapter layer (`alacritty.rs`); the rest uses Zed's own types (`Cell`, `IndexedCell`, `Point`, `Modes`, `Cursor`, `Selection`). This way the backend can be swapped.
- Initialization runs on the background executor: removes `SHLVL`, sets `LANG=en_US.UTF-8` if missing, sets `ZED_TERM=true`, `TERM_PROGRAM=zed`, `TERM=xterm-256color`, `COLORTERM=truecolor`, `TERM_PROGRAM_VERSION`. `Term` sits in an `Arc<FairMutex<Term>>`. `tty::new` opens the PTY, then alacritty's `EventLoop` runs on its own I/O thread. The UI thread's signal mask is passed to the child process so Ctrl-C still works even though the PTY is created off the main thread.
- **Event flow.** The PTY thread reads and parses bytes, then sends events (`Wakeup`, `Title`, `Bell`, `PtyWrite`, `ClipboardStore`, `ChildExit`…) through a channel. The UI side batches events in a **4 ms** window: the first event is handled immediately to reduce latency, many `Wakeup`s merge into one flag, at most 100 events per batch, then `yield`. Raw bytes do not go through the channel; only signals do.
- **Changes from the UI** (resize, scroll, select, clear, link lookup) are queued and then applied in `sync()`, under the same lock hold.
- **Snapshot per frame.** `sync()` is called at prepaint: it takes the lock once, applies the queue, then copies the **visible** cells into a `Vec<IndexedCell>`, along with the mode, cursor, selection, scroll position. Painting only reads this snapshot.
- **Lock.** Alacritty's `FairMutex`: the PTY thread uses `try_lock_unfair` when reading, blocks outright only when 1 MB is backed up unprocessed, and parses at most 64 KB per lock hold. The UI side holds the lock briefly.

### 2.2 Painting (`terminal_element.rs`)

- Font, size, weight come from the terminal settings, falling back to the buffer font. Ligatures are off. Line height is a factor: `standard` 1.3, `comfortable` 1.618, or custom. Cell width is the advance of the character `m`.
- The size is forced to a whole number of lines in device pixels; the remainder goes on top when content is bottom-anchored (alt screen, or scrolled to the bottom). The origin is rounded to pixels so nothing jitters when resizing.
- **Run merging:** adjacent cells on the same line with the same font, color, background, underline, strikethrough are merged into one `BatchedTextRun`, drawn with `shape_line` with a fixed cell width so glyphs fit the grid. A run is cut at the end of the line.
- **Backgrounds:** cells with a non-default background are joined into strips by line, then merged, each strip being one quad.
- Empty cells and the padding cells of wide characters are skipped. Block and shade characters (U+2580…, sextant, quadrant) are drawn as rectangles on an 8×24 sub-grid instead of glyphs, so TUIs look seamless.
- When clipped only the visible lines are laid out; off-screen lines are not.
- **No layout cache between frames.** Every prepaint re-merges the whole visible grid. The saving comes from painting only on `Wakeup`.
- Paint order: background, highlights (search results, selection), text, block characters, cursor, IME, link tooltip.
- A block cursor draws the character beneath it in the background color. When focus is lost the cursor is hollow.
- **Colors:** the theme keys `terminal.ansi.{black…white}`, `terminal.ansi.bright_*`, `terminal.ansi.dim_*`, `terminal.foreground`, `terminal.bright_foreground`, `terminal.dim_foreground`, `terminal.background`. Indexes 0–15 take the theme, 16–231 take the xterm color cube, 232–255 the gray ramp, truecolor is used directly.
- **Minimum contrast** (APCA-style, default 45): not applied to colors the app chose exactly (truecolor, indexes 16–255) and to decorative characters.

### 2.3 Behavior

- **Scrollback:** default 10,000 lines, hard cap 100,000.
- **Select and copy:** drag threshold 2 px. Copy keeps the selection. `copy_on_select` is off by default. Linux also writes the primary selection.
- **Paste:** bracketed paste wraps in `ESC[200~`…`ESC[201~` and filters ESC characters; otherwise newlines are converted to CR.
- **Mouse:** mouse reporting goes to the app when the app has turned on mouse mode and Shift is not held. In the alt screen with `ALTERNATE_SCROLL`, the scroll wheel sends arrow keys.
- **Links:** OSC 8 is taken from cell attributes. Otherwise the URL regex runs, then the path regexes (`path_hyperlink_regexes`, with `path` and `line` groups), with a 1 ms time budget. Detection runs only while ⌘ is held, at most every 100 ms or every 5 px. A path carries the cwd **at that line** of the scrollback. Resolved heuristically: absolute, relative to the cwd, relative to the worktree root, stripping the git `a/` `b/` prefix, then scanning the worktree by suffix.
- **Bell:** off by default; when on, marks the tab until the next keystroke.
- **Tab name:** from the foreground process (detected with `sysinfo`): `<cwd folder name> — <command>`, cut to 25 characters. OSC 0/2 goes only to the breadcrumb.
- **Working directory:** setting `working_directory`, default `current_project_directory`. At runtime, the cwd is detected from the foreground process, not through OSC 7.
- **Process exit:** for an interactive shell the tab closes if the user has typed anything; if not, it closes only when the exit code is 0, so a broken `$SHELL` error stays visible.
- **Shell:** `"system"`, `{ "program": … }`, or `{ "with_arguments": … }`. Has `env`, `detect_venv`.
- `option_as_meta` defaults to false.

### 2.4 UI

- `TerminalPanel` is a dock panel, at the **bottom** by default; changeable to left/right (`terminal.dock`). Default height 320 px at the bottom, width 640 px at the side. Opening the panel when there is no terminal creates one.
- **A status bar button** (terminal icon, tooltip "Terminal Panel"), can be hidden with `terminal.button: false`.
- Inside the panel are panes with an **always-visible tab bar** (about 32 px tall, background `tab_bar.background`, bottom border `border`). The buttons on the right of the tab bar appear only when the pane has focus: `+` (New Terminal), Split, Zoom.
- The dock uses `panel.background`, a 1 px border on the edge facing the editor, a 6 px resize handle. The terminal body has background `terminal.background`, with a vertical scrollbar.
- **Keys:** ⌃` toggles the panel, ⌃~ new terminal, ⌘J toggles the bottom dock. In the terminal: ⌘C/⌘V, ⌘K clear, ⌘N new terminal, ⌘F find, ⌘A select all, ⌘D split, ⌘←/⌘→ send Ctrl-A/Ctrl-E, ⌘⌫ sends Ctrl-U, ⌥←/⌥→ send ESC b / ESC f, ⌘↑/⌘↓/⌘Home/⌘End scroll.
- The terminal is also an ordinary workspace item, so it can be opened in the editor area, and dragged between the panel and the editor area.

### 2.5 Trust

There is no trust check anywhere in `crates/terminal` and `crates/terminal_view`. **Opening a terminal by hand is never blocked.** Indirectly: a project's local settings (`.zed/settings.json`, including `terminal.shell` and `env`) are held back until the worktree is trusted; auto-run tasks also run only in a trusted worktree.

### 2.6 Performance tips worth learning (design, not code)

1. Parse on the PTY thread; send only the merged `Wakeup` signal to the UI.
2. Batch 4 ms on the UI side, merge wakeups, at most 100 events per batch.
3. Repaint only on `Wakeup`; each frame takes one snapshot under one short lock.
4. Limit the parse per lock hold (64 KB) and the 1 MB threshold on the read side, both built into alacritty.
5. Queue user operations, apply them in `sync()`.
6. Resize the PTY only when the rows, columns or metrics change; merge consecutive resizes.
7. Merge text runs, merge background quads, draw block characters as rectangles.
8. Skip off-screen lines; round to device pixels.
9. Rate-limit link detection and give it a time budget.

## 3. Comparison and Lucerna's choices

| Topic | VS Code | Zed | Lucerna's choice |
|---|---|---|---|
| Emulation core | xterm.js (JS) | `alacritty_terminal` (fork) | `alacritty_terminal` from crates.io 0.26.0, hidden behind an adapter like Zed |
| Position | bottom panel, shared with Problems/Output | bottom dock, changeable to left/right | bottom panel (following Zed for UI) |
| Tabs | list on the right, shown only when ≥ 2 | tab bar on top, always visible | tab bar on top, always visible, following Zed |
| Toggle key | ⌃` | ⌃` | ⌃` |
| Commands, settings | `workbench.action.terminal.*`, `terminal.integrated.*` | `terminal_panel::*`, `terminal.*` | following VS Code |
| Keys in the terminal | ⌘K clear, ⌘C/⌘V | ⌘K, ⌘C/⌘V, ⌘←/⌘→ send Ctrl-A/E | VS Code's, plus Zed's ⌘←/⌘→/⌘⌫/⌥←/⌥→ because they are handy for the shell |
| Scrollback | 1000 | 10,000, cap 100,000 | see the spec |
| Theme colors | `terminal.ansi*` | `terminal.ansi.*` | read the Zed theme keys (Lucerna's themes come from Zed extensions) |
| File links | ⌘click, resolved against the initial cwd, falls back to search | ⌘click, cwd per line, worktree-scan heuristic | ⌘click, by cwd and workspace root |
| Restricted Mode | blocks, asks for trust; has `allowInUntrustedWorkspace` | does not block; only holds back local settings | see the spec |
| Painting | WebGL | runs per line, paint only on Wakeup | following Zed |

## 4. The `alacritty_terminal` license

Checked on 2026-11-13 with a temporary crate depending only on `alacritty_terminal = "0.26.0"`, running `cargo deny check licenses bans sources` with Lucerna's `deny.toml`, adding the targets `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `x86_64-pc-windows-msvc`:

- **Result: `licenses ok`, `bans ok`, `sources ok`** on all three platforms. There is only a duplicate-version warning for `windows-sys` (0.59 and 0.61), at the `warn` level.
- `alacritty_terminal` is Apache-2.0. The dependencies are all MIT, Apache-2.0, Unlicense/MIT, Zlib or Unicode-3.0, already on the allow list.
- **New crates compared to the current `Cargo.lock`:** `alacritty_terminal`, `vte`, `rustix-openpty`, `signal-hook`, `miow` (Windows), `home`, `cursor-icon`. The rest (`parking_lot`, `regex-automata`, `polling`, `rustix`…) are already there.
- **Size:** a release binary (strip, thin LTO) calling `Term`, `Processor` and `tty::new` is about **290 KB** larger than an empty binary. The painting in `lucerna-workbench` will add on top.
- Zed uses a git fork of alacritty. Lucerna uses the crates.io version to avoid adding a git source to `allow-git`. If a patch from the fork is needed later, `https://github.com/zed-industries/alacritty` must be added to `deny.toml` and re-checked.
- `deny.toml` currently checks only the macOS target. When Lucerna goes to Linux and Windows, add those targets to `[graph] targets`.
