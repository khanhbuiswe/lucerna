# Welcome, Open Recent and the menu bar: implementation plan

> **For the executing agent:** REQUIRED: use the sub-skill superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to carry out this plan task by task. Steps use checkboxes (`- [ ]`) for tracking.

**Goal:** when the app opens without a folder, show a Welcome screen with a list of recent folders; add an Open Recent command (⌃R); add a watermark in the empty editor area; add a full menu bar built from command IDs.

**Architecture:**
- `recent.rs` is pure storage, no gpui.
- `RecentPicker` is shared by Welcome and the workbench.
- `WelcomeView` is the root view of a window that has no folder yet. `Router` switches the root to `Workbench` with `replace_root`.
- In the workbench, opening a different folder starts a new `luc` process and then closes the current window.
- The menu is a data table. `build_menus` is a pure function; every item calls a single GPUI action, `RunCommand`.

**Tech stack:** Rust, GPUI (Zed rev `b5cd310`), serde_json, tempfile for tests.

**Spec:** `docs/superpowers/specs/2026-11-12-welcome-design.md`. Research: `docs/research/2026-11-12-welcome.md`. Read the spec before each task. Each task lists the § sections it implements.

## Global Constraints

- Only `lucerna-workbench` may use gpui. `recent.rs` and `build_menus` must not call gpui, except the `gpui::Menu` type in the output of `build_menus`.
- Do not add macOS-only assumptions outside code placed behind `cfg(target_os = "macos")` or outside the menu-building layer (`Platform`).
- The UI thread never waits on I/O. `load`, `existing`, `record`, `remove`, `clear` of the recent list run through `cx.background_spawn`.
- Change shared files as little as possible:
  - `default-keybindings.json`: add exactly 5 lines;
  - `default-settings.json`: add 2 keys;
  - `lib.rs`: add the `mod` and `pub use` lines that are needed.
- Do not touch `lucerna-editor`, `save.rs` (only call `confirm_quit`), the conflict bar, `merge`.
- Before every `cargo test` or build:
  - run `export PATH="/opt/homebrew/opt/rustup/bin:$PATH"` and `scripts/prune-target.sh`;
  - keep only one build profile;
  - do not delete a profile when `pgrep -x cargo` shows another session is building;
  - free disk space must not drop below about 1.2 GB.
- Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, and files are staged by explicit path.
- Displayed strings are taken verbatim from the spec:
  - "Welcome to Lucerna" / "Welcome back to Lucerna", "GET STARTED", "RECENT", "More…";
  - "Select to open (⌘Enter for a new window)", "No recently opened folders";
  - "Remove from Recently Opened", "Open in New Window";
  - "Do you want to clear all recently opened folders?" with two buttons Clear / Cancel.
- Command to run a crate's tests: `cargo test -p lucerna-workbench <test name>` (run from the repo root). The `lucerna-settings` command is similar.

## Review Focus

1. A folder is deleted after the list was loaded and the user still clicks it: show the message "‹path› no longer exists", remove the entry from the list, no crash and open nothing (Task 5, Task 7).
2. Choosing another folder (Open Recent or Close Folder) while there are unsaved files, then clicking Cancel in the save prompt: the window stays as it was and no process is started (Task 7).
3. The new process cannot be started: the window stays open and the status bar reports the error (Task 7).
4. The user removes a binding (`-workbench.action.openRecent`) or changes it to a chord: the watermark drops the corresponding line, the menu shows no key, no panic (Task 3, Task 8).
5. No `HOME` (data dir is `None`) or a corrupt `recent.json`: Welcome shows only GET STARTED, every write is skipped, the corrupt file is renamed to `.bak` (Task 1, Task 5).
