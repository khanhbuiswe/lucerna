# Git 5.1 (core, Explorer colors, gutter) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lucerna reads the repository through the `git` CLI in the background, colors changed files and folders in the Explorer, and draws change bars in the editor gutter against `git.diffBase`. Change navigation uses Alt+F5 and Shift+Alt+F5, plus `]c` and `[c` in Vim. Everything updates by itself when an agent writes files or commits.

**Architecture:**
- A new gpui-free crate, `lucerna-git`, does all the git work:
  - runs `git` with hardening flags;
  - parses `status --porcelain=v2 -z`;
  - keeps a long-lived `cat-file --batch` process;
  - resolves the default branch and the merge-base;
  - watches the git dirs;
  - diffs lines into hunks.
- In the workbench, a `GitStore` entity per window owns one `Repo` and a serial job queue, where a job replaces a queued job of the same key. It publishes immutable `GitSnapshot`s (statuses plus folder rollups) and per-file `Arc<[Hunk]>`.
- The `ExplorerView` reads the snapshot to color rows. `CodeView` paints hunks given to it like diagnostics.

**Tech Stack:** Rust 2024, `std::process`, `similar` (already a workspace dependency), `notify` and `crossbeam-channel` (already in the workspace), gpui (workbench only). No new external crates.

**Spec:** `docs/superpowers/specs/2026-11-13-git-view-design.md`. Research: `docs/research/2026-11-13-git.md`. This plan covers spec §4.1–§4.6, §4.9 (navigation rows only), §4.10, §4.11, §4.12, §5 and §6. The diff tabs, `git.openChange` and the gutter click are in plan 5.2 (`2026-11-14-git-5-2-diff-views.md`).

## Global Constraints

- **Licensing:**
  - The project is MIT OR Apache-2.0.
  - Zed's `git`, `buffer_diff`, `git_ui` and `project` crates are GPL: **learn the design, never copy code.**
  - `cargo deny check` must pass.
- **Crates:**
  - Only `lucerna-workbench` uses gpui.
  - `lucerna-git` depends on `similar`, `notify`, `crossbeam-channel` and `tracing` only, plus `lucerna-text` for `decode_file`. It does **not** depend on `lucerna-lsp`: it receives the path of the `git` binary.
- **Threads:** no `git` process, file read or diff on the UI thread, ever. The UI only swaps in finished snapshots.
- **Every `git` invocation** is exactly `git -c core.fsmonitor=false -c core.hooksPath=/dev/null --no-optional-locks --no-pager <args>`, run with:
  - env `GIT_TERMINAL_PROMPT=0` and `LC_ALL=C`;
  - stdin null;
  - current dir = the worktree root.

  On Windows, `core.hooksPath` is `NUL`.
- **Status command:** `status --porcelain=v2 -z --untracked-files=all --no-renames [-- <pathspecs>]`.
- **Default-branch order:**
  1. `refs/remotes/upstream/HEAD`;
  2. `refs/remotes/origin/HEAD`;
  3. local `main`;
  4. local `master`.

  If none exists, there is no default branch.
- **Ignored inside git dirs:**
  - directories: `objects`, `hooks`, `lfs`, `logs`, `rebase-merge`, `rebase-apply`, `sequencer`, `fsmonitor--daemon`;
  - files: `COMMIT_EDITMSG`, `FETCH_HEAD`, `ORIG_HEAD`, `gc.pid`, and any `*.lock`.
- **Limits:**
  - no diff for files over **8 MB**, or binary (a NUL in the first 8 KB);
  - gutter debounce **50 ms**;
  - a `git` command killed after **10 s**;
  - `git.statusLimit` default **10000**.
- **Settings** (exact keys and defaults), added to `crates/lucerna-settings/assets/default-settings.json`:
  - `"git.enabled": true`
  - `"git.path": null`
  - `"git.decorations.enabled": true`
  - `"git.diffBase": "head"` (or `"defaultBranch"`)
  - `"git.statusLimit": 10000`
  - `"explorer.decorations.colors": true`
  - `"explorer.decorations.badges": false`
  - `"scm.diffDecorations": "all"`
  - `"scm.diffDecorationsGutterAction": "diff"`
- **Theme keys** (Zed names). The fallbacks are VS Code dark/light defaults; the values are in Task 4.
- **Restricted Mode:** no `git` process runs while the window's folder is untrusted.
- **Before any `cargo test`:** run `scripts/prune-target.sh`, and stage files by explicit path. Cargo needs `export PATH="/opt/homebrew/opt/rustup/bin:$PATH"`.

## Review Focus

1. **An agent writes 500 files in one second.** The UI keeps painting. At most one "refresh paths" job and one "rescan" job are queued, and the final colors match `git status`. Test: Task 5 `burst_of_changes_coalesces_into_one_queued_refresh`.
2. **Paths with spaces, Unicode and newlines, or a workspace that is a subfolder of the repo.** Status is parsed from `-z` output, and paths are mapped from repo-relative to workspace-relative paths. Files outside the workspace are dropped. Tests: Task 1 `parses_unicode_and_space_paths`, Task 5 `workspace_in_subfolder_maps_paths`.
3. **No `git` on macOS, or only the `/usr/bin/git` shim without Command Line Tools.** Lucerna never runs the shim. It shows "Git not found" once and turns the features off. Test: Task 3 `shim_without_clt_is_not_git`.
4. **A CRLF file with `core.autocrlf`.** The gutter must not mark every line. The blob is decoded with `decode_file`, which already turns CRLF into LF. Test: Task 2 `crlf_base_equals_lf_buffer`.
5. **A hostile repo config in an untrusted folder.** No `git` runs until the folder is trusted, and the hooks and fsmonitor never run even when it is trusted. Tests: Task 1 `hooks_and_fsmonitor_never_run`, Task 6 `untrusted_folder_runs_no_git_and_prompts`.

### Task 2: Repo, blobs and hunks

**Files:**
- Create: `crates/lucerna-git/src/{repo.rs,blobs.rs,hunks.rs}`
- Create: `crates/lucerna-git/tests/{repo.rs,hunks.rs}`

**Interfaces:**
- Consumes: `GitBinary`, `GitError` and `parse_status_v2` (Task 1).
- Produces:
  - `pub struct Repo` (cheap to clone, `Send + Sync`). It holds:
    - `workdir: PathBuf`, the toplevel;
    - `git_dir: PathBuf`;
    - `common_dir: PathBuf`;
    - `prefix: PathBuf`, the workspace root relative to `workdir` (empty when equal);
    - `git: GitBinary`;
    - `blobs: Arc<Mutex<BlobReader>>`.
  - `Repo::discover(git: GitBinary, workspace_root: &Path) -> Result<Option<Repo>, GitError>`. It runs `rev-parse --show-toplevel --absolute-git-dir --git-common-dir`. `Ok(None)` means not in a repo.
  - `Repo::status(&self, paths: Option<&[PathBuf]>) -> Result<Vec<(PathBuf, FileStatus)>, GitError>`. Paths in and out are **workspace-relative**. Entries outside the prefix are dropped.
  - `Repo::head_oid(&self) -> Result<Option<String>, GitError>`. `None` means no commit yet.
  - `Repo::default_branch(&self) -> Result<Option<String>, GitError>`, following the order in Global Constraints and using `rev-parse --verify --quiet`.
  - `Repo::merge_base(&self, rev: &str) -> Result<Option<String>, GitError>`
  - `Repo::changed_since(&self, base: &str) -> Result<Vec<(PathBuf, FileStatus)>, GitError>`. It combines `diff --name-status -z --no-renames <base>` with the untracked entries from `status`, as workspace-relative paths.
  - `Repo::branches(&self) -> Result<Vec<String>, GitError>`. It runs `for-each-ref --format=%(refname:short) refs/heads refs/remotes` and drops `*/HEAD`. Used by plan 5.2.
  - `Repo::read_blob(&self, rev: &str, path: &Path) -> Result<Option<Vec<u8>>, GitError>`. It uses `BlobReader`, which sends `<rev>:<repo-relative path>\n` and reads `<oid> blob <size>\n<bytes>\n`. A `missing` reply is `Ok(None)`. Non-blob types are `Ok(None)`. The process is restarted once if it died.
  - `pub enum HunkKind { Added, Modified, Deleted }`
  - `pub struct Hunk { pub kind: HunkKind, pub rows: Range<u32>, pub base_rows: Range<u32> }`
    - `rows` are 0-based current rows. For `Deleted` it is the empty range at the row that follows the deletion.
    - `base_rows` are the base rows that were removed or replaced.
  - `pub fn diff_hunks(base: &str, current: &str) -> Vec<Hunk>`. It is line-based, using `similar::TextDiff::from_lines` with `Algorithm::Myers`. Pure insert is `Added`, pure delete is `Deleted`, and anything else is `Modified`. Both inputs are LF text.
  - `pub fn load_base_text(bytes: &[u8]) -> Option<String>`. It returns `None` when the bytes are over 8 MB or `decode_file(bytes, false)` fails (binary). Otherwise it returns `Decoded.text`.
  - `pub const MAX_DIFF_BYTES: u64 = 8 * 1024 * 1024;`

### Task 5: `GitStore` entity

**Files:**
- Create: `crates/lucerna-workbench/src/git/mod.rs`
- Modify: `crates/lucerna-workbench/src/lib.rs` (`pub mod git;` and re-export `GitStore`, `GitSnapshot`, `GitStoreEvent`)
- Modify: `crates/lucerna-workbench/Cargo.toml` (add `lucerna-git`)
- Test: `crates/lucerna-workbench/tests/git_store.rs`

**Interfaces:**
- Consumes: `Repo`, `GitDirWatcher`, `diff_hunks`, `load_base_text` and `locate_git` (Tasks 1–3), and `Rollup` (Task 4).
- Produces:
  - `pub enum GitState { Off, Locating, NoGit, NoRepo, Restricted, Ready, TooManyChanges }`
  - `pub struct GitSnapshot`: `generation: u64`, `statuses: Arc<HashMap<Arc<Path>, FileStatus>>` (workspace-relative, against `git.diffBase`), `rollup: Arc<Rollup>`, `head: Option<String>`, `base_rev: Option<String>` (the resolved diff-base oid), `default_branch: Option<String>`.
  - `pub enum GitStoreEvent { SnapshotChanged, HunksChanged(Arc<Path>), StateChanged }`
  - `impl GitStore`:
    - `pub fn new(root: PathBuf, cx: &mut Context<Self>) -> Self`. It starts in state `Off`. Nothing runs until `set_trusted(true)`.
    - `pub fn set_trusted(&mut self, trusted: bool, cx)`. On `true` with `git.enabled`:
      1. locate `git` in the background (`login_shell_env()` once, cached in a `OnceLock`);
      2. `Repo::discover`;
      3. start the watcher (skipped on the test scheduler, as `OpenFileWatcher` does);
      4. queue a rescan.

      On `false` the state is `Restricted` and the repo and watcher are dropped.
    - `pub fn state(&self) -> GitState`
    - `pub fn has_repo_hint(root: &Path) -> bool`. It reuses `git_branch::head_path(root).is_some()` and is used by trust before git runs.
    - `pub fn snapshot(&self) -> GitSnapshot`
    - `pub fn paths_changed(&mut self, paths: Vec<Arc<Path>>, cx)` queues the job `RefreshPaths`. Queued paths are merged.
    - `pub fn rescan(&mut self, cx)` queues the job `Rescan`. It also re-resolves `default_branch` and `base_rev`, and reloads the base text of every tracked file.
    - `pub fn track_buffer(&mut self, path: Arc<Path>, snapshot: BufferSnapshot, cx)` (re)computes that file's hunks 50 ms after the last call. It loads the base text from `base_rev` when it is not cached for this `base_rev`.
    - `pub fn untrack_buffer(&mut self, path: &Path)`
    - `pub fn hunks(&self, path: &Path) -> Option<Arc<[Hunk]>>`
    - `pub fn settings_changed(&mut self, cx)`. A change to `git.enabled`, `git.path` or `git.diffBase` restarts or rescans.
  - **Job queue:**
    - one `Task` runs at a time;
    - `pending: Option<Job>` per key;
    - `Rescan` supersedes `RefreshPaths`;
    - a `RefreshPaths` arriving while another is queued merges its paths;
    - each finished job emits `SnapshotChanged` once.
  - **Too many changes:** a status with more than `git.statusLimit` entries sets `TooManyChanges`, keeps that snapshot and stops reacting to `paths_changed` and to the watcher. `rescan` (from `git.refresh`) still runs. The status bar shows once: "Too many changes in this repository; automatic Git updates are off. Run Git: Refresh to update."
  - **Errors:** a failing job keeps the last snapshot, logs with `tracing::warn!`, and shows a status message once per session.
  - **diffBase:**
    - with `"head"`, statuses come from `Repo::status(None)` and `base_rev = head_oid`;
