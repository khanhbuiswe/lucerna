# Hot exit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Never lose unsaved changes when the app quits, by any route: continuous backup, quitting without asking, and restoring on the next open.

**Architecture:**
- A module that does not use gpui, `hot_exit/store.rs`, handles the format and the reading and writing of backup files in `<data_dir>/backups/<workspace key>/`.
- An entity `HotExit`, one per workbench, listens to `DocumentEvent` to schedule a write after 1000 ms and delete the backup when the file is clean. It also flushes on quit.
- `Documents` gets one more job, `Restore`, to load text from a backup instead of from disk.
- The `quit()` flow calls flush first. Only the files whose backup write failed have to go through the save dialog.

**Tech Stack:** Rust, GPUI (`b5cd310`), `sha2`, `serde_json`, `tempfile` (tests).

**Spec:** `docs/superpowers/specs/2026-11-16-hot-exit-design.md` (read together with `docs/research/2026-11-16-hot-exit.md`).

## Global Constraints

- Only `lucerna-workbench` uses gpui. `hot_exit/store.rs` does not import `gpui`.
- Backup write debounce: **1000 ms**.
- `files.hotExit`: `"onExit"` (default) | `"off"`. Any other value, including `"onExitAndWindowClose"`, is read as `"onExit"`. This is an app-scope setting (`is_app_scope`).
- Storage location: `<data_dir>/backups/<key>/`.
  - A folder's key is the hex SHA-256 of the canonical path.
  - A single-file window's key is the hex SHA-256 of `"file:" + canonical path`.
  - A backup file's name is the hex SHA-256 of the file's absolute path.
  - The directory also holds a `workspace.json` with `{ "version": 1, "kind": "folder"|"file", "path": … }`.
- Backup file format:
  - Line 1 is one-line JSON: `version` (=1), `path`, `mtime` (`[secs, nanos]` or `null`), `size` (or `null`), `base_sha256` (hex or `null`), `encoding` (WHATWG name), `bom`, `line_ending` (`"lf"`/`"crlf"`).
  - Line 2 onward is UTF-8 text with `\n` line endings.
- Write with `workspace_state::write_atomic` (temp, then rename).
- A backup file that cannot be read is renamed to `<name>.bak` and kept.
- **Without a data dir, hot exit is off** (like `"off"`). A workbench opened with `Workbench::new`, that is, in tests, keeps the old behavior.
- Closing a window, Close/Open Folder and closing a tab **still ask to save** as they do today. A running terminal still asks on Cmd+Q.
- Cargo:
  - Run `export PATH="/opt/homebrew/opt/rustup/bin:$PATH"` first.
  - Run `scripts/prune-target.sh` before every build or test.
  - Delete `target/release` before testing, but only when `pgrep -x cargo` prints nothing.
  - Do not set `CARGO_TARGET_DIR`.
- Commit by specific path, with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Rulings settled while writing the plan

- **`base_sha256` hashes the decoded text**, that is, the UTF-8 string with `\n` from `Document::base`, not the bytes on disk.
  - Reason: `Document` already keeps `base` as text. No need to re-read the disk or change the load path to get the bytes.
  - On restore, decode the file on disk and hash that text. Both sides compare the same thing.
  - The cost: changing only the encoding or the line ending on disk (identical text) is still treated as "unchanged". On save, the document writes using the backup's `encoding`/`line_ending`.
  - Spec §5.2 is amended to match.
- **`Closed` does not delete the backup while quitting.** `HotExit` has a `quitting` flag, set when flushing on quit or in `on_app_quit`. Outside quitting, a document closed while "unsaved" can only be Don't Save, so delete.

## Review Focus

1. **Large text** (close to 20 MB) being typed continuously: no backup write on the UI thread, and an older write does not overwrite a newer one. → Test `backup_writes_keep_order` in Task 2.
2. **A save finishes while a backup write is running:** the backup must not "come back to life" after it was deleted. → Test `save_during_backup_write_leaves_no_backup` in Task 2.
3. **CRLF, BOM, UTF-16 files** restored then saved: the result is exactly the original bytes plus the edited part. → Test `restore_keeps_encoding_and_line_ending` in Task 3.
4. **Two windows: folder `/p` and a single-file window `/p/a.rs`**, both editing `a.rs`: the two backups sit in two different directories, and each window restores its own. → Test `folder_and_file_window_backups_apart` in Task 1.
5. **Disk full on Cmd+Q:** the save dialog appears, only for the files whose write failed. On Cancel the app does not quit. → Test `quit_asks_for_files_whose_backup_failed` in Task 4.

  - `Documents::backup_source(&self, path: &Path) -> Option<BackupSource>`. Returns `Some` only when the buffer is loaded and currently unsaved.

  - `pub struct HotExit` (entity), created with `HotExit::new(documents: Entity<Documents>, data_dir: PathBuf, key: WorkspaceKey, cx) -> Entity<HotExit>`. The constant `pub const BACKUP_DELAY: Duration = Duration::from_millis(1000)`.
  - `HotExit::flush(&mut self, cx) -> Task<Vec<Arc<Path>>>`: immediately writes every unsaved document and returns the paths whose write failed.
  - `HotExit::flush_blocking(&mut self, cx)`: writes synchronously, used in `on_app_quit`.
  - `HotExit::set_quitting(&mut self)`
  - `HotExit::enabled(cx: &App) -> bool`: reads `files.hotExit` from `AppState.settings`.
  - `Workbench::hot_exit(&self) -> Option<&Entity<HotExit>>`

**`HotExit` behavior:**
- `Edited` and `DirtyChanged{dirty:true}`: schedule a write after `BACKUP_DELAY`, one timer per path, typing more reschedules it.
- `DirtyChanged{dirty:false}` and `Saved` when the document is clean: cancel the timer and delete the backup.
- `Closed` when not `quitting`: delete the backup.
- Writes and deletes for the same path run in sequence on a per-path queue (chain the `Task`s). A delete always runs after the write that is in progress.
- `enabled == false`: write nothing, and on creation call `remove_all(dir)`.

### Task 3: Restore when opening a workspace

**Files:**
- Modify:
  - `crates/lucerna-workbench/src/documents.rs`: add `Job::Restore`, `JobOutput::Restored`, `Documents::open_from_backup`.
  - `crates/lucerna-workbench/src/workbench.rs`: after the `state.groups` restore part (around lines 585–606), read the backups and open tabs.
  - `crates/lucerna-workbench/src/hot_exit/tracker.rs`: `HotExit::restore(&mut self, …)` returns the list of backups.
- Test: `tests/hot_exit.rs`

**Interfaces:**
- Consumes: Task 1 (`read_backups`, `Backup`), Task 2 (`HotExit`, `BackupSource` and its fields).
- Produces:
  - `Documents::open_from_backup(&mut self, backup: Backup, cx) -> Arc<Path>`: creates the document, sets a `Restore` job, returns the key. The view opened afterward uses this document.
  - The constant `RESTORED_UNKNOWN_BASE: u64 = 0`.

**`run_job(Job::Restore { backup })`:**
- Read the file on disk (use the existing `read`). If the file cannot be read or does not exist, `disk = None`. If it reads, `decode_file`.
- Buffer: `Buffer::from_decoded(Decoded { text: backup.text, encoding: by name, has_bom: header.bom, line_ending: header.line_ending, hash: RESTORED_UNKNOWN_BASE })`.
- **Disk exists and `text_sha256(disk.text) == header.base_sha256`:**
  - `base = Some(BufferSnapshot::from_text(&disk.text))`
  - `base_hash = disk.hash`
  - `stamp = Stamp` of the disk
- **Otherwise:**
  - `base = None`
  - `base_hash = RESTORED_UNKNOWN_BASE`
  - `stamp = Stamp::from_parts(header.mtime, header.size)`
- Then call `buffer.clear_saved()` so the buffer is in the unsaved state. The undo history is empty.
- Emit `Opened` then `DirtyChanged{dirty:true}`.

**Workbench on open:**
- If there is a `HotExit`, `read_backups(dir)`.
- For each backup:
  - `documents.open_from_backup(...)`.
  - If there is no tab for the path yet, open a tab in the first group: not preview, not focused.
- Do not filter by root.

### Task 4: Quit without asking, flush when the system quits

**Files:**

- Test: `tests/hot_exit.rs`. Also fix the quit tests in `tests/multi_window.rs` if they use a data dir.

**Interfaces:**
- Consumes: Task 2 (`HotExit::flush`, `flush_blocking`, `set_quitting`, `enabled`, `Workbench::hot_exit`).
- Produces: `Workbench::confirm_quit_for(&mut self, paths: Vec<Arc<Path>>, window, cx) -> Task<bool>`. This is `confirm_quit` but it only asks for `paths` plus terminals. `confirm_quit` calls it with `dirty_paths()`.

**New `quit()`:** for each window, in the existing `windows_to_ask` order:
1. If `wb.hot_exit()` exists and `HotExit::enabled`:
   1. Really save the files for which the window's `files.autoSave` is not `"off"`. Use `save::save_each` with `dirty_paths()`.
   2. `set_quitting()`, then `failed = flush().await`.
   3. Call `confirm_quit_for(failed, …)`. If `failed` is empty and no terminal is running it returns `true` right away, without asking.
2. Otherwise: the old behavior.

Note: `agreed` is still used as before. A window that has finished flushing but still has unsaved files is not asked again.

**`on_app_quit`:** call `set_quitting()` then `flush_blocking()` **before** saving the layout.
