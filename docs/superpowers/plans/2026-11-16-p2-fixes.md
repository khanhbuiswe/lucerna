# Fix the P2 bugs before release: plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Each task is one bug (or two bugs in the same place): use superpowers:systematic-debugging to confirm the cause, then TDD. Steps use checkboxes (`- [ ]`).

**Goal:** Fix the 13 P2 bugs still open in the review report before v0.1.0.

**Architecture:** Each task:
1. Write a test that reproduces the bug, the way the report describes it.
2. See the test fail.
3. Fix the actual root cause.
4. See the test pass.
5. Add one "Fixed" line to that bug's entry in the review report.

The tasks are independent of each other; only T4-1 and T3-5 are merged because they are in the same place.

**Spec (source of behavior):** `docs/superpowers/reviews/2026-11-15-release-flow-review.md`. Each bug entry has the location, how to reproduce, the cause and a suggested fix. Read the entry for your bug first. When the report and the plan differ, the "Behavior decisions" section below wins.

## Global Constraints

- Behavior follows VS Code, UI follows Zed (`docs/design-principles.md`). Notify the user with the existing mechanisms: the status message (`status_message.rs`) or the Explorer's empty state. Do not add a new kind of UI.
- Only `lucerna-workbench` uses gpui. Make no macOS assumption outside platform-specific code.
- Do not break the hot exit behavior that was just merged (`hot_exit/`, `tests/hot_exit.rs`).
- A new dependency must be MIT/Apache, and `cargo deny check` must pass.
- Cargo:
  - Run `export PATH="/opt/homebrew/opt/rustup/bin:$PATH"` first.
  - Run `scripts/prune-target.sh` before every build or test.
  - Use the shared target; do not set `CARGO_TARGET_DIR`.
  - Delete `target/release` before testing, but only when `pgrep -x cargo` prints nothing.
  - Keep more than 1.2 GB of disk free.
- Commit by specific path, with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. One fix commit per task.
- Each task runs the tests of the crates it touches. The last task runs the whole workspace.

## Behavior decisions

These are the controller's decisions when writing the plan. The implementer does not change them on their own.

- **T2-2:** after a rename that differs only in case, the tree keeps only the new name. This applies both to an Explorer Rename and to an agent running `mv` or `git mv`.
- **T2-3:** when Cmd+Q or closing a window happens while a Paste/Duplicate is running, ask with the existing prompt, in the style of the terminal dialog: "A file operation is still running", with two buttons Quit / Cancel.
  - Cancel does not quit.
  - In addition, copy to a hidden temporary name in the same directory and rename when done. That way an interrupted copy never looks like a complete copy.
  - A running Cut and Delete count too.
- **T5-6:** a file that is open and unsaved is searched on the buffer's snapshot instead of on disk, like VS Code. Line numbers and click positions match the buffer.
- **M3-2:** when writing `trusted.json` fails:
  - the window keeps its trust for the session;
  - do not bump `TrustGeneration`;
  - show the status message "Couldn't save the trusted folders list: <error>".
- **T4-1 and T3-5:**
  - The root folder disappears (renamed, moved to the Trash, ejected): all its tabs switch to the Deleted state. The Explorer shows the empty state "Folder <name> no longer exists".
  - The root folder cannot be read: the Explorer shows the empty state "Can't read folder <name>: <reason>".
  - When the folder becomes readable again (a rescan succeeds), go back to normal.
- **T4-2:** a tab opened through a symlink reloads by itself when the target file changes, like a normal tab.
- **T3-2:** in single-file mode, Open Recent (picker and menu) hides only the file itself, not the parent folder.
- **T3-4:**
  - Opening something that is not a regular file (a FIFO, a device) makes the tab report the error "Not a regular file", without hanging and without reading.
  - `luc /dev/zero` reports an error and exits, without opening the app.
- **T5-2:** an empty group is dropped when other groups remain, including the first group, following VS Code's default `workbench.editor.closeEmptyGroups: true`. Add no setting. A restored layout does not keep empty groups either.
- **T5-3:**
  - Normalize both the path and the query to NFC before matching.
  - The highlight positions are mapped back to char indexes of the displayed string.
  - Use the crate `unicode-normalization`, MIT/Apache.
- **M1-1:** when the `luc` client hits EOF or an error before it receives a reply, it claims the socket again once (it may resend to the app that just came up), instead of reporting an error.
- **M3-1:** closing a window, or a Workbench being released, while the theme or icon theme picker is open closes the picker with a revert. The preview flag never stays stuck.
- **M2-1:** before asking to save a window during a quit, bring that window to the front: un-minimize and activate it, like Zed.

## Review Focus

1. **The root folder disappears and comes back** (drive replugged, `mv proj2 proj`): no crash, tabs return to normal, no unsaved buffer is lost. → test in Task 3.
2. **Search in the project when an unsaved file has text that is no longer on disk:** the result comes from the buffer, and a click lands in the right place. → test in Task 5.
3. **Renaming a folder with a case-only change when it has unsaved tabs inside:** the tabs follow, no duplicate document. → test in Task 1.
4. **Quit while copying, choose Quit:** no destination folder/file that looks complete but is actually missing parts. → test in Task 2.
5. **Quick Open with a file name that has both combining characters and emoji:** no panic when highlighting. → test in Task 10.

### Task 1: T2-2, rename that differs only in case
- **Location:** `lucerna-project/src/worktree.rs:471`, `watch.rs:126`, `explorer/view.rs:794`.
- **Test** (`lucerna-project/tests/`): on a case-insensitive filesystem, call `apply_fs_events` with events for both `foo.rs` and `Foo.rs` after a `rename`. The snapshot keeps only `Foo.rs`. The same for a folder, with no duplicate subtree left.

- **Workbench test:**
  - Rename the open tab `foo.rs` to `Foo.rs`: only one tab remains, with path `Foo.rs`.
  - Add the case of a folder that contains an unsaved tab (Review Focus 3).

### Task 2: T2-3, quit while a copy is running
- **Location:** `explorer/clipboard.rs:263`, `lucerna-project/src/fs_ops.rs:330-361`, `workbench.rs` (`confirm_unsaved`, quit).
- **Test:**
  - The copy goes through a hidden temporary name and is renamed only when done. While the copy is running, the destination does not exist yet.
  - Quit with a file operation running → the prompt "A file operation is still running". Cancel does not quit.

### Task 3: T4-1 and T3-5, the root folder disappears or cannot be read
- **Location:** `lucerna-project/src/coalesce.rs:49`, `worktree.rs:661`, `documents.rs` (`on_worktree_event`), the Explorer empty state (`explorer/view.rs`).
- **Test:**
  - `mv proj proj2` → the tabs are in the Deleted state, the Explorer has an empty state with the folder name.
  - `mv proj2 proj` → the Explorer is normal, the unsaved tab keeps its text unchanged (Review Focus 1).
  - `chmod 000` on the root → the empty state "Can't read folder".
- Detecting that the root disappeared: treat an event at the root (empty relative path) as a rescan signal, and during the rescan check that the root still exists. Add no polling timer.
