# Release 0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Lucerna 0.1.0 on GitHub Releases with a drag-to-install DMG, and point the landing page's Download buttons at it.

**Architecture:** `scripts/make-dmg.sh` learns to pack an already-built (and possibly re-signed) app and to fail when the Finder layout fails; `release.yml` runs it after signing and ships the DMG next to the zip. A manual workflow run proves the DMG on a runner before the tag is pushed. The site changes last, once the release exists.

**Tech Stack:** POSIX sh, GitHub Actions (`macos-14`), `hdiutil`/`osascript`, Python 3 stdlib (`scripts/check-site.py`, `unittest`), static HTML.

**Spec:** `docs/superpowers/specs/2026-11-16-release-0.1.0-design.md`

## Global Constraints

- Repository: `https://github.com/khanhbuiswe/lucerna`; version `0.1.0` (from `[workspace.package]` in `Cargo.toml`); tag `v0.1.0`.
- Asset names: `Lucerna-0.1.0-macos-aarch64.dmg`, `Lucerna-0.1.0-macos-aarch64.zip`, each with a `.sha256` beside it.
- Site download URL: `https://github.com/khanhbuiswe/lucerna/releases/download/v0.1.0/Lucerna-0.1.0-macos-aarch64.dmg`.
- Pushing `main` and pushing the tag are outward-facing: ask the user and wait for a yes before each.
- The uncommitted domain change (`lucerna.dev` → `lucerna.skynomadlabs.dev`) in `site/index.html`, `scripts/check-site.py`, `scripts/test_check_site.py` is not ours: never stage it unless the user says so. Stage hunks with `git add -p` or commit by explicit path only after checking `git diff` holds only our change.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit with `-- <paths>`.
- No local release build is needed; do not build `target/release` locally (disk is tight).
- Public copy: call the UI minimal; no new mention of Zed.

## Review Focus

1. A Developer ID–signed app re-bundled ad hoc by `make-dmg.sh` → the DMG must hold the app exactly as signed (Task 1 `--no-build`, verified in Task 2 by `codesign -dv` on the mounted app).
2. Finder layout fails on the runner → job fails, no unarranged DMG ships (Task 1 `--strict`, Task 1 Step 2 check).
3. A site link whose tag and file name disagree (e.g. `v0.1.0/…-0.2.0-…`) or that is not a DMG → check-site fails (Task 4 tests).
4. Site deployed before the release exists → Download 404s (Task 4 starts only after Task 3's release is verified with `gh release view`).
5. A `Lucerna` volume left mounted on the runner or the dev's Mac → script already ejects it; keep that path unchanged under `--no-build`.

**Interfaces:**
- Produces: `scripts/make-dmg.sh [--debug] [--no-build] [--strict]`, output still `$target/$profile/Lucerna.dmg`.
  - `--no-build`: skip `bundle-app.sh`; exit 1 with `make-dmg: no app at <path>; build it first` if the app is missing.
  - `--strict`: where the script now prints `make-dmg: warning: Finder layout failed…` or `…Finder saved no layout`, exit 1 instead (after cleanup via the existing trap).
- Produces: release assets named per Global Constraints.

### Task 2: Push `main` and prove the DMG with a manual run

**Interfaces:**
- Consumes: Task 1's workflow on `origin/main` (a `workflow_dispatch` run uses the workflow file from the ref it runs on).

- [ ] **Step 1: Ask the user** to approve pushing `main` (`git log --oneline origin/main..main | wc -l` commits). Confirm `git status` shows no merge in progress. On yes: `git push origin main`. Never rebase or force.

- [ ] **Step 2: Run the workflow by hand**

Run: `gh workflow run release.yml -R khanhbuiswe/lucerna --ref main`, then find the run with `gh run list -R khanhbuiswe/lucerna --workflow release.yml -L 1` and wait with `gh run watch <id> --exit-status` in the background.
Expected: success. On failure, read `gh run view <id> --log-failed`; a Finder layout failure means stop and go back to the user (spec fallback C).

- [ ] **Step 3: Inspect the DMG** in a fresh scratchpad folder: `gh run download <id> -R khanhbuiswe/lucerna -D <scratch>/run`; `shasum -a 256 -c` both `.sha256` files; `hdiutil attach -nobrowse` the DMG; check `/Volumes/Lucerna/.DS_Store` exists, `codesign -dv /Volumes/Lucerna/Lucerna.app` succeeds, `Applications` is a link to `/Applications`. Then open the volume in Finder, screenshot the window for the user, eject.
Expected: arranged window (app left, arrow, Applications right). User confirms it looks right.
