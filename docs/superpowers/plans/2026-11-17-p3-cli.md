# Fixing the P3 bugs of group 4: `luc`, socket, multi-window — plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the seven P3 bugs of group 4 (M1-2, M1-3, M1-4, M1-5, M1-6, M2-3, M3-4) on the branch `claude/p3-cli`, update the multi-window spec to match, then mark them "Fixed" in the review.

**Architecture:** The socket name no longer carries a version. The protocol (still `version: 1`) gets a `status` field for the `Quitting` reply, and `claim_and_send` claims again by itself while the old app is quitting. `main.rs` splits how it runs into three modes (`RunMode`): `Detach` (the default, also when there is no socket), `Here` (Finder/Dock and the child process with the hidden flag `--detached-child`), `Exclusive` (the user's `--foreground`/`--trace-startup`: if the socket is already held, report an error, one sentence per flag). The router shows a status message for a failed open requested by `luc` only when `luc` has stopped waiting (the socket connection is closed), and `reopen()` does nothing while restoring. The language server's `{data_dir}` gets a slot number, handed out by one table shared by the whole app.

**Tech Stack:** Rust, GPUI (only `lucerna-workbench`), Unix socket (`std::os::unix::net`), serde_json, sha2, clap, assert_cmd.

**Spec:** `docs/superpowers/specs/2026-11-17-p3-fixes-design.md` (§5, "Group 4"). Location, reproduction and cause of each bug: `docs/superpowers/reviews/2026-11-15-release-flow-review.md`. The original spec for this area: `docs/superpowers/specs/2026-11-15-multi-window-design.md` (§6.5, M13, §10).

## Global Constraints

- Strings the user sees (`luc`'s stderr, status messages, errors in replies) are in English only. Vietnamese appears only in documents and test data.
- Only `lucerna-workbench` uses gpui. `lucerna-lsp` and `lucerna` (the binary) add no gpui dependency.
- Make no macOS assumptions outside platform-specific code: the socket code stays behind `#[cfg(unix)]` as it does now; the `#[cfg(not(unix))]` branch of `main.rs` still compiles.
- Cargo: `export PATH="/opt/homebrew/opt/rustup/bin:$PATH"` before every cargo command.
- Run `scripts/prune-target.sh` before every build or test. Before testing, delete `target/release` if it exists, but only when `pgrep -x cargo` prints nothing. Keep more than 1.2 GB of disk free.
- Never set `CARGO_TARGET_DIR` or pass `--target-dir`; every worktree shares `target` (`scripts/target-dir.sh` tells where). If another branch holds the cargo lock, wait.
- Stage files by explicit path (`git add <path>…`, `git commit -- <paths>`), never `git add -A`.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `cargo deny check` must pass (this task adds no dependency).
- Do not change `PROTOCOL_VERSION` (still `1`): the new field is optional, like `activate` before it.
- Strings fixed by the spec, used verbatim:
  - Reply refusing a newer protocol: `"Lucerna was updated. Quit Lucerna and open it again."`
  - M1-6, `--trace-startup`: `"Lucerna is already running; quit it to measure startup."`; the user's `--foreground`: `"Lucerna is already running; quit it to run in the foreground."`. Both go to stderr with the prefix `luc: ` like other errors, and exit with code 1. With both flags, use the `--trace-startup` sentence.
  - The error in a `Quitting` reply keeps the old string `"Lucerna is quitting"`, so an old `luc` (same protocol) can still print the reason.
- Parameters fixed by the spec: retry the claim every 100 ms, at most 5 seconds (M1-2); socket name `luc.sock`, debug build `luc-dev.sock` (M1-5); slot 0 gives exactly the same data directory as today (M3-4).

## Review Focus

1. **`luc <path>` just as the app is quitting:** the path opens exactly once in the new app, not twice and with no error. → `claim_and_send_claims_past_a_quitting_app` in Task 2.
2. **An old `luc` (same protocol 1) meeting a new app that is quitting:** it still reads the reply and prints "Lucerna is quitting", not "bad reply". → `quitting_reply_wire_format` in Task 2.
3. **The child process started by `detach()` finds a socket that already has an app (the M1-1 race):** it still hands the request over and exits 0, without the M1-6 error. → `detached_child_hands_off_to_a_running_app` in Task 3.
4. **Opening from Finder/Dock (cwd `/`, no arguments) while the app runs:** it still sends `activate`, with no "already running" error. → `finder_launch_activates_a_running_app` in Task 3.
5. **A language server stopped or crashed in one window:** the slot is returned, so the next start in another window takes the smallest slot again (jdtls's old data directory is reused). → `data_dir_slot_per_window_on_one_root` in Task 7.

### Task 5: M1-3, status message when an open from `luc` fails after `luc` stopped waiting

Decision: while `luc` still waits for the reply, the error is only printed to the terminal (as today). Only when `luc` has printed "will open when ready" and exited (the request was deferred past `REPLY_TIMEOUT`) does the app report the error in the status bar.
