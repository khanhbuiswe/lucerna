# Fixing the P3 bugs of group 2 (Explorer and watcher): plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the three P3 bugs T2-5, T4-4, T4-5 of the pre-release review, on the branch `claude/p3-explorer`.

**Architecture:**
- T2-5 is a new pure function in `lucerna-project::fs_ops`, used by the Explorer to decide between a file and a folder.
- T4-4 has two sources of errors: the worktree sends a new `WorktreeEvent`, and `GitStore` keeps the `.git` watcher's error. A new status bar item in `lucerna-workbench` reads both.
- T4-5 changes `OpenFileWatcher` (`open_files.rs`) to watch the nearest ancestor directory that still exists, and to recompute the watched directories after every batch.

**Tech Stack:** Rust, GPUI (only in `lucerna-workbench`), `notify`.

**Spec:** `docs/superpowers/specs/2026-11-17-p3-fixes-design.md`, §5 "Group 2: Explorer and watcher". The location and reproduction of each bug are in `docs/superpowers/reviews/2026-11-15-release-flow-review.md` (items T2-5, T4-4, T4-5).

## VS Code reference

`src/vs/workbench/contrib/files/browser/fileActions.ts`, `openExplorerAndCreate`, function `onSuccess`:

- `resourceToCreate = resources.joinPath(folder.resource, value)`, then `if (value.endsWith('/')) { isFolder = true; }`. It checks only `/`, not `\`, even on Windows.
- `validateFileName` calls `getWellFormedFileName`, which strips a trailing `/` and `\` before checking, so `foo/` is not reported as an error.
- A multi-level name `a/b/c.rs` is created with a single `ResourceFileEdit`; the file service creates the intermediate folders.
- After creating: a folder is selected in the Explorer, a file opens in a pinned editor.

Lucerna already creates intermediate folders: `fs_ops::create_file` and `create_dir` call `create_dir_all(parent)`, and the test `create_file_makes_parents_and_never_overwrites` checks it. So the `a/b/c.rs` part of T2-5 only needs a test at the Explorer level. The part that is truly missing is `foo/`.

## Plan decisions

These are the plan's decisions where the spec leaves things open (§7). The implementer does not change them.

- **T2-5:** only a trailing `/` turns New File into a folder, like VS Code. The name is `trim_end()`ed before checking, like `validate_new_name`. A trailing `\` on Windows still creates a file, like VS Code.
- **T4-4, position:** the item sits on the left of the status bar, right after the settings error item (`ConfigErrorItem`). The item is a 12 px `TRIANGLE_ALERT` icon in `ui.warning` color, with no text. The tooltip goes through `ui::tooltip`. The `debug_selector` is `"watch-off"`. With no error the item is hidden (`.hidden()`), like `ConfigErrorItem`.
- **T4-4, tooltip content:** each broken watcher is one line, with the spec's exact sentence: `File watching is off for {folder}: {reason}. Changes made outside Lucerna won't show.`
  - Worktree: `{folder}` is the root folder's name (`root.file_name()`; if there is none, `root.display()`).
  - `.git`: `{folder}` is `.git`.
  - The worktree line comes first, joined with `\n`.
  - `{reason}` is `err.to_string()` of the `notify::Error`.
- **T4-4, when it goes away:** the worktree's watcher is not retried, so its warning stays until the window closes. The `.git` warning is cleared when `GitStore` restarts (`reset`), and comes back if the new discover still fails.
- **T4-5:** after every batch, the watcher recomputes the directories to watch for every tracked file, without waiting for `set_files`. For a directory that was just watched again (the parent reappeared), every tracked file inside it is reported in the batch, so a file written before the watch could move down is still reloaded.

## Review Focus

1. **New File `src/` when `src` already exists**: reports an Exists error like any duplicate name, creates nothing. → Task 1, `validate_rejects_bad_names`.
2. **New File `a/b/` (multiple levels with `/`)**: creates both `a` and `a/b`, both expanded, no tab opened. → Task 1, `new_file_trailing_slash_multi_level_creates_folders`.
3. **The worktree reports a watch error twice** (for example from a test or a re-sent event): the tooltip still has only one line for the worktree. → Task 3, `watch_off_item_shows_each_failure_once`.
4. **`GitStore` restarts** (trust changes, `git.enabled` turned off): the old `.git` warning disappears. → Task 3, `restart_clears_git_watch_error`.
5. **An ignored file two levels deep** (`dist/js/bundle.js`), an agent runs `rm -rf dist`, then `mkdir -p dist/js` and writes the file at once: the tab is still notified. → Task 4, `open_file_watcher_follows_a_recreated_nested_parent`.
