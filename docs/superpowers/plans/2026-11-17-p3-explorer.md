# Sửa lỗi P3 nhóm 2 (Explorer và watcher): plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sửa ba lỗi P3 T2-5, T4-4, T4-5 của review trước release, trên nhánh `claude/p3-explorer`.

**Architecture:**
- T2-5 là một hàm thuần mới trong `lucerna-project::fs_ops`, được Explorer dùng để quyết định file hay folder.
- T4-4 gồm hai nguồn lỗi: worktree gửi một `WorktreeEvent` mới, `GitStore` giữ lỗi của watcher `.git`. Một status bar item mới trong `lucerna-workbench` đọc cả hai.
- T4-5 đổi `OpenFileWatcher` (`open_files.rs`) để watch thư mục tổ tiên gần nhất còn tồn tại, và tính lại các thư mục được watch sau mỗi batch.

**Tech Stack:** Rust, GPUI (chỉ trong `lucerna-workbench`), `notify`.

**Spec:** `docs/superpowers/specs/2026-11-17-p3-fixes-design.md`, mục §5 "Nhóm 2: Explorer và watcher". Vị trí lỗi và cách tái hiện nằm trong `docs/superpowers/reviews/2026-11-15-release-flow-review.md` (mục T2-5, T4-4, T4-5).

## Tham khảo VS Code

`src/vs/workbench/contrib/files/browser/fileActions.ts`, `openExplorerAndCreate`, hàm `onSuccess`:

- `resourceToCreate = resources.joinPath(folder.resource, value)`, rồi `if (value.endsWith('/')) { isFolder = true; }`. Chỉ kiểm `/`, không kiểm `\`, kể cả trên Windows.
- `validateFileName` gọi `getWellFormedFileName`, hàm này bỏ `/` và `\` ở cuối trước khi kiểm, nên `foo/` không bị báo lỗi.
- Tên nhiều cấp `a/b/c.rs` được tạo bằng một `ResourceFileEdit` duy nhất; file service tạo các folder trung gian.
- Tạo xong: folder thì được chọn trong Explorer, file thì mở editor pinned.

Lucerna đã tạo folder trung gian: `fs_ops::create_file` và `create_dir` gọi `create_dir_all(parent)`, và test `create_file_makes_parents_and_never_overwrites` đã kiểm. Vì vậy phần `a/b/c.rs` của T2-5 chỉ cần thêm test ở tầng Explorer. Phần thiếu thật là `foo/`.

## Quyết định của plan

Đây là các quyết định của plan ở những chỗ spec để ngỏ (§7). Implementer không tự đổi.

- **T2-5:** chỉ dấu `/` ở cuối mới biến New File thành folder, như VS Code. Tên được `trim_end()` trước khi kiểm, như `validate_new_name`. Dấu `\` ở cuối trên Windows vẫn tạo file, giống VS Code.
- **T4-4, vị trí:** item nằm ở bên trái status bar, ngay sau item lỗi settings (`ConfigErrorItem`). Item gồm icon `TRIANGLE_ALERT` 12 px màu `ui.warning`, không có chữ. Tooltip qua `ui::tooltip`. `debug_selector` là `"watch-off"`. Không có lỗi thì item ẩn (`.hidden()`), giống `ConfigErrorItem`.
- **T4-4, nội dung tooltip:** mỗi watcher hỏng là một dòng, theo đúng câu của spec: `File watching is off for {folder}: {reason}. Changes made outside Lucerna won't show.`
  - Worktree: `{folder}` là tên folder gốc (`root.file_name()`; nếu không có thì `root.display()`).
  - `.git`: `{folder}` là `.git`.
  - Dòng worktree đứng trước, nối bằng `\n`.
  - `{reason}` là `err.to_string()` của `notify::Error`.
- **T4-4, khi nào tắt:** watcher của worktree không được thử lại, nên cảnh báo của nó giữ đến khi đóng cửa sổ. Cảnh báo `.git` bị xoá khi `GitStore` khởi động lại (`reset`), rồi có lại nếu lần discover mới vẫn hỏng.
- **T4-5:** sau mỗi batch, watcher tính lại thư mục cần watch cho mọi file đang theo dõi, không chờ `set_files`. Thư mục vừa được watch lại (thư mục cha xuất hiện lại) thì mọi file theo dõi nằm trong nó được báo trong batch, để file đã được ghi trước khi watch kịp chuyển xuống vẫn được reload.

```rust
#[test]
fn watcher_that_cannot_start_is_reported() {
    let dir = tempfile::tempdir().unwrap();
    let missing = dir.path().join("gone");
    let wt = Worktree::start(missing, ScanOptions::default());
    let events = wt.events();
    let deadline = Instant::now() + Duration::from_secs(10);
    let mut failed = Vec::new();
    loop {
        let left = deadline.saturating_duration_since(Instant::now());
        match events.recv_timeout(left).expect("scan completes") {
            WorktreeEvent::WatchFailed(reason) => failed.push(reason),
            WorktreeEvent::ScanComplete => break,
            _ => {}
        }
    }
    assert_eq!(failed.len(), 1);
    assert!(!failed[0].is_empty());
}
```
