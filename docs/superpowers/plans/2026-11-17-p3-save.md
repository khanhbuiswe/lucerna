# Fixing the P3 bugs of group 1: saving files — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix every bug of "Group 1: Saving files" (T1-1, T1-2, T1-3, T1-5, T1-6, T1-7, T2-4, the two hot exit limits) on the branch `claude/p3-save`, each with a test.

**Architecture:**
- `lucerna-text` (no gpui) gets the changes at the byte level: a `lossy` flag when decoding, a stamp taken from the handle of the file just written, temp file names ≤ 255 bytes, and a `TempFiles` registry that records the temp files in use.
- `lucerna-workbench` wires them into the existing save flow (`Documents::save`, `WriteJob`, `AutoSave`), and adds a lossy bar that shares its component with the conflict bar, a dialog before the first save, and waiting for saves to finish in `quit()`.
- Hot exit: `BackupHeader.lossy`, and two fixes on the startup path (`app.rs`, `router.rs`) so a single-file window that has a backup is always reopened.

**Tech Stack:** Rust 1.99, GPUI (`b5cd310`), `encoding_rs`, `chardetng`, `tempfile`, `serde`.

**Spec:** `docs/superpowers/specs/2026-11-17-p3-fixes-design.md` (§5 "Group 1", §6). Read it together with the bug items in `docs/superpowers/reviews/2026-11-15-release-flow-review.md` and §5.4 of `docs/superpowers/specs/2026-11-16-hot-exit-design.md`.

## Plan decisions (the spec leaves them open)

- **The `lossy` flag lives in `Buffer`**, next to `has_bom`: `from_decoded` and `set_disk_state` take it from `Decoded`, so every load, reload and merge recomputes it. A successful save calls `clear_lossy()`.
- **Consent (§6.4) and Dismiss (§6.3)** are two flags of `Document` (`lossy_consent`, `lossy_dismissed`), reset to `false` whenever the document receives a new decode from disk (`take_buffer`, `apply_merge`, `apply_disk`). They are not saved through hot exit.
- **Buttons of the lossy dialog:** `[PromptButton::new("Cancel"), PromptButton::new("Save")]`. On macOS, NSAlert assigns Return to the first button, so Return is Cancel as the spec says. See "Notes for the reviewer" at the end.
- **T2-4:** the temp file registry is `lucerna_text::TempFiles`, one instance shared by the app (a gpui `Global` in `save.rs`); the `on_app_quit` hook is registered on first use. The wait limit is `QUIT_SAVE_TIMEOUT = 5 s`.
- **Hot exit (b), the Finder path:** when the app starts because Finder opened a file, only reopen the single-file windows that have a backup (do not reopen the folder session, as today).

## Review Focus

1. **Closing a tab and choosing Save on a lossy file** (spec §6.4 "save when closing a tab"): the lossy dialog still shows after the "Save changes?" dialog; on Cancel the tab stays open and unsaved. → test in Task 9.
2. **Cmd+Q with hot exit on and `files.autoSave` on, with a lossy file:** that file is not saved, nothing is asked, and the backup has `lossy: true`. The quit flow calls `save_each` with `SaveReason::Explicit`, so without filtering it would pop up the dialog. → test in Task 10.
3. **`luc <file>` for exactly the file of a single-file window that has a backup:** only one window, with the backed-up text. → test in Task 12.
4. **An agent runs `mv a.rs b.rs` just before the autosave timer fires:** `a.rs` is not made again, `b.rs` stays as it is. → test in Task 4.
5. **A valid UTF-8 file and Latin-1** (anti-goal): no lossy bar, Cmd+S does not ask. → tests in Task 7 and Task 8.

### Task 1: T1-7, `files.trimFinalNewlines` as VS Code does

VS Code (`src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts`, `TrimFinalNewLinesParticipant.doTrimFinalNewLines`): does nothing when the text has only one line; `findLastNonEmptyLine` returns the last line with `getLineLength > 0` (a line with only whitespace still counts as having content), `0` when no line has content; with autosave, `cannotTouchLineNumber` is the furthest line that has a cursor; it deletes from the start of line `max(lastNonEmptyLine + 1, cannotTouchLineNumber + 1)` to the end. So `\n\n\n` becomes `""`, and `\n` also becomes `""`.

- Produces: none (the signature `fn trim_final_newlines(text: &BufferSnapshot, cursor_rows: &[u32]) -> Edits` stays).

## Notes for the reviewer

- **The default button of the lossy dialog (§6.4 "Cancel is the default"):** GPUI `b5cd310` on macOS lets NSAlert assign Return to the first button, assign Escape to the `PromptButton::Cancel` button (which takes Return away if it is first), and put focus (the Space key) on the last non-cancel button. With `[Other("Cancel"), Other("Save")]`, Return = Cancel but Space = Save, and Escape is up to NSAlert. It needs a hand test; if that is not acceptable, a choice has to be made: change the spec (Save as default like the other dialogs) or patch GPUI.
- **T2-4, the hardlink exception:** `write_in_place` has no temp file, so when it is cut off midway (past 5 s, or Dock Quit) a file with a hardlink may be truncated. The plan does not handle this; the spec says "The original file stays intact in every case".
