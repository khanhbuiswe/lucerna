# Release 0.1.0 and a working Download button

Date: 2026-11-16. Size: small change.

## Intent

Publish Lucerna 0.1.0 on GitHub Releases and make the landing page's Download button fetch it,
replacing the "Soon" labels. Mac users expect a drag-to-install DMG, so the DMG is the main
download; the zip stays for scripts.

## Goals

- `v0.1.0` release with `Lucerna-0.1.0-macos-aarch64.dmg`, the existing zip, and a `.sha256` for each.
- The DMG opens on the arranged window (background, arrow, Applications link), built on CI.
- Landing page: Download buttons point at the DMG; the "Soon" labels go; a one-line Gatekeeper
  note sits next to the button (the app is signed ad hoc, not notarized).

## Non-goals

- Notarization, an Intel or universal build, Homebrew cask, and Linux or Windows builds.

## Anti-goals

- A site live with a Download link that 404s: the site ships only after the release exists.
- A DMG whose icons sit unarranged over the arrow background shipped as if it were fine.

## Approaches

- **A. Build the DMG on CI with `make-dmg.sh`, try it with a manual run first. (Picked.)** Many
  projects arrange DMG windows through Finder AppleScript on GitHub's macOS runners. If the manual
  run's DMG opens unarranged, fall back to C.
- B. Build the DMG on the local Mac and upload it by hand. Sure to look right, but it needs a local
  release build on a tight disk and manual work for every release.
- C. Write the window layout (`.DS_Store`) without Finder, e.g. with `dmgbuild`. Steadiest on CI,
  but adds a Python dependency and replaces the script's layout code.

## Design

1. `scripts/make-dmg.sh` gets `--no-build`: pack the existing `Lucerna.app` instead of running
   `bundle-app.sh`, so a Developer ID signature from the release workflow survives. Default
   behaviour stays as today.
2. `.github/workflows/release.yml`: after "Sign and notarize", run `scripts/make-dmg.sh --no-build`
   and copy the image to `dist/Lucerna-<version>-macos-aarch64.dmg` with its `.sha256`. Upload it
   with the zip in both the manual-run artifact and `gh release create`. Fail the job if
   `make-dmg.sh` warns that the Finder layout failed (no silent unarranged DMG).
   Release notes mention the DMG first.
3. `docs/releasing.md`: drop the "ship the zip until tried" note, list the DMG.
4. Manual run of the Release workflow; download the artifact, mount the DMG, check the window
   (screenshot for the user).
5. Tag `v0.1.0` on the pushed `main`, push the tag, wait for the release.
6. `site/index.html`: nav and download section buttons link to
   `https://github.com/khanhbuiswe/lucerna/releases/download/v0.1.0/Lucerna-0.1.0-macos-aarch64.dmg`;
   "Soon" labels and "coming to GitHub Releases" copy replaced; Gatekeeper line added; "Build from
   source" stays as the secondary path. `scripts/check-site.py site` and its tests pass. Then push,
   so Pages deploys.

## Calls made (correct if wrong)

- Versioned DMG URL on the site (`releases/download/v0.1.0/…`), not `releases/latest/download/…`:
  the file name carries the version, so each release updates the link on purpose.
- Pushing `main` (73 commits ahead of `origin`) and the tag happens only after the user says yes.
